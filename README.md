# เวร IPD — ตารางเวรนักรังสีการแพทย์ (เวอร์ชัน 2.2 · Google Sheets)

แอปจัดตารางเวรและบันทึกวันลาของหน่วยงานผู้ป่วยใน (IPD) ใช้งานบนมือถือแบบ PWA (ติดตั้งไว้บนหน้าจอโฮมได้)
เวอร์ชัน 2 ขึ้นไปเก็บข้อมูลกลางไว้ใน **Google Sheet** ของหน่วยงาน ผ่าน **Google Apps Script Web App**
ทุกเครื่องจึงเห็นข้อมูลชุดเดียวกัน และเซิร์ฟเวอร์เป็นผู้ตรวจสิทธิ์ทุกคำสั่ง

> คู่มือนี้เขียนสำหรับผู้ดูแลแอปในหน่วยงาน (ไม่จำเป็นต้องเป็นโปรแกรมเมอร์)
> รายละเอียดเชิงเทคนิค (โครงสร้างชีต, API, การออกแบบความปลอดภัย) อยู่ที่ [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)

## 1. ภาพรวม และสิ่งที่เปลี่ยนจากเวอร์ชันเดิม

แอปมี 4 แท็บเหมือนเดิม: **🏥 Station** (จัดคนลง Station รายวัน + สรุปผู้ลา + หมายเหตุ), **📝 การลา** (บันทึกวันลา/สถานะ + สรุปวันลา),
**👥 รายชื่อ** (จัดการบุคลากร — เฉพาะ Supervisor), **📊 สรุป/ส่งออก** (CSV, ภาพ JPG, คัดลอก/วาง — เฉพาะ Supervisor)
หน้าตา สี ฟอนต์ และตำแหน่งปุ่มคงเดิมเกือบทั้งหมด

### มีอะไรใหม่ใน v2.2

**🗓️ ปฏิทินการลา** — การ์ดแรกของแท็บ **📝 การลา** แสดงทั้งเดือนในหน้าเดียวว่าแต่ละวันมีคนลากี่คน (ทุกคนเห็น ทั้ง Supervisor และ Staff)

- ช่องวันที่มี **"N คน"** และสีแดงเข้มขึ้นตามจำนวนผู้ลา (1 / 2 / 3 / 4 คนขึ้นไป) — วันที่ไม่มีผู้ลาเป็นช่องสีขาว,
  วันอาทิตย์ตัวเลขสีแดง, วันนี้มีวงกลมสีน้ำเงิน, วันที่เลือกอยู่มีกรอบสีน้ำเงิน
- **แตะวันที่** = เลือกวันนั้น (ทั้งแอป) และแสดงรายชื่อผู้ลาของวันนั้นใต้ปฏิทิน พร้อม "(คนที่ N)" ของพักร้อน/Off เวร
  — รายการบันทึกการลาด้านล่างก็เปลี่ยนเป็นวันนั้นด้วย จึงแก้สถานะต่อได้ทันที
- **‹ ›** เลื่อนดูเดือนก่อน/ถัดไป (ไม่เปลี่ยนวันที่ที่เลือก) · **วันนี้** กลับมาเดือนปัจจุบันและเลือกวันนี้
- บรรทัด **"รวมทั้งเดือน"** บอกจำนวนการลาทั้งเดือนแยกตามประเภท
- ปุ่มกรอง **ทั้งหมด / คนประจำ / ทีมแทนเวร** ของแท็บการลา กรองตัวเลขในปฏิทินด้วย
- เดือนที่เครื่องยังไม่มีข้อมูลจะโหลดจากเซิร์ฟเวอร์ให้เอง ถ้าโหลดไม่ได้ ช่องวันที่จะเป็นเส้นประ (ยังไม่มีข้อมูล ไม่ใช่ "ไม่มีคนลา")
  และมีปุ่ม **โหลดอีกครั้ง**

### มีอะไรใหม่ใน v2.1

v2.1 เน้น **เปิดเร็วขึ้นและไม่หลุดง่าย** — แก้ปัญหาที่พบจากการใช้ v2.0 จริง (เซิร์ฟเวอร์ Google ตอบช้าเป็นช่วง ๆ
และบางครั้งตอบหน้า error กลับมา) พร้อมฟีเจอร์ที่ผู้ใช้ขอ 4 อย่าง ข้อมูลและรหัสผ่านเดิมใช้ต่อได้ทั้งหมด ไม่มีใครถูกออกจากระบบ

### สิ่งที่เปลี่ยนจากเวอร์ชันเดิม (v1 → v2)

| หัวข้อ | เวอร์ชันเดิม | เวอร์ชัน 2 |
|---|---|---|
| ที่เก็บข้อมูล | ในเบราว์เซอร์ของแต่ละเครื่อง (localStorage) — แต่ละเครื่องเห็นข้อมูลไม่ตรงกัน | Google Sheet กลางของหน่วยงาน — ทุกเครื่องเห็นข้อมูลเดียวกัน |
| การเข้าสู่ระบบ | ตรวจรหัสในเบราว์เซอร์ (แก้ผ่าน DevTools ให้ตัวเองเป็น Supervisor ได้) | ตรวจที่เซิร์ฟเวอร์ ทุกคำสั่งต้องแนบ token (อายุ 30 วัน) และเซิร์ฟเวอร์ตรวจสิทธิ์เองทุกครั้ง |
| รหัสผ่าน | เก็บเป็นข้อความธรรมดาในเครื่อง | เก็บในชีตเป็น **hash + salt** (SHA-256 วน 100 รอบ) ไม่มีใครอ่านรหัสจริงได้ · รหัสเดิมที่ค้างอยู่ในเครื่องถูกลบอัตโนมัติเมื่อเปิดเวอร์ชัน 2 |

| ใส่รหัสผิด | ไม่จำกัด | ผิด 5 ครั้ง (ทั้งตอนล็อกอินและรหัสเดิมตอนเปลี่ยนรหัส) ล็อกชื่อนั้น 10 นาที |

| ประวัติการแก้ไข | 5 รายการล่าสุดต่อวัน เก็บในเครื่อง | บันทึกทุกการเปลี่ยนแปลงลงชีต `Audit` (Supervisor ดูได้ในแท็บ Station) |
| ออฟไลน์ | ใช้ได้ (เพราะข้อมูลอยู่ในเครื่องอย่างเดียว) | **ดูข้อมูลที่เคยโหลดไว้ได้อย่างเดียว** แก้ไข/บันทึกไม่ได้จนกว่าจะออนไลน์ |
| การอัปเดตแอป | ผู้ใช้ไม่เคยได้รับเวอร์ชันใหม่ (แคชค้างตลอด) | เปิดจากสำเนาในเครื่องทันทีแล้วอัปเดตสำเนาเบื้องหลัง เมื่อมีเวอร์ชันใหม่จะขึ้นปุ่ม "🔄 มีเวอร์ชันใหม่ — แตะเพื่อโหลดใหม่" (v2.1 — หัวข้อ 4) |
| ลบรายชื่อ | ลบทิ้งทั้งหมดรวมประวัติ | ปิดการใช้งาน (soft delete): ลบเฉพาะเวร/วันลา **ตั้งแต่วันนี้เป็นต้นไป** ข้อมูลในอดีตยังอยู่ครบ (วันที่ผ่านมาแสดงเป็น "ชื่อ (ลบแล้ว)") |
| เปลี่ยนรหัสผ่าน | กล่อง prompt ไม่ต้องใส่รหัสเดิม | หน้าต่างเปลี่ยนรหัส ต้องใส่รหัสเดิม + ยืนยันรหัสใหม่ และเครื่องอื่นที่ล็อกอินชื่อนั้นอยู่จะถูกออกจากระบบ |

### บั๊กของเวอร์ชันเดิมที่แก้แล้ว

1. **เปิดแอปใหม่แล้วแก้วันลาไม่ได้** — เดิมถ้าจำการล็อกอินไว้ ปุ่มวันลาทุกแถวจะถูกล็อก ต้องออกแล้วเข้าใหม่ → ตอนนี้คำนวณสิทธิ์ใหม่ทุกครั้งที่แสดงผล
2. **วันที่เพี้ยนช่วงหลังเที่ยงคืน** — เดิมใช้วันที่แบบ UTC ทำให้ช่วง 00:00–06:59 น. "วันนี้" กลายเป็นเมื่อวาน, ช่วงเดือนเริ่มต้นกลายเป็น 31 ส.ค.–29 ก.ย. และเวลาบันทึกลาผิดจนลำดับคิวเพี้ยน → ตอนนี้ใช้วันที่ตามเวลาไทยทั้งหมด (และแก้วันที่ของรายการเดิมให้ตอนนำเข้า)
3. **บันทึก Station แล้ววันลาของคนอื่นหาย** — เดิมบันทึกโดยอ่านจากปุ่มบนหน้าจอ หลังโอนสิทธิ์ Supervisor แล้วกดบันทึกครั้งเดียววันลาของทุกคนถูกล้าง → ตอนนี้ข้อมูลอยู่ในหน่วยความจำของแอปและบนเซิร์ฟเวอร์ ไม่อ่านจากหน้าจออีก
4. **ไม่ได้รับเวอร์ชันใหม่ / ออฟไลน์แล้วหน้าตาเพี้ยน** — service worker เดิมใช้แคชตลอดไปและไม่แคชฟอนต์/สไตล์ → เขียนใหม่ (ดูหัวข้อ 4)
5. **ชื่อที่มีอักขระพิเศษทำให้หน้าจอพัง / CSV เพี้ยน / ตัวกรองกลุ่มหลุด** — ตอนนี้ escape ข้อความทุกจุด, ใส่เครื่องหมายคำพูดครอบทุกช่องใน CSV (และกันไม่ให้ Excel ตีความข้อความเป็นสูตร) และตัวกรองกลุ่มจำค่าถูกต้อง
6. **ข้อมูลอยู่เครื่องเดียว, รหัสผ่านไม่เข้ารหัส, ใครก็เป็น Supervisor ได้** — แก้ด้วย backend Google Sheets + การตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์

### ฟีเจอร์ที่เอาออก

| ฟีเจอร์ | เหตุผล |
|---|---|
| ปุ่ม **"↩️ คืนค่ารายชื่อเริ่มต้น"** (แท็บรายชื่อ) | เมื่อข้อมูลเป็นของกลาง ปุ่มนี้จะรีเซ็ตรายชื่อและรหัสผ่าน **ของทุกคน** กลับเป็น 1234 ในกดเดียว อันตรายเกินไป ถ้าจำเป็นให้เพิ่ม/ลบรายชื่อทีละคน หรือแก้ในชีตโดยผู้ดูแล |

ข้อมูลที่ **ไม่ถูกย้ายมา** ตอนนำเข้าข้อมูลเดิม: รหัสผ่านเดิม (ทุกคนเริ่มใหม่ที่ `1234`) และประวัติ "แก้ไขล่าสุดโดย" 5 รายการต่อวัน (ในชีต `Audit` จะมีบันทึกการนำเข้าแทน)

## 2. สถาปัตยกรรม

```
[ มือถือ / คอมพิวเตอร์ของเจ้าหน้าที่ ]   แอป PWA "เวร IPD"
    index.html + config.js + css/tailwind.css + js/*.js + sw.js   (ไฟล์หน้าเว็บ โฮสต์บน GitHub Pages)
    เปิดจากสำเนาในเครื่องทันที และเก็บข้อมูลล่าสุดไว้ดูตอนออฟไลน์ (service worker + localStorage)
          │
          │  ① HTTPS POST ไปที่ script.google.com/…/exec
          │     {"action": "...", "token": "...", "requestId": "...", "clientVersion": "2.1.0", ...}
          │     Content-Type: text/plain  (เลี่ยง CORS preflight ที่ Apps Script ตอบไม่ได้)
          │  ② Google ส่งต่อ (redirect) ให้ไปรับคำตอบที่ script.googleusercontent.com
          ▼
[ Google Apps Script Web App ]   URL ลงท้ายด้วย /exec
    Code.gs → doPost / doGet  (+ onEdit ทำงานเองเมื่อมีคนแก้ชีตด้วยมือ)
    ตรวจ token + สิทธิ์ทุกคำสั่ง · LockService กันเขียนชนกัน · Execute as: Me
    Script Cache: เลขเวอร์ชันข้อมูล, ข้อมูลสิทธิ์ (ไม่มีรหัสผ่าน), คำตอบของคำสั่งเขียน 10 นาที (กันบันทึกซ้ำ)
          │
          │  SpreadsheetApp (ทำงานด้วยสิทธิ์ของเจ้าของชีต เข้าถึงได้เฉพาะชีตที่ผูกอยู่)
          ▼
[ Google Sheet ส่วนตัวของหน่วยงาน (ไม่แชร์) ]
    Staff │ Config │ Days │ Leaves │ Audit
```

- **หน้าเว็บ** เป็นไฟล์ static ธรรมดา วางไว้ที่ไหนก็ได้ที่เป็น HTTPS (แนะนำ GitHub Pages ฟรี)
- **Apps Script** ผูกอยู่กับ Google Sheet (container-bound) รันด้วยสิทธิ์ของเจ้าของชีต ผู้ใช้ทั่วไป **ไม่ต้องมีบัญชี Google**
  สคริปต์ขอสิทธิ์เฉพาะ "สเปรดชีตที่ผูกอยู่" (`spreadsheets.currentonly`) ไม่ใช่ทุกไฟล์ของบัญชีเจ้าของ
- **Google Sheet** เป็นฐานข้อมูล มี 5 ชีต: `Staff` รายชื่อ/รหัสผ่าน(hash), `Config` ใครเป็น Supervisor และจำนวนคนที่แต่ละ Station ต้องการ, `Days` การจัด Station + หมายเหตุรายวัน, `Leaves` วันลา, `Audit` ประวัติการแก้ไข
- **เครือข่าย:** มือถือต้องเข้าถึงได้ 3 โดเมน — โฮสต์ของหน้าเว็บ (เช่น `<ชื่อผู้ใช้>.github.io`), `script.google.com` และ `script.googleusercontent.com`
  (ที่เหลือไม่จำเป็น — ดู [ใช้งานผ่าน Wi-Fi ของโรงพยาบาล](#ใช้งานผ่าน-wi-fi-ของโรงพยาบาล))

## 3. การติดตั้งครั้งแรก (ทีละขั้น)

**สิ่งที่ต้องมี**

- บัญชี Google 1 บัญชีสำหรับเป็นเจ้าของข้อมูล (แนะนำบัญชีกลางของหน่วยงาน ไม่ใช่บัญชีส่วนตัวของคนใดคนหนึ่ง)
  - ถ้าเป็นบัญชีองค์กร (Google Workspace) ผู้ดูแลระบบองค์กรอาจปิดตัวเลือก *Anyone* ไว้ — ถ้าเจอปัญหานี้ให้ใช้บัญชี @gmail.com
- บัญชี GitHub (ฟรี) สำหรับโฮสต์หน้าเว็บ
- ไฟล์ของโปรเจกต์นี้ทั้งโฟลเดอร์

> ถ้าเมนูของ Google แสดงเป็นภาษาไทย ให้ดูจากตำแหน่ง/ไอคอนเดียวกัน เช่น *Extensions* = *ส่วนขยาย*, *Deploy* = *การทำให้ใช้งานได้*

### ขั้นที่ 1 — สร้าง Google Sheet

1. เข้า <https://sheets.google.com> ด้วยบัญชีเจ้าของ → สร้างสเปรดชีตเปล่า (**Blank spreadsheet**)
2. ตั้งชื่อไฟล์ เช่น `เวร IPD — ฐานข้อมูล`
3. ตั้งเขตเวลา: **File > Settings > General > Time zone** เลือก **(GMT+07:00) Bangkok** → **Save settings**
4. ไม่ต้องสร้างชีตหรือหัวคอลัมน์เอง — ขั้นที่ 4 จะสร้างให้อัตโนมัติ

### ขั้นที่ 2 — เปิด Apps Script แล้ววาง `Code.gs`

1. ในสเปรดชีต ไปที่เมนู **Extensions > Apps Script** (จะเปิดแท็บใหม่)
   - ต้องเปิดจากเมนูในชีตเท่านั้น ห้ามสร้างโปรเจกต์ใหม่จาก script.google.com เพราะโค้ดใช้ชีตที่ผูกอยู่ (`getActiveSpreadsheet`)
2. คลิกชื่อ *Untitled project* ด้านบน เปลี่ยนเป็น `เวร IPD Backend`
3. ในไฟล์ `Code.gs` ที่เปิดอยู่ ลบโค้ดเดิม (`function myFunction() {...}`) ออกให้หมด
4. เปิดไฟล์ `apps-script/Code.gs` จากโปรเจกต์นี้ด้วย Notepad → **Ctrl+A**, **Ctrl+C** → กลับไปวางในหน้า Apps Script (**Ctrl+V**)
   - บรรทัดแรกของโค้ดต้องเป็น `/** @OnlyCurrentDoc */` (จำกัดสิทธิ์ให้เข้าถึงเฉพาะชีตนี้) — อย่าลบทิ้ง
5. กด **Ctrl+S** (หรือไอคอน 💾 **Save project**)

### ขั้นที่ 3 — วาง `appsscript.json`

1. แถบซ้ายสุด คลิกไอคอนฟันเฟือง ⚙️ **Project Settings**
2. ติ๊ก **Show "appsscript.json" manifest file in editor**
3. กลับไปที่ไอคอน `< >` **Editor** → จะเห็นไฟล์ `appsscript.json` เพิ่มขึ้นมา คลิกเปิด
4. ลบเนื้อหาเดิม แล้ววางเนื้อหาจากไฟล์ `apps-script/appsscript.json` ของโปรเจกต์ → **Ctrl+S**
   (ไฟล์นี้กำหนด `timeZone` = `Asia/Bangkok`, runtime `V8`, ค่าเริ่มต้นของ Web App = Execute as: Me / Who has access: Anyone
   และสิทธิ์ที่ขอ `oauthScopes` = `spreadsheets.currentonly` คือเฉพาะสเปรดชีตที่ผูกอยู่)

### ขั้นที่ 4 — รัน `setup` ครั้งแรก (อนุญาตสิทธิ์)

1. กลับไปที่ไฟล์ `Code.gs` บนแถบเครื่องมือด้านบนจะมีช่องเลือกฟังก์ชัน → เลือก **`setup`**
   (ในรายการจะเห็นเฉพาะฟังก์ชันสาธารณะ: `doGet`, `doPost`, `onEdit`, `setup`, `adminResetSupervisorPassword`, `resetAllSessions` — **ห้ามรัน** `doGet`/`doPost` เอง
   ส่วน `onEdit` ไม่ต้องรัน Google เรียกให้เองทุกครั้งที่มีคนแก้ชีตด้วยมือ เพื่อให้แอปเห็นการแก้นั้นในการดึงข้อมูลครั้งถัดไป)
2. กด **▷ Run**
3. จะขึ้นหน้าต่าง **Authorization required** → กด **Review permissions** → เลือกบัญชีเจ้าของ
4. จะเจอหน้าเตือน **"Google hasn't verified this app"** — เป็นเรื่องปกติ เพราะเป็นสคริปต์ที่เราเขียนใช้เอง ไม่ได้ส่งให้ Google ตรวจ
   - กด **Advanced** (ตัวเล็กด้านล่างซ้าย) → กด **Go to เวร IPD Backend (unsafe)**
5. หน้าถัดไปแสดงสิทธิ์ที่ขอ ซึ่งควรเป็น
   **"View and manage spreadsheets that this application has been installed in"** (ดูและจัดการสเปรดชีตที่ติดตั้งแอปนี้ไว้ = เฉพาะชีตนี้)
   → ถ้ามีช่องให้ติ๊ก ให้ติ๊ก → กด **Allow** / **Continue**
   - ถ้าหน้านี้ขอ **"See, edit, create, and delete all your Google Sheets spreadsheets"** (ทุกไฟล์ในบัญชี) แปลว่าโค้ดที่วางไม่ครบ/เป็นรุ่นเก่า
     ให้กดยกเลิก แล้วตรวจขั้นที่ 2 (บรรทัดแรก `/** @OnlyCurrentDoc */`) และขั้นที่ 3 ก่อนรันใหม่
6. รอจน *Execution log* แสดง **Execution completed** และข้อความ `พร้อมใช้งาน: พนักงาน … คน, Supervisor = "…"`
7. กลับไปที่แท็บ Google Sheet จะเห็นชีตใหม่ 5 ชีต: `Staff`, `Config`, `Days`, `Leaves`, `Audit`
   - ชีต `Staff` มีรายชื่อเริ่มต้น 21 คน (คนประจำ 15 + ทีมแทนเวร 6) ทุกคนรหัส `1234`
   - ชีต `Config` มี `supervisor` = `วาท`, `schema_version` = `3` และ 7 แถว `station_count:portable` … `station_count:supervisor`
     (จำนวนคนที่แต่ละ Station ต้องการ ค่าเริ่มต้น 3, 3, 2, 2, 3, 1, 1 — ให้ Supervisor แก้ผ่านปุ่ม **⚙️ ตั้งค่าจำนวนคน** ในแอป)
   - ชีตว่างเดิม (*Sheet1* / *ชีต1*) จะปล่อยไว้หรือลบทิ้งก็ได้

> `setup` รันซ้ำได้อย่างปลอดภัย จะไม่ลบหรือเขียนทับข้อมูลที่มีอยู่แล้ว — ถ้ามีคนลบชีตหรือค่าใน `Config` ไป รัน `setup` อีกครั้งเพื่อสร้างส่วนที่ขาดคืน

### ขั้นที่ 5 — Deploy เป็น Web App

1. มุมขวาบนของ Apps Script กด **Deploy > New deployment**
2. ข้าง *Select type* กดไอคอนฟันเฟือง ⚙️ → เลือก **Web app**
3. กรอก:

   | ช่อง | ค่าที่ต้องเลือก |
   |---|---|
   | Description | `v2.1.0` (อะไรก็ได้) |
   | Execute as | **Me** (อีเมลเจ้าของ) |
   | Who has access | **Anyone** — *ไม่ใช่* "Anyone with Google account" และ *ไม่ใช่* "Only myself" |

4. กด **Deploy** (ถ้าถามสิทธิ์อีกครั้ง ให้ทำแบบขั้นที่ 4)
5. คัดลอก **Web app URL** — รูปแบบ `https://script.google.com/macros/s/AKfy..../exec` (ต้องลงท้ายด้วย **`/exec`**) → กด **Done**
6. ทดสอบ: เปิด **หน้าต่างไม่ระบุตัวตน** (Chrome: Ctrl+Shift+N · Edge: Ctrl+Shift+N = InPrivate) หรือใช้มือถือที่ไม่ได้ล็อกอิน Google
   แล้ววาง URL ต้องเห็นข้อความ JSON ประมาณนี้

   ```json
   {"ok":true,"data":{"version":"2.1.0","timeZone":"Asia/Bangkok","now":"..."},"serverTime":"...","action":"ping"}
   ```

   (`"version"` บอกเวอร์ชันของ `Code.gs` ที่ deploy อยู่ — หลังอัปเดตต้องเป็น `2.1.0`)

   - ถ้าเห็นหน้าล็อกอิน Google หรือข้อความว่าไม่มีสิทธิ์ แปลว่า *Who has access* ไม่ใช่ **Anyone** (แก้ตามหัวข้อ 7 "ตรวจการตั้งค่า Web App")
   - ⚠️ **อย่าทดสอบในเบราว์เซอร์ที่ล็อกอินบัญชีเจ้าของอยู่** — เจ้าของจะเห็น JSON เสมอแม้ตั้งค่าเป็น "Only myself" หรือ "Anyone with Google account"
     ซึ่งมือถือของทุกคนจะเชื่อมต่อไม่ได้

### ขั้นที่ 6 — ใส่ URL ให้แอป (เลือกวิธีใดวิธีหนึ่ง)

**วิธี ก (แนะนำ) — แก้ `config.js`** ก่อนอัปโหลด:

```js
window.APP_CONFIG = { API_URL: "https://script.google.com/macros/s/AKfy..../exec" };
```

**วิธี ข — ปล่อย `config.js` ว่างไว้** (`API_URL: ""`) แล้วตอนเปิดแอปครั้งแรกในแต่ละเครื่อง แอปจะแสดงหน้าตั้งค่า
ให้วาง URL แล้วกด **"ทดสอบและบันทึก"** (URL จะถูกจำไว้ในเครื่องนั้น และในหน้าล็อกอินจะมีลิงก์ **"⚙️ ตั้งค่าการเชื่อมต่อ"** ไว้แก้ภายหลัง)
เหมาะถ้าไม่อยากให้ URL ปรากฏในไฟล์สาธารณะ แต่ทุกเครื่องต้องวาง URL เอง
- URL ต้องขึ้นต้นด้วย `https://` ถ้าไม่ใช่รูปแบบ `https://script.google.com/macros/s/.../exec` แอปจะเตือนแต่ยังลองเชื่อมต่อให้
- ถ้าขึ้น **"เชื่อมต่อไม่ได้ — ตรวจสอบอินเทอร์เน็ต หรือ URL / การตั้งค่า Who has access ต้องเป็น Anyone"** ให้ตรวจตามหัวข้อ 7 "ตรวจการตั้งค่า Web App"
  (ในหน้าตั้งค่ามีลิงก์ **🩺 ตรวจสอบการเชื่อมต่อ** ไว้ตรวจว่าเครื่อง/เครือข่ายใช้อินเทอร์เน็ตได้หรือไม่)

### ขั้นที่ 7 — โฮสต์หน้าเว็บบน GitHub Pages

> **เคยใช้เวอร์ชันเดิมบน GitHub Pages อยู่แล้ว?** ให้อัปโหลดไฟล์ใหม่ **ทับใน repository เดิม** (URL เดิม) แทนการสร้าง repository ใหม่
> ไม่อย่างนั้นจะย้ายข้อมูลเดิมจาก iPhone ไม่ได้ — ดูขั้นที่ 9 ก่อนเริ่ม

**ไฟล์ที่ต้องอัปโหลด** (เฉพาะเท่านี้):

```
index.html
config.js
sw.js
manifest.json
icon-192.png
icon-512.png
css/           (ทั้งโฟลเดอร์: tailwind.css — สไตล์ทั้งหมดของแอป ถ้าขาดไฟล์นี้แอปจะแสดงผลไม่มีสี/ไม่จัดหน้า)
js/            (ทั้งโฟลเดอร์: utils.js, api.js, app.js)
```

**ไม่ต้องอัปโหลด:** `apps-script/`, `tests/`, `tools/` (รวมถึง `docs/`, `.claude/`, `README.md` ไม่จำเป็น)

ขั้นตอน:

1. ล็อกอิน <https://github.com> → ปุ่ม **+** มุมขวาบน → **New repository**
2. *Repository name* เช่น `ipd-shift` → เลือก **Public** → **Create repository**
3. ในหน้า repository ว่าง คลิกลิงก์ **uploading an existing file**
4. ลากไฟล์ตามรายการด้านบนลงไป — สำหรับ `js` และ `css` ให้ **ลากทั้งโฟลเดอร์** (ไม่ใช่ลากไฟล์ข้างใน) เพื่อให้ได้ path `js/app.js`, `css/tailwind.css` ฯลฯ
5. เลื่อนลงล่าง กด **Commit changes**
6. ไปที่ **Settings > Pages** → *Build and deployment* → *Source*: **Deploy from a branch** → *Branch*: **main** และ **/ (root)** → **Save**
7. รอ 1–3 นาที แล้วรีเฟรชหน้า Settings > Pages จะเห็น **"Your site is live at `https://<ชื่อผู้ใช้>.github.io/ipd-shift/`"**
8. เปิด URL นั้นบนมือถือ แล้วติดตั้งเป็นแอป:
   - **Android (Chrome):** เมนู ⋮ > **Install app** / **Add to Home screen**
   - **iPhone (Safari):** ปุ่มแชร์ > **Add to Home Screen**

> ต้องเป็น HTTPS เท่านั้น (GitHub Pages เป็น HTTPS อยู่แล้ว) — จะใช้โฮสต์ static อื่นแทนก็ได้

### ขั้นที่ 8 — เข้าสู่ระบบครั้งแรก

1. เปิดแอป → เลือกชื่อ **วาท ⭐ (Supervisor)** → รหัส **`1234`** → **เข้าสู่ระบบ**
   (ถ้ารายชื่อไม่ขึ้น กด **"🔄 โหลดรายชื่อใหม่"** เหนือช่องเลือกชื่อ)
2. แอปจะบังคับเปิดหน้าต่างเปลี่ยนรหัส (ปิดไม่ได้ มีแค่ปุ่ม "ออกจากระบบ"): ใส่รหัสเดิม `1234` → รหัสใหม่ (4–64 ตัวอักษร ห้ามเป็น `1234`) → ยืนยัน → บันทึก
   - จนกว่าจะเปลี่ยนรหัสสำเร็จ เซิร์ฟเวอร์จะไม่ยอมทำคำสั่งอื่น (อ่านข้อมูลก็ไม่ได้) — แอปจะโหลดข้อมูลต่อให้เองหลังเปลี่ยนรหัส
3. แจ้งทุกคน: **ทุกคนเริ่มที่รหัส `1234`** ให้เข้าด้วยชื่อตัวเอง แล้วตั้งรหัสใหม่ทันที
4. ถ้ารายชื่อไม่ตรงกับหน่วยงาน ให้แก้ในแท็บ **👥 รายชื่อ** (หรือนำเข้าข้อมูลเดิมตามขั้นที่ 9 ซึ่งจะเพิ่มรายชื่อที่ขาดให้เอง)

### ขั้นที่ 9 — ย้ายข้อมูลเดิมจากเครื่อง (ถ้ามี)

ข้อมูลของเวอร์ชันเดิมอยู่ใน **localStorage ของเบราว์เซอร์** ซึ่ง **ผูกกับโดเมน (origin)** ที่เปิดแอป
เช่น ข้อมูลที่บันทึกจาก `https://abc.github.io/...` จะอ่านได้เฉพาะหน้าเว็บที่อยู่บน `https://abc.github.io` เท่านั้น
(origin = `https://` + ชื่อโดเมน + พอร์ต — ส่วน path หลังโดเมนไม่มีผล)
ดังนั้น **ต้องเปิดแอปเวอร์ชันใหม่บนโดเมนเดียวกับเวอร์ชันเก่า และบนเครื่อง/เบราว์เซอร์เดียวกับที่มีข้อมูล** ปุ่มนำเข้าจึงจะเห็นข้อมูล

> เมื่อเปิดเวอร์ชัน 2 ครั้งแรก แอปจะลบ **รหัสผ่านเดิมที่เก็บเป็นข้อความธรรมดา** (`rad_passwords`, `rad_current_user`) ออกจากเครื่องทันที
> ส่วนตารางเวร/วันลา/รายชื่อเดิม (`rad_schedules`, `rad_staff`) ยังอยู่จนกว่าจะกดลบเองในข้อ 7 ด้านล่าง

1. วางไฟล์เวอร์ชันใหม่ให้เปิดได้บนโดเมนเดียวกับเวอร์ชันเก่า
   - **วิธีที่ใช้ได้ทุกกรณี (แนะนำ):** อัปโหลดไฟล์ใหม่ **ทับใน repository เดิม** (URL เดิมทุกตัวอักษร) แล้วเปิดจาก URL/ไอคอนเดิม
   - ใช้ **repository ใหม่** ภายใต้บัญชี GitHub เดิม (`<ชื่อผู้ใช้>.github.io` เดียวกัน) ได้เฉพาะเครื่อง **Android (Chrome) / คอมพิวเตอร์**:
     ต้องเปิด **URL ใหม่** ในเบราว์เซอร์ตัวเดียวกับที่เคยใช้เวอร์ชันเดิม (URL/ไอคอนเดิมยังเป็นแอปเก่าที่ไม่มีปุ่มนำเข้า)
   - ⚠️ **iPhone ที่ใช้แอปจากไอคอนบนหน้าจอโฮม ต้องใช้วิธีอัปโหลดทับเท่านั้น** — iOS แยกพื้นที่เก็บข้อมูลของไอคอนหน้าจอโฮมออกจาก Safari
     ข้อมูลเดิมจึงเปิดได้จากไอคอนเดิมเท่านั้น (Safari หรือไอคอนใหม่ของ URL ใหม่มองไม่เห็น)
2. บนเครื่องที่มีข้อมูลเดิม (ปกติคือเครื่องของ Supervisor) เปิดแอปจาก URL/ไอคอนเดิม (หรือ URL ใหม่ตามเงื่อนไขในข้อ 1)
   - ถ้ายังเห็นหน้าตาเวอร์ชันเก่า ให้ปิดแอปทั้งหมดแล้วเปิดใหม่ 1–2 ครั้ง (ดูหัวข้อ 7 "เห็นเวอร์ชันเก่า")
   - **ห้าม** กด "ล้างข้อมูลเว็บไซต์ / Clear site data" ก่อนนำเข้าเสร็จ ข้อมูลเดิมจะหายถาวร
3. ล็อกอินเป็น Supervisor
4. ไปแท็บ **👥 รายชื่อ** → จะมีการ์ด **"📦 นำเข้าข้อมูลจากเวอร์ชันเดิม (เครื่องนี้)"** บอกจำนวนวันและรายชื่อที่พบในเครื่อง (การ์ดนี้แสดงเฉพาะเมื่อเครื่องมีข้อมูลเวอร์ชันเดิม)
5. เลือกว่าจะติ๊ก **"เขียนทับข้อมูลที่มีอยู่แล้ว"** หรือไม่
   - ไม่ติ๊ก (ค่าเริ่มต้น): วัน/วันลาที่มีบนเซิร์ฟเวอร์แล้วจะถูกข้าม — ปลอดภัยที่สุด (วันที่บนเซิร์ฟเวอร์ว่างอยู่ เช่น เคยกดล้างข้อมูลทั้งวัน ถือว่ายังไม่มีข้อมูล จะถูกเติมให้)
   - ติ๊ก: ข้อมูลจากเครื่องนี้จะทับของบนเซิร์ฟเวอร์ในวันเดียวกัน (วันลาประเภทเดียวกันที่มีอยู่แล้วไม่ถูกแตะ คิวเดิมคงอยู่
     และวันที่ในเครื่องไม่มีการจัด Station/หมายเหตุ จะไม่ลบ Station ของวันนั้นบนเซิร์ฟเวอร์)
6. กดปุ่ม **"⬆️ นำเข้าข้อมูลขึ้นระบบกลาง"** (ข้อมูลเยอะอาจใช้เวลาเป็นนาที) → แอปแสดงสรุป: รายชื่อที่เพิ่ม, จำนวนวัน, จำนวนวันลา,
   จำนวนคนที่ถูกนำออกจาก Station ที่มีอยู่แล้ว และรายการที่ข้าม (พร้อมเหตุผล)
7. ตรวจข้อมูลโดย **สลับแท็บในแอปนี้** (หรือเปิดจากอีกเครื่อง/เปิดชีตดู) แล้ว (ถ้าต้องการ) กด **"🧹 ลบข้อมูลเดิมในเครื่องนี้"** เพื่อลบข้อมูลเก่าในเครื่อง
   - ปุ่มนี้ **แสดงเฉพาะหลังกดนำเข้าในรอบนั้น** และหายไปเมื่อปิด/โหลดแอปใหม่หรือออกจากระบบ — ถ้าปุ่มหายไป ให้กดนำเข้าอีกครั้งแบบ **ไม่ติ๊ก** เขียนทับ
     แล้วจึงกดลบ (ข้อมูลที่นำเข้าแล้วจะไม่ซ้ำ แต่วันลา/วันที่ที่ถูกลบหรือล้างบนเซิร์ฟเวอร์หลังการนำเข้าครั้งแรกจะถูกนำเข้ากลับมา — ตรวจอีกครั้งหลังกด)

สิ่งที่ควรรู้เกี่ยวกับการนำเข้า:

- รายชื่อในเครื่องที่ยังไม่มีบนเซิร์ฟเวอร์จะถูกเพิ่ม (รหัส `1234`, บังคับเปลี่ยนรหัส) ชื่อที่ผิดกฎ (เช่น มีเครื่องหมายจุลภาค หรือเป็นคำสงวน) จะถูกข้ามและแสดงในสรุป
- วันลานำเข้าเฉพาะของคนที่ยังใช้งานอยู่ และเฉพาะประเภทที่รู้จัก ผู้บันทึก/เวลาบันทึกเดิมถูกเก็บไว้ (ใช้เรียงคิว)
  รายการที่เวอร์ชันเดิมบันทึกช่วง 00:00–06:59 น. มีวันที่เพี้ยนไป 1 วัน (บั๊กข้อ 2) — ตอนนำเข้าแอปแก้วันที่ให้อัตโนมัติ ลำดับคิวจึงถูกต้อง
- **คนที่มีวันลาในวันใด จะไม่อยู่ใน Station ของวันนั้น** ทั้งในวันที่นำเข้าจากเครื่องนี้ และในวันที่มีข้อมูลบนเซิร์ฟเวอร์อยู่แล้ว
  (คนที่วันลาเพิ่งถูกนำเข้าจะถูกนำออกจาก Station เดิม พร้อมบันทึก `AUTO_UNASSIGN` ในชีต `Audit` เหมือนตอนกดลาในแอป)
- ถ้าเวอร์ชันเดิมถูกใช้บนหลายเครื่อง: นำเข้าจากเครื่องหลักก่อน แล้วค่อยนำเข้าจากเครื่องอื่นแบบ **ไม่ติ๊ก** เขียนทับ เพื่อเติมเฉพาะส่วนที่ขาด (ต้องล็อกอินเป็น Supervisor บนเครื่องนั้น แล้วออกจากระบบเมื่อเสร็จ)
- ถ้าเปิดเวอร์ชันใหม่บนโดเมนเดิมไม่ได้ (เช่น เดิมเปิดจากไฟล์ในเครื่อง) ปุ่มนำเข้าจะมองไม่เห็นข้อมูล ต้องกรอกข้อมูลใหม่ หรือให้นักพัฒนาดึงข้อมูลจาก localStorage ให้

### อัปเดตจาก v2.1 เป็น v2.2

v2.2 (ปฏิทินการลา) แก้เฉพาะไฟล์หน้าเว็บ — **ไม่ต้องแก้ `Code.gs` และไม่ต้อง Deploy ใหม่** (ใช้กับ `Code.gs` 2.1.0 ได้เลย)

2. แต่ละเครื่องเปิดแอปขณะต่อเน็ต แล้วแตะ **"🔄 มีเวอร์ชันใหม่ — แตะเพื่อโหลดใหม่"** (หรือปิด-เปิดแอปใหม่)

### อัปเดตจาก v2.0 เป็น v2.1

ทำ 3 ส่วนตามลำดับ ก → ข → ค (ใช้เวลาประมาณ 15 นาที) — **ไม่ต้อง** สร้างชีตใหม่, ไม่ต้องอนุญาตสิทธิ์ใหม่,
ไม่ต้องแก้ `config.js` และไม่มีใครถูกออกจากระบบ (รหัสผ่านและการเข้าสู่ระบบเดิมใช้ต่อได้)

**ก. Apps Script (`Code.gs`) — ทำก่อน**

1. เปิด Google Sheet ของหน่วยงาน → **Extensions > Apps Script**
2. เปิดไฟล์ `Code.gs` → คลิกในโค้ด → **Ctrl+A** แล้วกด **Delete** (ลบโค้ดเดิม **ทั้งหมด** ห้ามวางต่อท้ายของเดิม)

   - บรรทัดแรกต้องเป็น `/** @OnlyCurrentDoc */` และช่วงต้นไฟล์มีบรรทัด `const API_VERSION_ = '2.1.0';`
   - `appsscript.json` ไม่เปลี่ยนในเวอร์ชันนี้ — ไม่ต้องแตะ
4. กด **Ctrl+S** (💾 **Save project**)
5. **Deploy > Manage deployments** → เลือก deployment ที่ใช้อยู่ → ไอคอนดินสอ ✏️ (**Edit**) → ช่อง **Version** เลือก **New version**
   (Description ใส่ `v2.1.0` ได้) → **Deploy** → **Done**
   - URL `/exec` **เหมือนเดิม** — ⚠️ ห้ามกด **New deployment** (จะได้ URL ใหม่ และต้องตั้งค่าทุกเครื่องใหม่)
   - การกด Save อย่างเดียวยังไม่มีผลกับแอป ต้องออก **New version** ตามข้อนี้
6. จะรัน `setup` ก็ได้แต่ **ไม่จำเป็น** — คำขอแรกที่เข้ามาหลัง Deploy (จากแอปเครื่องใดก็ได้ หรือการเปิด URL ในข้อ 7) จะปรับชีตให้เองครั้งเดียว:
   - หัวคอลัมน์ `OR (Standby IPD)` ในชีต `Days` เปลี่ยนเป็น `OR`
   - ชีต `Config` ได้แถวใหม่ `station_count:portable` … `station_count:supervisor` (ค่าเริ่มต้น 3, 3, 2, 2, 3, 1, 1 = จำนวนเดิม) และ `schema_version` เป็น `3`
   - แถวข้อมูลเดิมทุกแถวไม่ถูกแตะ
7. ตรวจ: เปิด URL `/exec` ใน **หน้าต่างไม่ระบุตัวตน** ต้องเห็น `"version":"2.1.0"` และ `"action":"ping"`
   (หรือในแอปเปิด 🩺 ตรวจสอบการเชื่อมต่อ → บรรทัด "ช่องทางรับคำตอบ" จะบอก "เวอร์ชัน 2.1.0")

**ข. หน้าเว็บ — อัปโหลดขึ้นโฮสต์ (repository GitHub เดิม URL เดิม)**

อัปโหลดทับของเดิม:

```
index.html
sw.js
css/           ← โฟลเดอร์ใหม่ (tailwind.css) ต้องมี ไม่อย่างนั้นแอปจะไม่มีสีและไม่จัดหน้า
js/            (utils.js, api.js, app.js)
manifest.json   icon-192.png   icon-512.png   (ไม่เปลี่ยนจาก v2.0 — อัปโหลดซ้ำได้)
```

1. หน้าแรกของ repository → **Add file > Upload files** → ลากไฟล์ข้างบน โดยลาก `css` และ `js` **ทั้งโฟลเดอร์** → **Commit changes**
2. ตรวจว่าใน repository มี `css/tailwind.css` และ `js/app.js` (ไม่ใช่ `tailwind.css` / `app.js` ลอยอยู่ที่หน้าแรก)
3. **ไม่ต้องอัปโหลด `config.js`** — ไฟล์บนโฮสต์มี URL `/exec` อยู่แล้ว (ถ้าจะอัปโหลด ต้องเป็นไฟล์ที่มี URL เดิมเท่านั้น)
4. `sw.js` ของ v2.1 ตั้ง `VERSION = 'ipd-shift-v2.2.0'` ไว้แล้ว ไม่ต้องแก้
5. แนะนำให้รอประมาณ **10 นาที** หลังอัปโหลดก่อนเริ่มส่วน ค (เหตุผลอยู่ใน "แก้ไฟล์หน้าเว็บ" ด้านล่าง)

**ค. มือถือ/คอมพิวเตอร์ทุกเครื่อง**

1. เปิดแอปขณะต่อเน็ต 1 ครั้ง → รอสักครู่จะขึ้นปุ่ม **"🔄 มีเวอร์ชันใหม่ — แตะเพื่อโหลดใหม่"** ด้านล่างจอ → แตะ
   - ถ้าไม่ขึ้น: ปิดแอปให้หมด (ปัดทิ้งจากหน้าสลับแอป / ปิดทุกแท็บ) แล้วเปิดใหม่ (อาจต้อง 2 ครั้ง)
2. รู้ได้ว่าเป็น v2.1 แล้ว: แท็บ Station มีการ์ด **"📋 สรุปรายชื่อผู้ลา / สถานะพิเศษ"** และ Station ชื่อ **"OR"**, แท็บการลามีปุ่ม **ลากิจ**,
   Supervisor เห็นปุ่ม **⚙️ ตั้งค่าจำนวนคน**
3. ⚠️ **Supervisor ต้องเป็น v2.1 ก่อนเปลี่ยนจำนวนคน — ทุกเครื่องที่ใช้บันทึก Station** (เช่น ทั้งมือถือและคอมพิวเตอร์)
   เมื่อจำนวนคนไม่ใช่ค่าเริ่มต้นแล้ว แอปเวอร์ชันเก่าที่ค้างในเครื่องจะบันทึก Station ไม่ได้ และขึ้น
   **"แอปในเครื่องนี้เป็นเวอร์ชันเก่า กรุณาปิดแล้วเปิดแอปใหม่เพื่ออัปเดตก่อนบันทึก"**
   (กันไม่ให้แอปเก่าตัดคนที่เกินจำนวนเดิมทิ้งโดยไม่รู้ตัว) — ก่อนโอนสิทธิ์ Supervisor ให้ผู้รับอัปเดตแอปก่อน
   - Staff ที่ยังเป็นแอปเก่ายังดูข้อมูลและบันทึกวันลาของตนได้ แต่จะยังไม่เห็นการ์ดผู้ลา ปุ่มลากิจ และชื่อ "OR" จนกว่าจะอัปเดต

**ลำดับ: แนะนำ ก (Code.gs) ก่อน แล้วจึง ข (หน้าเว็บ)** — สลับกันก็ไม่พัง แต่ระหว่างรอจะต่างกันดังนี้

| หน้าเว็บก่อน | แอป v2.1 ทำงานได้แต่ไม่ครบ: ดึงข้อมูลใหม่ทั้งหมดทุกรอบ, ถ้าเน็ตช้าจนแอปส่งซ้ำอาจขึ้น "ข้อมูลวันนี้ถูกแก้ไขจากเครื่องอื่นแล้ว" หลอกเหมือน v2.0, จำนวนคนคงที่ตามค่าเริ่มต้น (กดบันทึกใน ⚙️ จะขึ้น **"ต้องอัปเดต Code.gs เป็นเวอร์ชันล่าสุดก่อน"**), เลือก **ลากิจ** ไม่ได้ (ขึ้น "ประเภทการลาไม่ถูกต้อง") และ **Supervisor** จะเห็นข้อความ **"เซิร์ฟเวอร์ (Code.gs) ยังเป็นเวอร์ชันเก่า กรุณาอัปเดตตามคู่มือ"** ครั้งเดียวต่อการเปิดแอป/เข้าสู่ระบบ → ทำส่วน ก ให้เสร็จ |

### แก้โค้ดฝั่งเซิร์ฟเวอร์ (`Code.gs`)

1. เปิดชีต → **Extensions > Apps Script** → วางโค้ดใหม่ทับใน `Code.gs` **ทั้งไฟล์** (และวาง `appsscript.json` ใหม่ทับด้วย ถ้าไฟล์นั้นเปลี่ยน) → **Ctrl+S**
2. **Deploy > Manage deployments** → เลือก deployment ที่ใช้งานอยู่ → กดไอคอนดินสอ ✏️ (**Edit**)
3. ช่อง **Version** เลือก **New version** → **Deploy**
4. URL `/exec` **เหมือนเดิม** ไม่ต้องแก้ `config.js`

> ⚠️ ถ้ากด **New deployment** แทน จะได้ **URL ใหม่** และต้องแก้ `config.js` / ตั้งค่าในทุกเครื่องใหม่
> ถ้าเวอร์ชันใหม่เปลี่ยนสิทธิ์ที่ขอ (`appsscript.json` / บรรทัด `@OnlyCurrentDoc`) ให้รัน `setup` อีกครั้งเพื่ออนุญาตสิทธิ์ (รันซ้ำได้ปลอดภัย)
> การกด Save อย่างเดียว **ไม่มีผล** กับ URL `/exec` จนกว่าจะออก Version ใหม่ตามขั้นที่ 2–3
> ถ้าเวอร์ชันใหม่เปลี่ยนโครงสร้างชีต (เลข schema) คำขอแรกหลัง Deploy จะปรับชีตให้เองครั้งเดียว ไม่ต้องรันอะไรเพิ่ม

### แก้ไฟล์หน้าเว็บ (`index.html`, `css/`, `js/*.js`, ฯลฯ)

1. แก้ไฟล์ แล้ว **เปลี่ยนค่า `VERSION` ในบรรทัดแรก ๆ ของ `sw.js`** ทุกครั้ง เช่น
   `const VERSION = 'ipd-shift-v2.2.0';` → `const VERSION = 'ipd-shift-v2.2.1';`
   (ทำให้มือถือทุกเครื่องติดตั้ง service worker ใหม่ ขึ้นปุ่ม "มีเวอร์ชันใหม่" และลบแคชหน้าเว็บเก่า)
   - ถ้าแก้/เพิ่มคลาสของ Tailwind ใน `index.html` หรือ `js/*.js` ต้องสร้าง `css/tailwind.css` ใหม่ด้วย `tools/build-css.ps1` ก่อน (หัวข้อ 8) แล้วอัปโหลดไฟล์นั้นด้วย
2. อัปโหลดไฟล์ที่แก้ทับใน GitHub (**Add file > Upload files** หรือเปิดไฟล์แล้วกดดินสอแก้) → **Commit changes**
   - **Upload files จะวางไฟล์ในโฟลเดอร์ที่กำลังเปิดอยู่** — ไฟล์ใน `js/` (หรือ `css/`) ต้องคลิกเข้าโฟลเดอร์นั้นใน GitHub ก่อนแล้วจึง Upload
     (หรือลากทั้งโฟลเดอร์จากหน้าแรกของ repository) ถ้าวาง `app.js` ไว้ที่หน้าแรก จะได้ไฟล์ `/app.js` ที่แอปไม่ได้ใช้ และผู้ใช้จะไม่ได้รับการแก้ไข
   - **อย่าอัปโหลด `config.js` ทับ** ยกเว้นตั้งใจเปลี่ยน URL — `config.js` ในโปรเจกต์ที่ดาวน์โหลดมาใหม่มี `API_URL: ""`
     ถ้าทับไป ทุกเครื่องที่ใช้วิธี ก จะเด้งไปหน้าตั้งค่าให้วาง URL
3. ผู้ใช้จะได้เวอร์ชันใหม่ในครั้งถัดไปที่เปิดแอปขณะออนไลน์: แอปเปิดจากสำเนาเดิมก่อน ติดตั้งเวอร์ชันใหม่เบื้องหลัง แล้วขึ้นปุ่ม
   **"🔄 มีเวอร์ชันใหม่ — แตะเพื่อโหลดใหม่"** (ถ้าไม่ขึ้น ปิด-เปิดแอปใหม่)
   — แนะนำให้รอประมาณ **10 นาที** หลังอัปโหลด: GitHub Pages ให้เบราว์เซอร์เก็บไฟล์ไว้ใช้ซ้ำได้ 10 นาที (`Cache-Control: max-age=600`)
   เครื่องที่เพิ่งเปิดแอปก่อนอัปโหลดจึงอาจยังได้ไฟล์เก่าบางไฟล์ในช่วงนั้น (ถ้าหน้าตาแปลก ให้ปิด-เปิดแอปอีกครั้งหลังพ้น 10 นาที)

## 5. การใช้งานตามบทบาท

แถบบนสุด: ชื่อแอป + วันที่ที่เลือก (ภาษาไทย) · สถานะการเชื่อมต่อ (🟢 ออนไลน์ / 🟡 กำลังซิงก์… / 🟡 กำลังเชื่อมต่อใหม่… / ⚪ ออฟไลน์ —
**แตะเพื่อเปิด 🩺 ตรวจสอบการเชื่อมต่อ**) · 🔄 โหลดข้อมูลล่าสุด · 📅 เลือกวันที่ (‹ ›) · 🚪 ออกจากระบบ
(บนมือถือจอแคบ ปุ่มแสดงเฉพาะไอคอนและสถานะแสดงเฉพาะจุดสี เพื่อให้วันที่แสดงได้ครบ — แตะที่จุดสีได้เหมือนกัน)
แอปตรวจข้อมูลใหม่อัตโนมัติทุก 90 วินาทีขณะเปิดหน้าจอ (ถามเซิร์ฟเวอร์ก่อนว่ามีอะไรเปลี่ยนไหม จึงเบามาก), เมื่อกลับเข้าแอป (ถ้าข้อมูลเก่ากว่า 30 วินาที)
และเมื่อเน็ตกลับมา — ถ้าดึงไม่สำเร็จจะลองใหม่เองหลัง 5, 15, 30 และ 60 วินาที

ข้อมูลของแต่ละวันต้องโหลดจากเซิร์ฟเวอร์ก่อน (ถ้าเครื่องยังไม่มีข้อมูลวันนั้นจะขึ้น **"⏳ กำลังโหลดข้อมูล…"** ถ้ามีสำเนาเดิมในเครื่องจะแสดงสำเนานั้นแบบอ่านอย่างเดียวไปก่อน)
ระหว่างนั้นการแก้ Station/หมายเหตุ และปุ่มบันทึก, คัดลอก, วาง, ล้างข้อมูล จะยังกดไม่ได้ — เพื่อไม่ให้บันทึกทับข้อมูลจริงด้วยหน้าจอที่ยังว่างหรือเก่า

### Supervisor (มี 1 คน — สิทธิ์เต็ม)

| แท็บ | ทำอะไรได้ |
|---|---|
| 🏥 Station | เลือกคนลงแต่ละช่อง (รายชื่อในช่องจะไม่แสดงคนที่ลา หรือถูกเลือกไปแล้วในช่องอื่น) · พิมพ์หมายเหตุ · เมื่อมีป้าย **"ยังไม่ได้บันทึก"** ให้กด **💾 บันทึก Station & หมายเหตุ** (ระหว่างบันทึก ช่องต่าง ๆ ของวันนั้นจะล็อกไว้ชั่วคราว) · การ์ด **📋 สรุปรายชื่อผู้ลา / สถานะพิเศษ** ของวันนั้น · **⚙️ ตั้งค่าจำนวนคน** ของแต่ละ Station · ดูประวัติการแก้ไข 20 รายการล่าสุดของวันนั้น (การจัดการรายชื่อ/รหัสผ่าน/จำนวนคนจะอยู่ในประวัติของวันที่ทำรายการ) |
| 📝 การลา | **🗓️ ปฏิทินการลา** (จำนวนผู้ลาแต่ละวันของเดือน — แตะวันที่เพื่อดูรายชื่อและเลือกวันนั้น) · บันทึกวันลา/สถานะให้ **ทุกคน** · ดูสรุปวันลาของทุกคนหรือรายคนตามช่วงวันที่ (ไม่เกิน 2 ปีต่อครั้ง) — คนที่ถูกลบไปแล้วแต่มีวันลาในช่วงนั้นแสดงเป็น "ชื่อ (ลบแล้ว)" |
| 👥 รายชื่อ | เพิ่มรายชื่อ (รหัสเริ่มต้นเว้นว่าง = `1234`) · 🔑 ตั้งรหัสใหม่ให้ผู้อื่น (ที่แถวตัวเอง = เปลี่ยนรหัสของตัวเอง) · ↔️ ย้ายกลุ่มคนประจำ/ทีมแทนเวร · 🗑️ ลบ · 👑 โอนสิทธิ์ Supervisor · นำเข้าข้อมูลเดิม |
| 📊 สรุป/ส่งออก | ดาวน์โหลดรายงาน CSV (เปิดด้วย Excel; ไม่เกิน 2 ปีต่อไฟล์) · ดู/แชร์/บันทึกภาพตารางเป็น JPG · 📋 คัดลอกวันนี้ → 📌 วางลงอีกวัน (บันทึกทันที และตัดคนที่ลาในวันปลายทางออกให้) · 🗑️ ล้างข้อมูลทั้งวัน (ลบ Station, หมายเหตุ และ **วันลาทุกคน** ของวันนั้น) |

  - มีผลกับ **ทุกวันและทุกเครื่อง**: จำนวนช่องให้เลือกคน, "ต้องการ N คน", "(ขาด N)", ภาพ JPG และการวางข้อมูลลงวันอื่น
  - ลดจำนวนแล้ว **วันที่จัดคนไว้เกินจำนวนใหม่ยังเก็บรายชื่อครบ** (แสดงช่องเท่าที่บันทึกไว้) แต่จะเพิ่มคนในวันนั้นเกินจำนวนเดิมไม่ได้
  - ทุกเครื่องที่ใช้บันทึก Station ต้องเป็นแอป v2.1 (ดู [อัปเดตจาก v2.0 เป็น v2.1](#อัปเดตจาก-v20-เป็น-v21) ส่วน ค)
- **ถ้ามีคนอื่นแก้วันเดียวกันก่อนกดบันทึก** แอปจะถาม: **OK** = บันทึกทับด้วยข้อมูลของคุณ, **Cancel** = ทิ้งการแก้ไขแล้วโหลดข้อมูลล่าสุด
  (ใน v2.1 การที่แอปส่งซ้ำให้เองตอนเน็ตช้า ไม่ทำให้ขึ้นคำถามนี้หลอกแล้ว)
- ถ้าคนที่จัดลง Station มีวันลาในวันนั้น เซิร์ฟเวอร์จะตัดชื่อออกให้และแจ้งเตือน (แล้วแอปโหลดข้อมูลวันนั้นใหม่ให้)
- **ลบรายชื่อ** = ปิดการใช้งาน: ชื่อหายจากรายชื่อ, ถูกตัดออกจากเวรและวันลาตั้งแต่วันนี้เป็นต้นไป, ข้อมูลในอดีตยังอยู่ และเครื่องของคนนั้นจะออกจากระบบ
  - ในวันที่ผ่านมา ชื่อนั้นยังอยู่ในช่องเดิมเป็น **"ชื่อ (ลบแล้ว)"** — แก้วันนั้นแล้วบันทึกได้ตามปกติ (ชื่อเดิมยังคงอยู่ หรือเลือกเอาออกได้) แต่เลือกคนที่ถูกลบลงช่องใหม่ไม่ได้
  - ถ้าเพิ่มชื่อเดิมกลับมา ระบบจะเปิดใช้งานชื่อเดิม (รหัสใหม่ + บังคับเปลี่ยนรหัส) ประวัติเดิมยังผูกกับชื่อนั้น
- **โอนสิทธิ์** แล้วคุณจะกลายเป็น Staff ทันที ถ้ามีการแก้ Station ที่ยังไม่ได้บันทึก แอปจะถามก่อนว่าจะบันทึกก่อนโอน (OK) หรือทิ้งการแก้ไข · ลบรายชื่อของ Supervisor ไม่ได้ ต้องโอนสิทธิ์ก่อน
- กฎการตั้งชื่อ: 1–40 ตัวอักษร, ห้ามมี `,` `<` `>` `"` `'` `\` `|` `;` หรือขึ้นบรรทัดใหม่/แท็บ, ห้ามขึ้นต้นด้วย `=` `+` `-` `@` หรือ `__`,
  ห้ามเป็นคำสงวนของระบบ (เช่น `constructor`, `toString`), ห้ามซ้ำกับชื่อที่ใช้งานอยู่ (ถ้าเป็นชื่อที่เคยถูกลบ ระบบจะเปิดใช้งานชื่อเดิมแทนการสร้างใหม่)
- รายงาน CSV: คอลัมน์ `วันที่, ชื่อ, กลุ่ม, สถานะการลา, Station ที่ปฏิบัติงาน, หมายเหตุประจำวัน` (วันที่ไม่ได้อยู่ Station ใดแสดง `—`)
  คนที่ถูกลบแล้วแต่มีข้อมูลในช่วงนั้นแสดงเป็น "ชื่อ (ลบแล้ว)" กลุ่ม "ไม่อยู่ในระบบ" · ข้อความที่ขึ้นต้นด้วย `=` `+` `-` `@` จะมี `'` นำหน้า เพื่อไม่ให้ Excel ตีความเป็นสูตร
- สรุปวันลาและรายงาน CSV ดึงข้อมูลช่วงนั้นจากเซิร์ฟเวอร์ใหม่ทุกครั้งที่กด (ข้อมูลล่าสุดเสมอ)
- **iPhone (แอปบนหน้าจอโฮม):** ส่งออก CSV และบันทึกภาพจะเปิดหน้าต่างแชร์ของ iOS → เลือก **บันทึกไปยังไฟล์ (Save to Files)** ถ้าแชร์ไม่สำเร็จแอปจะดาวน์โหลดไฟล์แทน
- เครื่องมือสร้างภาพ JPG (html2canvas จาก `cdnjs.cloudflare.com`) โหลดตอนกดบันทึก/แชร์ภาพครั้งแรก (แอปพยายามเก็บสำเนาไว้ใช้ตอนออฟไลน์ตั้งแต่ติดตั้ง)
  ถ้าโหลดไม่ได้จะขึ้น **"⚠️ โหลดเครื่องมือสร้างภาพไม่สำเร็จ — ตรวจสอบอินเทอร์เน็ตแล้วลองใหม่"** — กดใหม่ได้เมื่อเน็ตกลับมา

- **คิว "(คนที่ N)"** ของ *พักร้อน* และ *Off เวร* เรียงตามเวลาที่ **เซิร์ฟเวอร์ได้รับ** การบันทึก
  กดสถานะเดิมซ้ำ = ไม่เปลี่ยนอะไร (คิวเดิม) แต่ถ้าเปลี่ยนเป็นประเภทอื่นแล้วเปลี่ยนกลับ จะได้คิวใหม่ต่อท้าย
- เมื่อบันทึกวันลา ถ้าคุณถูกจัดลง Station ของวันนั้นอยู่ ระบบจะตัดชื่อออกจาก Station ให้อัตโนมัติ
- เปลี่ยนรหัสแล้ว เครื่องอื่นที่ล็อกอินชื่อคุณอยู่จะถูกออกจากระบบ
- ถ้ายังใช้รหัสเริ่มต้นหรือรหัสที่ Supervisor ตั้งให้ แอปจะเปิดหน้าต่างเปลี่ยนรหัสให้เอง และใช้งานอย่างอื่นไม่ได้จนกว่าจะเปลี่ยน

## 6. ความปลอดภัยและข้อจำกัด

### ความปลอดภัย

- **Web App ตั้งเป็น *Anyone* แต่ไม่ได้เปิดโล่ง:** ใครก็เรียก URL ได้ แต่ทุกคำสั่งที่อ่าน/เขียนข้อมูลต้องมี token ที่ได้จากการล็อกอิน
  คำสั่งที่ไม่ต้องล็อกอินมีแค่ `ping`, รายชื่อผู้ใช้ (สำหรับหน้าล็อกอิน) และ `login`
  → คนที่รู้ URL จะเห็น **รายชื่อบุคลากร** ได้ และลองเดารหัสได้ — **ให้ทุกคนเปลี่ยนรหัสจาก 1234 โดยเร็ว**
  (ชื่อที่ยังใช้ 1234 อยู่ คนที่รู้ URL ล็อกอินแล้วตั้งรหัสใหม่แทนเจ้าของได้ · เพิ่มคน/ตั้งรหัสใหม่ให้ใคร ให้บอกให้เปลี่ยนรหัสทันที)
- **จำกัดการเดารหัส:** ใส่รหัสผิด 5 ครั้งต่อชื่อ (นับทั้งการล็อกอินและ "รหัสเดิม" ในหน้าต่างเปลี่ยนรหัส) → ชื่อนั้นถูกล็อก 10 นาทีนับจากครั้งที่ 5 (ความพยายามระหว่างที่ถูกล็อกไม่นับเพิ่ม และไม่ต่อเวลา)
  (ระหว่างล็อก แม้ใส่รหัสถูกก็เข้าไม่ได้) การนับทำภายใต้ล็อกของเซิร์ฟเวอร์ ส่งคำขอพร้อมกันหลายอันก็ได้ไม่เกิน 5 ครั้ง
  ปลดล็อกทันทีได้เมื่อ Supervisor ตั้งรหัสใหม่ให้ (🔑), เจ้าของชีตรัน `adminResetSupervisorPassword` (สำหรับ Supervisor) หรือเพิ่มชื่อที่เคยลบกลับมา
  - ข้อจำกัดที่เลี่ยงไม่ได้ของการล็อกรายชื่อ: คนที่รู้ URL สามารถ **จงใจใส่รหัสผิดให้ชื่อใดชื่อหนึ่งถูกล็อก** ได้ครั้งละ 10 นาที (ไม่ได้ข้อมูลอะไร แต่เจ้าของชื่อเข้าไม่ได้ชั่วคราว)
    ถ้าเกิดซ้ำ ๆ ให้สร้าง deployment ใหม่ (**Deploy > New deployment** ได้ URL ใหม่) แจ้งเฉพาะคนในหน่วยงาน แล้ว **Archive** deployment เดิมใน Manage deployments
- สิทธิ์ Supervisor ตรวจจากชีต `Config` ทุกคำสั่ง ไม่ได้เชื่อข้อมูลจากเครื่องผู้ใช้
  (คำสั่งอ่านใช้สำเนาข้อมูลสิทธิ์ในแคชของสคริปต์ ซึ่งถูกทิ้งทันทีเมื่อมีการบันทึกผ่านแอปหรือมีคนพิมพ์แก้ชีต — คำสั่งบันทึกอ่านชีตจริงทุกครั้ง
  ดังนั้นการลบรายชื่อ/เปลี่ยนรหัส/โอนสิทธิ์ผ่านแอปมีผลทันทีเหมือนเดิม)
- สคริปต์ได้สิทธิ์เฉพาะสเปรดชีตที่ผูกอยู่ (`spreadsheets.currentonly` + `@OnlyCurrentDoc`) — ไฟล์อื่นในบัญชีเจ้าของเข้าไม่ถึง
- **เก็บ Google Sheet เป็นส่วนตัว — อย่าแชร์สิทธิ์แก้ไข (Editor) ให้คนทั่วไป** ผู้มีสิทธิ์แก้ไขชีตจะ
  เปิด Apps Script ที่ผูกอยู่ได้ แก้โค้ดได้ และอ่านกุญแจลับที่ใช้สร้าง token ได้ (= ปลอมตัวเป็นใครก็ได้)
  แม้สิทธิ์ Viewer ก็เห็น hash รหัสผ่าน — ถ้าต้องการรายงาน ให้ใช้ปุ่มส่งออก CSV ในแอปแทนการแชร์ชีต
- repository GitHub แบบ Public ทำให้ `config.js` (ที่มี URL) เป็นสาธารณะ ถ้าไม่ต้องการ ให้ใช้วิธี ข ในขั้นที่ 6
- token อายุ 30 วัน ถ้ามือถือหาย: Supervisor ตั้งรหัสใหม่ให้คนนั้น (เครื่องเดิมจะหลุดทันที) หรือรัน `resetAllSessions` (ดูหัวข้อ 7)
- รหัสผ่านแบบข้อความธรรมดาของเวอร์ชันเดิมถูกลบออกจากทุกเครื่องที่เปิดเวอร์ชัน 2 และการออกจากระบบจะลบข้อมูลทั้งหมดของผู้ใช้ออกจากหน้าจอและแคช

### ข้อห้ามเมื่อเปิดดูชีตโดยตรง

- ❌ **ห้ามแก้หัวคอลัมน์ ห้ามสลับ/แทรก/ลบคอลัมน์ และห้ามเปลี่ยนชื่อชีต** — โค้ดอ้างคอลัมน์ตามลำดับตายตัว
- ❌ ห้ามเปลี่ยนชื่อคนในชีต `Staff` (ชื่อถูกใช้อ้างอิงในชีต `Days`/`Leaves`) และห้ามลบแถวใน `Staff` — ให้ลบผ่านแอป
- ❌ ห้ามลบแถวในชีต `Days` เพื่อ "ล้าง" วัน — ใช้ปุ่ม 🗑️ ล้างข้อมูลทั้งวันในแอป
  (แถวที่ถูกล้างจะยังอยู่เป็นแถวว่างที่มีเลข `version` — ตั้งใจให้เป็นแบบนั้น เพื่อกันเครื่องที่ถือข้อมูลเก่าบันทึกทับ)
- ⚠️ ถ้าจำเป็นต้องแก้ข้อมูลในชีตเอง (เช่น แก้คำผิดในหมายเหตุ): วันที่ต้องเป็นรูปแบบ `YYYY-MM-DD` เท่านั้น, ชื่อต้องตรงเป๊ะ
  การแก้ในชีตโดยตรง **ไม่ถูกบันทึกใน Audit** — ทางที่ดีที่สุดคือแก้ผ่านแอป
- แอปจะเห็นการแก้ในชีตเมื่อไร:
  - **พิมพ์/วาง/ลบค่าในช่อง** → ทุกเครื่องเห็นในการดึงข้อมูลครั้งถัดไป (ภายใน 90 วินาที หรือกด 🔄) เพราะ `onEdit` แจ้งสคริปต์ให้ทันที
  - **แทรก/ลบแถว, Restore เวอร์ชันเก่า, แก้ผ่านสคริปต์อื่น** (Google ไม่เรียก `onEdit` ให้) → แอปเห็นภายในประมาณ **10 นาที**
    หรือ **ทันที** หลังรัน `setup` จาก Apps Script editor (การกดบันทึกในแอปตรวจกับชีตจริงเสมอ จึงไม่เขียนทับด้วยข้อมูลเก่า)
- ชีต `Config` แถว `station_count:<id>` คือจำนวนคนที่ Station นั้นต้องการ (จำนวนเต็ม 1–10 ค่าอื่นหรือแถวที่หายไปจะถือเป็นค่าเริ่มต้น)
  — แนะนำให้แก้ผ่านปุ่ม ⚙️ ในแอปซึ่งบันทึก Audit ให้

## 7. กู้คืนและแก้ปัญหา

### ลืมรหัสผ่าน

| ใครลืม | วิธีแก้ |
|---|---|
| Staff | Supervisor ไปแท็บ **👥 รายชื่อ** กด 🔑 ที่ชื่อนั้น → ตั้งรหัสใหม่ (เว้นว่าง = `1234`) → คนนั้นจะถูกบังคับเปลี่ยนรหัสตอนล็อกอิน (ถ้าชื่อนั้นถูกล็อกเพราะใส่รหัสผิด จะปลดล็อกทันที) |
| **Supervisor** | เจ้าของชีตเปิด **Extensions > Apps Script** → เลือกฟังก์ชัน **`adminResetSupervisorPassword`** → **▷ Run** → รหัสของ Supervisor ปัจจุบันกลับเป็น `1234` (ปลดล็อกทันที) และต้องเปลี่ยนตอนล็อกอิน |
| Supervisor ลาออก/ไม่อยู่ | เจ้าของชีตแก้ค่าในชีต `Config` แถว `supervisor` คอลัมน์ `value` เป็นชื่อคนใหม่ (ต้องตรงกับชื่อในชีต `Staff` เป๊ะ) แล้วรัน `adminResetSupervisorPassword` ถ้าคนใหม่จำรหัสไม่ได้ (ถ้าชื่อไม่ตรง ฟังก์ชันจะแจ้งว่าไม่พบ Supervisor ในชีต Staff) |

### บังคับทุกคนออกจากระบบ

เปิด **Extensions > Apps Script** → เลือก **`resetAllSessions`** → **▷ Run**
ทุกเครื่องต้องล็อกอินใหม่ (รหัสผ่านไม่เปลี่ยน) ใช้เมื่อสงสัยว่ามีคนแอบใช้ หรือมือถือหายหลายเครื่อง
ถ้ามีปัญหาเฉพาะคนเดียว ให้ตั้งรหัสใหม่ให้คนนั้นแทน (เครื่องที่ล็อกอินชื่อนั้นจะหลุดเหมือนกัน)

### ตรวจการตั้งค่า Web App (ใช้เมื่อเชื่อมต่อไม่ได้)

เบราว์เซอร์ไม่ยอมให้แอปอ่านหน้าเว็บที่ Google ตอบกลับเมื่อการตั้งค่าผิด (หน้าล็อกอิน/หน้า error ไม่มี CORS header)
แอปจึงรายงานเป็น **"เชื่อมต่อเซิร์ฟเวอร์ไม่ได้"** เหมือนเน็ตหลุด (บางกรณีเป็น **"เซิร์ฟเวอร์ Google ขัดข้องชั่วคราว"** ที่ไม่หายเอง)
ก่อนอื่นให้เปิด [ตรวจสอบการเชื่อมต่อในแอป](#ตรวจสอบการเชื่อมต่อในแอป) — ถ้าเป็นเฉพาะบางเครือข่าย (เช่น Wi-Fi ของโรงพยาบาล แต่เน็ตมือถือใช้ได้)
แปลว่าการตั้งค่าถูกแล้ว ปัญหาอยู่ที่เครือข่าย ([ใช้งานผ่าน Wi-Fi ของโรงพยาบาล](#ใช้งานผ่าน-wi-fi-ของโรงพยาบาล)) — ถ้าเป็นทุกเครือข่ายและทุกเครื่อง ให้ตรวจตามลำดับ:

1. เปิด URL `/exec` ใน **หน้าต่างไม่ระบุตัวตน** (Incognito / InPrivate) หรือบนมือถือที่ไม่ได้ล็อกอิน Google — ต้องเห็น `"ok":true` (และ `"version":"2.1.0"`)
   (อย่าทดสอบในเบราว์เซอร์ที่ล็อกอินบัญชีเจ้าของ เพราะจะผ่านเสมอ)
2. ถ้าเห็นหน้าล็อกอิน Google / "ไม่มีสิทธิ์เข้าถึง" → **Deploy > Manage deployments > ✏️** ตั้ง *Who has access* = **Anyone** และ *Execute as* = **Me** → **Deploy**
3. ถ้าเห็นหน้า "ไม่พบ" / error → URL ผิดหรือ deployment ถูก Archive ไปแล้ว: คัดลอก Web app URL ใหม่จาก Manage deployments (ต้องลงท้าย `/exec` ไม่ใช่ `/dev`)
   แล้วแก้ใน `config.js` หรือ "⚙️ ตั้งค่าการเชื่อมต่อ" ในหน้าล็อกอิน
4. ตรวจว่ากด Save `Code.gs` ก่อนออก Version และดูข้อผิดพลาดใน **Executions** (แถบซ้ายของ Apps Script)
5. บัญชี Workspace ที่ปิดตัวเลือก Anyone → ใช้บัญชี @gmail.com

### ตรวจสอบการเชื่อมต่อในแอป

หน้าจอ **🩺 ตรวจสอบการเชื่อมต่อ** ใช้ได้ **โดยไม่ต้องเข้าสู่ระบบ** เปิดได้ 3 ทาง:

- แตะ **สถานะการเชื่อมต่อ** ที่แถบบน (บนมือถือคือจุดสีข้างวันที่)
- ปุ่ม **🩺 ตรวจสอบการเชื่อมต่อ** ในแถบ "📴 …" ที่ขึ้นตอนออฟไลน์
- ลิงก์ **🩺 ตรวจสอบการเชื่อมต่อ** ในหน้าเข้าสู่ระบบ และในหน้าตั้งค่าการเชื่อมต่อ (ก่อนตั้ง URL จะตรวจได้เฉพาะบรรทัด 1–2)

กด **▶️ เริ่มตรวจสอบ** → แอปตรวจทีละบรรทัด (บรรทัดละไม่เกิน 20 วินาที) พร้อมเวลาที่ใช้ (ms):
✅ ผ่าน · ⚠️ ผ่านแต่มีข้อสังเกต (เช่น **"แต่ตอบช้า"** เมื่อเกิน 10 วินาที) · ❌ ไม่ผ่าน · ➖ ข้าม (ยังไม่ได้ตั้งค่า URL)

| บรรทัด | ตรวจอะไร | ถ้าไม่ผ่าน |
|---|---|---|
| 1. อินเทอร์เน็ตของเครื่อง | เครื่องต่อ Wi-Fi/เน็ตมือถืออยู่หรือไม่ | เปิด Wi-Fi หรือเน็ตมือถือ |
| 2. หน้าเว็บของแอป (`<โฮสต์ของแอป>`) | ดาวน์โหลดไฟล์เล็ก ๆ ของแอปจากเว็บโฮสต์จริง (ไม่ใช้สำเนาในเครื่อง) | เครือข่ายนี้ยังใช้อินเทอร์เน็ตไม่ได้ (เช่น Wi-Fi ต้อง login ใหม่) หรือบล็อกโฮสต์ของแอป |
| 3. เซิร์ฟเวอร์ Google Apps Script (`script.google.com`) | คำขอไปถึงด่านแรกของ Google ได้หรือไม่ | เครือข่ายนี้บล็อก `script.google.com` |
| 4. ช่องทางรับคำตอบ (`script.googleusercontent.com`) | ส่งคำสั่งทดสอบ (ping) ครบทั้งทางเหมือนที่แอปใช้จริง — ถ้าผ่านจะบอกเวอร์ชันของ `Code.gs` เช่น "เซิร์ฟเวอร์ตอบกลับปกติ (เวอร์ชัน 2.1.0)" | ถ้าบรรทัด 3 ผ่านแต่บรรทัดนี้ไม่ผ่าน: **"โดเมน script.googleusercontent.com น่าจะถูกบล็อกโดยเครือข่ายนี้"** · กรณีอื่นแสดงข้อความผิดพลาด เช่น "เซิร์ฟเวอร์ Google ขัดข้องชั่วคราว" |
| 5. (ไม่จำเป็นต่อการใช้งาน) `fonts.googleapis.com`, `cdnjs.cloudflare.com` | ฟอนต์ Sarabun และเครื่องมือสร้างภาพ | ขึ้นแค่ ⚠️ — แอปใช้งานได้ (ใช้ฟอนต์ของเครื่อง และอาจบันทึกภาพ JPG ไม่ได้) |

ใต้ตารางมี **สรุปผล** หนึ่งย่อหน้า เช่น "เชื่อมต่อเซิร์ฟเวอร์ได้ตามปกติ" หรือ "เข้าถึง script.google.com ไม่ได้ — เครือข่ายนี้อาจบล็อก Google Apps Script ลองใช้อินเทอร์เน็ตมือถือ หรือแจ้งฝ่าย IT"

**📋 คัดลอกผล** คัดลอกรายงานเป็นข้อความ (เวอร์ชันแอป, เวลา, ชนิดเบราว์เซอร์, สถานะการเชื่อมต่อในแอป, ผลทุกบรรทัด และสรุป) ไปวางใน LINE/อีเมลส่งฝ่าย IT ได้ทันที
— รายงาน **ไม่มี** token, URL ของ Web App หรือรายชื่อบุคลากร (มีเฉพาะชื่อโดเมน) · ถ้าคัดลอกไม่ได้ ให้บันทึกภาพหน้าจอแทน

### ใช้งานผ่าน Wi-Fi ของโรงพยาบาล

แอปต้องเข้าถึงโดเมนเหล่านี้ผ่าน HTTPS (พอร์ต 443):

| โดเมน | ใช้ทำอะไร | จำเป็นไหม |
|---|---|---|
| โฮสต์ของหน้าเว็บ เช่น `<ชื่อผู้ใช้>.github.io` | ไฟล์ของแอป (เปิดครั้งแรกและตอนอัปเดต — นอกนั้นเปิดจากสำเนาในเครื่องได้) | ✅ จำเป็น |
| `script.google.com` | ส่งคำสั่งไปเซิร์ฟเวอร์ (Google Apps Script) | ✅ จำเป็น |
| `script.googleusercontent.com` | รับคำตอบจากเซิร์ฟเวอร์ (Google ส่งต่อมาที่โดเมนนี้ทุกคำสั่ง) | ✅ จำเป็น |
| `fonts.googleapis.com`, `fonts.gstatic.com` | ฟอนต์ Sarabun | ไม่จำเป็น (ใช้ฟอนต์ไทยของเครื่องแทน) |
| `cdnjs.cloudflare.com` | เครื่องมือบันทึก/แชร์ภาพตาราง JPG | เฉพาะตอนบันทึก/แชร์ภาพ |

v2.1 ไม่ใช้ `cdn.tailwindcss.com` แล้ว (สไตล์อยู่ในไฟล์ของแอปเอง)

**ตรวจว่าปัญหาอยู่ที่ Wi-Fi หรือไม่** (ใช้มือถือเครื่องเดียวกัน):

1. ต่อ Wi-Fi ของโรงพยาบาล (เช่น `wifi-officer`) → เปิดแอป → 🩺 → **▶️ เริ่มตรวจสอบ** → **📋 คัดลอกผล** แล้ววางเก็บไว้ (LINE/โน้ต)
2. ปิด Wi-Fi ใช้ **เน็ตมือถือ** → **🔁 ตรวจสอบอีกครั้ง** → **📋 คัดลอกผล** อีกชุด
3. เทียบผล:
   - เน็ตมือถือผ่านทุกบรรทัด แต่ Wi-Fi ❌ ที่บรรทัด 3 หรือ 4 → **เครือข่ายของโรงพยาบาลบล็อกหรือกรอง Google Apps Script** → ส่งข้อความด้านล่างพร้อมผลทั้งสองชุดให้ฝ่าย IT
   - Wi-Fi ❌ ตั้งแต่บรรทัด 2 → Wi-Fi อาจต้อง login ใหม่ (หน้า login ของ Wi-Fi หมดเวลา) → เปิดเบราว์เซอร์เพื่อ login Wi-Fi แล้วตรวจอีกครั้ง ถ้าเป็นบ่อยให้ขอข้อ 3 ในข้อความด้านล่าง
   - ทั้งสองเครือข่ายไม่ผ่านที่บรรทัด 4 ด้วย "เซิร์ฟเวอร์ Google ขัดข้องชั่วคราว" → ปัญหาฝั่ง Google ชั่วคราว รอสักครู่แล้วตรวจใหม่
   - ⚠️ "แต่ตอบช้า" → เครือข่ายช้า แอปยังใช้ได้และลองใหม่ให้เอง

**ข้อความขอความช่วยเหลือจากฝ่าย IT** (คัดลอก แก้ส่วนใน `< >` แล้วส่งพร้อมผลตรวจทั้งสองชุด):

```text

เรียน ฝ่ายเทคโนโลยีสารสนเทศ

เมื่อใช้ผ่าน Wi-Fi ของโรงพยาบาล แอปเชื่อมต่อเซิร์ฟเวอร์ไม่ได้หรือช้าผิดปกติ แต่ใช้ผ่านอินเทอร์เน็ตมือถือได้ตามปกติ

   - <โฮสต์ของแอป เช่น xxxx.github.io>    (หน้าเว็บของแอป)
   - script.google.com                       (เซิร์ฟเวอร์ Google Apps Script)

   เนื่องจากเมื่อ session หมดอายุ คำขอของแอปจะถูกพาไปหน้า login ของ Wi-Fi และล้มเหลว

ผู้ประสานงาน: <ชื่อ / เบอร์โทรภายใน>
```

### เห็นเวอร์ชันเก่า / ไม่เห็นการเปลี่ยนแปลง

1. ตรวจว่าเปลี่ยน `VERSION` ใน `sw.js` และอัปโหลดขึ้น GitHub แล้ว (ไฟล์ใน `js/` และ `css/` ต้องอยู่ในโฟลเดอร์ของมัน — หัวข้อ 4) แล้วรอประมาณ 10 นาที
2. เปิดแอปขณะออนไลน์ แล้วรอปุ่ม **"🔄 มีเวอร์ชันใหม่ — แตะเพื่อโหลดใหม่"** → แตะ
3. ถ้าปุ่มไม่ขึ้น: ปิดแอปให้หมด (ปัดทิ้งจากหน้าสลับแอป / ปิดทุกแท็บ) แล้วเปิดใหม่ — อาจต้องทำ 2 ครั้ง (ครั้งแรกติดตั้งเวอร์ชันใหม่เบื้องหลัง ครั้งที่สองใช้งาน)
4. บนคอมพิวเตอร์กด **Ctrl+Shift+R**
5. ทางสุดท้าย: ล้างข้อมูลเว็บไซต์ของโดเมนนั้นในเบราว์เซอร์ — ⚠️ **อย่าทำบนเครื่องที่ยังไม่ได้นำเข้าข้อมูลเดิม**, ต้องล็อกอินใหม่
   และจะลบข้อมูลของเว็บอื่นทุกเว็บใน `<ชื่อผู้ใช้>.github.io` ในเบราว์เซอร์นั้นด้วย
6. ถ้าเป็นฝั่งเซิร์ฟเวอร์: ตรวจว่าออก **New version** ใน Manage deployments แล้ว (Save อย่างเดียวไม่พอ) — ดูเวอร์ชันที่ใช้อยู่ได้จาก 🩺 บรรทัด "ช่องทางรับคำตอบ"
7. แอปไม่มีสี/ไม่จัดหน้า (ปุ่มเรียงเป็นข้อความธรรมดา) → บนโฮสต์ไม่มี `css/tailwind.css` — อัปโหลดโฟลเดอร์ `css` (หัวข้อ 4)

### ข้อมูลหาย / ลบผิด

ดูก่อนว่าใครทำอะไรเมื่อไรจากชีต `Audit` (ไม่มีข้อความหมายเหตุ) — ถ้าเสียหายไม่มาก การกรอกใหม่ผ่านแอปง่ายและปลอดภัยที่สุด

Google Sheets เก็บประวัติไว้ให้ที่ **File > Version history > See version history** มี 2 วิธี:

1. **กู้เฉพาะแถวที่หาย (แนะนำ):** เลือกเวลาที่ต้องการ → เมนู ⋮ ของเวอร์ชันนั้น > **Make a copy** → เปิดสำเนา
   คัดลอกแถวของวันที่ต้องการในชีต `Days` / `Leaves` แล้ววางทับแถวของวันเดียวกันในชีตจริง (ถ้าไม่มีแถวของวันนั้นให้วางต่อท้าย)
   **ห้ามคัดลอกชีต `Staff` / `Config`** จากนั้นให้ทุกคนกด 🔄 (การวางค่าลงช่องถือเป็นการแก้ชีต แอปจะเห็นในการดึงข้อมูลครั้งถัดไป)
2. **Restore this version ทั้งไฟล์:** ย้อนทุกชีต รวมถึง `Staff` และ `Config` ด้วย จึงมีผลข้างเคียง:
   - เครื่องที่เคยถูกบังคับออก (มือถือหายที่ตั้งรหัสใหม่ให้แล้ว, คนที่ถูกลบ, เครื่องอื่นของคนที่เปลี่ยนรหัส) **กลับมาใช้งานได้อีก**
   - รหัสผ่านที่เปลี่ยนหลังเวลานั้นกลับเป็นรหัสเดิม และ Supervisor/รายชื่อ/จำนวนคนของ Station กลับเป็นแบบเดิม
   - ดังนั้น **หลัง Restore ให้รัน `resetAllSessions` ทันที** แล้วแจ้งคนที่เปลี่ยนรหัสหลังเวลานั้นว่าต้องใช้รหัสเดิม (หรือให้ Supervisor ตั้งรหัสใหม่ให้)
     — การรันนี้ยังทำให้ทุกเครื่องเห็นข้อมูลที่ย้อนกลับทันที (Restore ไม่ผ่าน `onEdit` ถ้าไม่รันอะไรเลย แอปจะเห็นภายในประมาณ 10 นาที)
   - ควรทำตอนที่ไม่มีใครกำลังบันทึก

### สร้าง `css/tailwind.css` ใหม่ (เมื่อแก้คลาส)

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-css.ps1
```

- **รันใหม่ทุกครั้งที่เพิ่มหรือเปลี่ยนคลาสของ Tailwind** ใน `index.html` หรือ `js/*.js` (รวมคลาสที่ประกอบเป็นข้อความใน JavaScript)
  — แอปใช้เฉพาะ `css/tailwind.css` ที่ build ไว้ คลาสใหม่ที่ยังไม่ได้ build จะไม่มีผลบนหน้าจอ
- วิธีทำงาน: เปิด Edge แบบ headless ไปที่ `tools/build-css.html` (`--allow-file-access-from-files`) ซึ่งโหลด Tailwind Play CDN
  เวอร์ชันที่ตรึงไว้ (`https://cdn.tailwindcss.com/3.4.17`) อ่าน `index.html` + `js/*.js` แล้วใส่ทุกคำที่หน้าตาเหมือนคลาสลงใน element ที่ซ่อนไว้
  รอจนสไตล์ที่ Play CDN สร้างนิ่ง แล้วส่งผลออกมาใน `<pre id="css-output">` — สคริปต์ดึงผลนั้นมาเขียน `css/tailwind.css` (UTF-8 ไม่มี BOM)
- ต้องต่ออินเทอร์เน็ต (โหลด Play CDN) · ก่อนเขียนไฟล์ สคริปต์ตรวจว่าเป็น Tailwind v3.4.17 และมีกฎตัวอย่างครบ ถ้าไม่ผ่านจะ exit 1 โดยไม่เขียนทับ
- ตัวเลือก: `-Edge <path ของ msedge.exe>`, `-TimeoutSec` (ค่าเริ่มต้น 120)
- เสร็จแล้ว **เปลี่ยน `VERSION` ใน `sw.js`** ก่อนอัปโหลด (หัวข้อ 4) และรันเทสต์

### หลักสำคัญเวลาแก้โค้ด

- `Code.gs` ต้องเป็น JavaScript ที่รันได้ทั้งใน Apps Script (V8) และเป็น `<script>` ธรรมดาในเบราว์เซอร์ (เทสต์โหลดไฟล์นี้ตรง ๆ) — ห้ามใช้ `?.`, `??`, `import/export`
- เรียกเวลาปัจจุบันผ่าน `now_()` เท่านั้น, เขียนชีตผ่าน `writeRows_` เท่านั้น (ขยายแถวด้วย `insertRowsAfter` ให้อัตโนมัติ — ดูเหตุผลใน ARCHITECTURE)
- ฝั่งหน้าเว็บ: ข้อมูลจริงอยู่ใน `state` ไม่ใช่ใน DOM, ข้อความจากผู้ใช้ต้องผ่าน `Utils.escapeHtml` ทุกครั้ง, ห้ามใช้ `toISOString()` หาวันที่ปฏิทิน,
  object ที่ใช้ชื่อคนเป็น key ต้องไม่มี prototype (`Object.create(null)` หรือ `Map`)
- ค่าคงที่ร่วม (`STATIONS` ส่วน id/name/count, `LEAVE_TYPES`, `QUEUE_TYPES`, `STATION_COUNT_MIN`/`MAX`) ต้องตรงกันทุกตัวอักษรใน `Code.gs` และ `js/utils.js`
- ใช้คลาส Tailwind ใหม่ → รัน `tools/build-css.ps1` (ไม่มี Tailwind CDN ตอนใช้งานจริงแล้ว)
- ถ้าเพิ่ม/เปลี่ยน URL จาก CDN ใน `index.html` (หรือ URL ของ html2canvas ใน `js/app.js`) ต้องแก้ `CDN_ASSETS` ใน `sw.js` ให้ตรงกัน (`tests/sw.test.html` ตรวจให้)
- แก้ไฟล์หน้าเว็บแล้วเปลี่ยน `VERSION` ใน `sw.js` ทุกครั้ง
