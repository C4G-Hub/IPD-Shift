# เวร IPD — ตารางเวรนักรังสีการแพทย์ (เวอร์ชัน 3.2 · Google Sheets)

แอปจัดตารางเวรและบันทึกวันลาของหน่วยงานผู้ป่วยใน (IPD) ใช้งานบนมือถือแบบ PWA (ติดตั้งไว้บนหน้าจอโฮมได้)
เวอร์ชัน 2 ขึ้นไปเก็บข้อมูลกลางไว้ใน **Google Sheet** ของหน่วยงาน ผ่าน **Google Apps Script Web App**
ทุกเครื่องจึงเห็นข้อมูลชุดเดียวกัน และเซิร์ฟเวอร์เป็นผู้ตรวจสิทธิ์ทุกคำสั่ง

## 1. ภาพรวม และสิ่งที่เปลี่ยนจากเวอร์ชันเดิม

ตั้งแต่ v2.9 แถบด้านล่างมี 3 ปุ่ม: **วันนี้** (จัดคนลง Station รายวัน + ของฉันวันนี้ + ผู้ลา + หมายเหตุ), **การลา** (ปฏิทิน + บันทึกวันลา/สถานะ
+ คำขอของฉัน + สรุปวันลา) และ **เมนู** (โปรไฟล์ของฉัน, เปลี่ยนรหัสผ่าน, ตรวจสอบการเชื่อมต่อ, ออกจากระบบ — และสำหรับ Supervisor:
**อนุมัติการลา**, **รายชื่อบุคลากร**, **รายงานและส่งออก**)
(v2.2 และก่อนหน้ามี 4 แท็บ: Station, การลา, รายชื่อ, สรุป/ส่งออก — หัวข้อด้านล่างที่เขียนถึงเวอร์ชันเก่าใช้ชื่อแท็บเดิม)

### มีอะไรใหม่ใน v3.2 (Dashboard แจ้งปัญหา แชท)

v3.2 ต้องใช้คู่กับ `Code.gs` เวอร์ชัน 3.2.0 (วิธีอัปเดตอยู่ที่ [อัปเดตจาก v3.1 เป็น v3.2](#อัปเดตจาก-v31-เป็น-v32)) — ข้อมูลเดิมอยู่ครบ ไม่มีใครต้องเข้าสู่ระบบใหม่
แอป v3.0/v3.1 ที่ยังไม่อัปเดตใช้งานกับเซิร์ฟเวอร์ 3.2 ได้ตามปกติ (แต่ไม่เห็นของใหม่) · แอป v3.2 กับเซิร์ฟเวอร์ 3.1 หรือ 3.0 จะซ่อน Dashboard แจ้งปัญหา และแชทไว้ และบอก Supervisor ให้อัปเดต `Code.gs`

- **Dashboard ของฉัน** (เมนู → ของฉัน): พักร้อนคงเหลือ คะแนนใบประกอบ (CE) และวันหมดอายุใบประกอบ สถิติการลา การอยู่ Station จำนวนเวร และเวร 7 วันข้างหน้า
  — ยอดพักร้อน: แต่ละคนกรอก "ยอดคงเหลือ ณ สิ้นวันที่ …" เอง (หรือ Supervisor กรอกให้) ระบบหักวันลาพักร้อนที่อนุมัติแล้วเฉพาะวันทำการหลังวันนั้น นับถึงสิ้นปีงบประมาณ (30 ก.ย.) — ไม่มีการเพิ่มสิทธิ์อัตโนมัติ ต้องกรอกใหม่ทุกปีงบ
- **Dashboard ทีม** (Supervisor): ตารางทุกคน การลารายเดือน ความเท่าเทียมของเวร วันที่คนไม่ครบ ปัญหาค้าง และส่งออก Excel
- **แจ้งปัญหา** (เมนู → ของฉัน และปุ่มบนการ์ด Station): แจ้งปัญหาของแต่ละ Station พร้อมรูปไม่เกิน 3 รูป ทุกคนเห็นและกด "แก้แล้ว" ได้ ·
  เปิดซ้ำ ลบเรื่อง และล้างรูปเก่าเฉพาะ Supervisor · **ห้ามถ่ายติดใบหน้า ชื่อ หรือ HN ของผู้ป่วย** (ผู้แจ้งหรือ Supervisor ลบรูปได้ทันที)
- **แชทส่วนตัว** (ไอคอนแชทที่หัวแอป): คุยกันแบบ 1 ต่อ 1 ข้อความถึงภายในประมาณ 5–15 วินาทีเมื่อเปิดห้องแชทค้างไว้ และภายใน 90 วินาทีเมื่อไม่ได้เปิด ·
  ไม่เกิน 20 ข้อความต่อนาที · ไม่มีการแจ้งเตือนเมื่อปิดแอป · **ห้ามส่งข้อมูลผู้ป่วย**
- **ตารางเวรส่งออกเป็น Excel (.xlsx)** แล้ว ("รายงานและส่งออก" เดิมยังเป็น .csv)
- **วันหยุดในปฏิทินการลา:** วันหยุดที่ Supervisor ลงไว้ (ตั้งค่าการจัดเวร → วันหยุด) ขึ้นในปฏิทินหน้า การลา ของทุกคน พร้อมบรรทัด "วันหยุดเดือนนี้"
- **จัดลำดับคนใน Station** (Supervisor): กด **จัดลำดับ** บนการ์ด Station เพื่อเลื่อนคนขึ้นลง แล้วกด **บันทึก** — ลำดับนี้ใช้ในรูปที่แชร์และรายชื่อของทุกคน ·
  การ์ด Portable บอกว่าแต่ละคนจะได้สายไหน (คนประจำสายยังอยู่สายเดิม คนแทนได้สายที่ว่างตามลำดับ)
- **ความเป็นส่วนตัว:** ข้อความแชทและรูปแจ้งปัญหา **เก็บอยู่ในชีตของหน่วยงาน — ใครเปิดชีตได้ก็อ่านได้** (ในแอป แชทเห็นเฉพาะ 2 คนที่คุยกัน Supervisor ก็ไม่เห็น) ·
  ยอดพักร้อนและคะแนนใบประกอบของแต่ละคนเห็นเฉพาะเจ้าของและ Supervisor · ข้อความแชท รายละเอียดปัญหา และหมายเหตุ ไม่อยู่ในชีต `Audit` ·
  **ลบรูป ลบเรื่อง หรือล้างรูปในแอป ไม่ได้ลบออกจากประวัติเวอร์ชันของชีต** (Google เก็บเวอร์ชันเก่าไว้ ใครมีสิทธิ์แก้ไขชีตเปิดดูได้ที่ ไฟล์ → ประวัติเวอร์ชัน) —
  จึง **ห้ามถ่ายติดผู้ป่วยตั้งแต่แรก** · ถ้าเกิดขึ้นแล้ว ให้ลบรูปในแอปทันที จำกัดคนที่มีสิทธิ์เปิดชีตให้น้อยที่สุด และแจ้งผู้รับผิดชอบ PDPA ของโรงพยาบาล

### มีอะไรใหม่ใน v3.1 (ระบบจัดเวร)

v3.1 ต้องใช้คู่กับ `Code.gs` เวอร์ชัน 3.1.0 (วิธีอัปเดตอยู่ที่ [อัปเดตจาก v3.0 เป็น v3.1](#อัปเดตจาก-v30-เป็น-v31)) — ข้อมูลเดิมอยู่ครบ ไม่มีใครต้องเข้าสู่ระบบใหม่
แอป v3.0 ที่ยังไม่อัปเดตใช้งานกับเซิร์ฟเวอร์ 3.1 ได้ตามปกติ (แต่ไม่เห็นของใหม่) · แอป v3.1 กับเซิร์ฟเวอร์ 3.0 จะซ่อนระบบจัดเวรไว้ และบอก Supervisor ให้อัปเดต `Code.gs`

- **แท็บใหม่ "ตารางเวร"** (แถบล่าง): สาย Portable 1–3 (เทค + ผู้ช่วย) · เวรกลางวัน ER / IPD · ภารกิจพิเศษวันละ 2 คนพร้อมเบอร์โทร · ทั้งเดือน
  ทุกคนดูได้ บันทึกเป็นรูป หรือไฟล์ .csv (เปิดด้วย Excel ได้) — Supervisor ตั้งคนประจำเดือน กด **สร้างอัตโนมัติทั้งเดือน** แก้รายช่อง แล้วบันทึก
- **ของฉันวันนี้** บอกสาย Portable เวรกลางวัน และภารกิจพิเศษของตัวเอง
- **ทีมแทนเวรวันนี้** (หน้าวันนี้ ทุกคนเห็น): **Supervisor เท่านั้น** วาง แก้ หรือลบข้อความจาก LINE ได้ ระบบอ่านชื่อให้ตรวจก่อนบันทึก (ชื่อที่ไม่แน่ใจจะถาม ไม่เดา)
- **ข้อเสนอจัดคน (Supervisor):** วันที่ยังไม่ได้จัด ระบบเสนอคนลง Station พร้อมเหตุผล — ยังไม่ถูกบันทึกจนกว่าจะกดบันทึก
- **เมนู → ตั้งค่าการจัดเวร (Supervisor):** Station ที่แต่ละคนอยู่ได้ · ผู้ช่วย · วันหยุด · ผู้ขึ้นภารกิจพิเศษ (ลำดับ + เบอร์) · ชื่อเรียกอื่น · ลำดับการเติมคน · **ห้ามอยู่คู่กัน** (คู่ที่ระบบจะไม่เสนอให้อยู่ Station เดียวกัน — เห็นเฉพาะ Supervisor) ·
  ผู้ช่วยตั้งชื่อซ้ำกับนักรังสีการแพทย์ได้ (เป็นคนละคน — ลบรายชื่อนักรังสีฯ ไม่กระทบผู้ช่วยชื่อเดียวกัน)
- **ความเป็นส่วนตัว:** เบอร์โทรและชื่อเรียกอื่นของทุกคน **ทุกคนที่เข้าสู่ระบบเห็นได้** (ใช้ในตารางภารกิจและการอ่านข้อความแทนเวร) ·
  ข้อความแทนเวรที่ Supervisor วาง (ข้อความจาก LINE ของทีม) **ทุกคนที่เข้าสู่ระบบอ่านได้** (การ์ดมีปุ่ม "ดูข้อความต้นฉบับ") และถูกเก็บไว้ในเครื่องของแต่ละคนพร้อมตารางเวร —
  อย่าใส่ข้อมูลส่วนตัวที่ไม่ควรให้ทุกคนเห็น · ข้อความไม่อยู่ในชีต `Audit` · ลบรายชื่อพนักงาน = ลบเบอร์/ชื่อเรียก/คู่ "ห้ามอยู่คู่กัน" ของคนนั้นด้วย แต่ชื่อในตารางเวรเก่ายังอยู่
- ลาหลังจัดตารางเวรแล้ว ระบบ **ไม่แก้ตารางเวรเอง** แต่ขึ้นป้าย "ลา" และเสนอคนแทนให้ Supervisor กดยืนยัน

**เริ่มใช้ครั้งแรก (Supervisor ทำในแอป ตามลำดับนี้):**
**เมนู → ตั้งค่าการจัดเวร:** ผู้ช่วย → วันหยุด → Station ที่แต่ละคนอยู่ได้ → ภารกิจพิเศษ (ลำดับ + เบอร์) →
แล้วไปที่แท็บ **ตารางเวร → คนประจำ** (เลือกเดือน → ตั้งคนประจำ → บันทึก) → **Portable** → **สร้างอัตโนมัติทั้งเดือน** → ตรวจ → **บันทึก**

v3.0 ต้องใช้คู่กับ `Code.gs` เวอร์ชัน 3.0.0 (วิธีอัปเดตอยู่ที่ [อัปเดตจาก v2.9 เป็น v3.0](#อัปเดตจาก-v29-เป็น-v30)) — ข้อมูลเดิมอยู่ครบ ไม่มีใครต้องเข้าสู่ระบบใหม่

- **ลาหาหมอแบบระบุเวลา** — ประเภทใหม่ 2 แบบ **ลาหาหมอตอนเช้า** และ **ลาหาหมอตอนบ่าย** เลือกช่วงเวลาสำเร็จรูป
  (เช้า 08:00–10:00 · 08:00–12:00 · 09:00–11:00 · 10:00–12:00 / บ่าย 13:00–15:00 · 13:00–16:00 · 14:00–16:00) หรือกำหนดเวลาเองก็ได้
  - เวลาที่กำหนดเอง: อยู่ระหว่าง **08:00–16:00 น.** · **ตอนเช้า** = เริ่มก่อน 12:00 น. (จบหลังเที่ยงได้ เช่น 11:30–13:30)
    · **ตอนบ่าย** = เริ่มตั้งแต่ 12:00 น. — ถ้าเลือกประเภทไม่ตรงกับเวลาเริ่ม แอปจะบอกให้เปลี่ยนประเภท
  - **ไม่นับเป็นวันลา**: นอกช่วงเวลานั้นยังปฏิบัติงานตามตาราง และยังจัดลง Station ได้ (ในหน้าวันนี้จะมีป้าย "หาหมอ 09:00–11:00" ข้างชื่อ)
  - ปฏิทิน จำนวนผู้ลา สรุปวันลา และ CSV นับเฉพาะคนที่ **ลาทั้งวัน** — ลาหาหมอแสดงเป็นบรรทัดของตัวเองพร้อมเวลา
- **ลาพักร้อนเกินจำนวนต้องรออนุมัติ** — พักร้อนของแต่ละวัน **2 คนแรก** (ตั้งได้ในชีต `Config` แถว `vacation_auto_slots`) ได้รับอนุมัติทันทีเหมือนเดิม
  ตั้งแต่คนที่ 3 แผ่นบันทึกการลาจะเตือนก่อนว่า "มีผู้ลาพักร้อนแล้ว N คน คำขอนี้จะส่งให้ Supervisor อนุมัติ" และปุ่มเปลี่ยนเป็น **ส่งคำขอ**
  - ระหว่าง **รออนุมัติ** ยังไม่นับเป็นวันลา และยังอยู่ใน Station ได้ตามปกติ
  - พักร้อนที่ Supervisor บันทึกให้เอง อนุมัติทันทีเสมอ · ถ้าคนก่อนหน้ายกเลิก คำขอที่รออยู่ **ไม่** ได้รับอนุมัติเองอัตโนมัติ
- **คำขอของฉัน** (หน้าการลา) — คำขอที่ **รออนุมัติ** หรือ **ไม่อนุมัติ** ของตัวเอง (ย้อนหลังไม่เกิน 30 วัน) แตะเพื่อดูผล ใครเป็นผู้พิจารณา และเหตุผล
  - คำขอที่ไม่อนุมัติ: กด **ขอใหม่** (ได้คิวใหม่ต่อท้าย) หรือ **ลบคำขอ**
  - เมื่อคำขอไม่ได้รับอนุมัติ หน้าการลาจะมีข้อความแจ้งพร้อมเหตุผล — กด **ดูคำขอ** เพื่อเปิดวันนั้น หรือกด ✕ เพื่อซ่อนข้อความ
- **อนุมัติการลา (Supervisor)** — เมื่อมีคำขอรออยู่ หน้า วันนี้ และ การลา จะมีข้อความ "มีคำขอพักร้อนรออนุมัติ N รายการ" และ เมนู มีตัวเลขแจ้ง
  - **เมนู → งานหัวหน้า → อนุมัติการลา** รวมคำขอทั้งหมดเรียงตามวันที่ (วันที่ผ่านไปแล้วอยู่ท้าย) พร้อมข้อมูลประกอบของวันนั้น:
    ใครลาพักร้อนแล้วบ้าง ใครลาอย่างอื่น และคิวของคำขอ
  - **อนุมัติ** กดครั้งเดียว — ถ้าคนนั้นอยู่ใน Station ของวันนั้น แอปจะถามก่อน เพราะการอนุมัติจะนำออกจาก Station ให้อัตโนมัติ
  - **ไม่อนุมัติ** ใส่เหตุผลได้ (ไม่บังคับ ไม่เกิน 200 ตัวอักษร) ผู้ขอจะเห็นเหตุผลนี้ในแอป
  - อนุมัติ/ไม่อนุมัติจากแผ่นบันทึกการลา (แตะชื่อในหน้าการลา) ได้เหมือนกัน
  - ถ้าคำขอนั้นถูกพิจารณาไปแล้วจากอีกเครื่อง (เช่น เปิดแอปไว้ 2 เครื่อง) แอปจะแจ้งว่า "ถูกพิจารณาไปแล้ว" และแสดงผลล่าสุด
    — ผลที่ตัดสินไปแล้วจะไม่ถูกเขียนทับโดยไม่รู้ตัว
- **โปรไฟล์ของฉัน** — แตะชื่อของคุณด้านบนของ **เมนู**
  - **รูปโปรไฟล์**: ถ่ายรูปหรือเลือกจากคลังภาพ แล้ว**จัดกรอบเอง**: ลากเพื่อเลื่อนรูป ซูมด้วยแถบเลื่อน (หรือสองนิ้วบนมือถือ) กด **จัดกึ่งกลาง** เพื่อเริ่มใหม่ → **ใช้รูปนี้** → ดูตัวอย่างก่อนกด **บันทึกรูป** (แอปย่อรูปให้เอง) · ทุกคนในทีมจะเห็นรูปนี้ข้างชื่อของคุณ
    (หัวแอป, หน้าวันนี้, การลา, รายชื่อ) · กด **ลบรูป** เพื่อกลับไปใช้ตัวอักษรย่อ · Supervisor ลบรูปที่ไม่เหมาะสมของคนอื่นได้ (แต่ตั้งรูปให้คนอื่นไม่ได้)
  - **รหัสผ่านของฉัน**: กด **แสดงรหัสผ่าน** เพื่อดูรหัสผ่านปัจจุบัน (แสดง 30 วินาทีแล้วซ่อนเอง และซ่อนทันทีเมื่อออกจากหน้านี้หรือสลับไปแอปอื่น)
    ถ้าระบบยังไม่มีรหัสของคุณเก็บไว้ จะขอให้ใส่รหัสปัจจุบันยืนยันหนึ่งครั้ง · **เปลี่ยนรหัสผ่าน** ได้ทั้งจากหน้านี้และจาก เมนู (เหมือนกันทุกอย่าง)
  - อ่านเรื่องความเป็นส่วนตัวของรหัสผ่านที่ [ความปลอดภัย](#ความปลอดภัย)
- ถ้า `Code.gs` ยังไม่ได้อัปเดต แอป v3.0 ทำงานแบบ v2.9 ทุกอย่าง (ซ่อนของใหม่ทั้งหมด) และ Supervisor จะเห็นข้อความใน เมนู ว่าต้องอัปเดต `Code.gs`

### มีอะไรใหม่ใน v2.9 (โฉมใหม่)

v2.9 เปลี่ยนหน้าตาทั้งแอป ข้อมูล รหัสผ่าน และวิธีบันทึกเหมือนเดิมทั้งหมด (แก้เฉพาะไฟล์หน้าเว็บ ใช้กับ `Code.gs` 2.1.0 เดิมได้)

- **หน้าตาใหม่และไอคอนใหม่** — โทนสีพาสเทลตามภาพ X-RAY IPD ตัวอักษรอ่านง่ายขึ้น ปุ่มใหญ่กดง่าย และใช้บนคอมพิวเตอร์ได้สะดวกขึ้น
  (เมนูอยู่ด้านซ้าย หน้าวันนี้แบ่งเป็น 2 คอลัมน์)
- **หน้าวันนี้** (เดิมคือแท็บ Station) — แถบเลือกวันทั้งสัปดาห์ใต้หัวแอป (แตะวันที่ด้านบนเพื่อเลือกวันอื่น), การ์ด **ของฉันวันนี้**
  บอกทันทีว่าคุณอยู่ Station ไหน ทำงานกับใคร หรือลาอะไร, ตามด้วยการ์ด Station แต่ละจุด ("ต้องการ N คน" และ "(ขาด N)" เหมือนเดิม), ผู้ลา และหมายเหตุ
- **หน้าการลา** — ปฏิทินอยู่บนสุด → **สถานะของฉัน** → รายชื่อทุกคน → **สรุปประวัติการลา** (พับไว้ แตะเพื่อเปิด)
  - แตะชื่อ แล้วเลือกสถานะจากแผ่นตัวเลือกที่เลื่อนขึ้นมา (ปกติ หรือประเภทการลาเดิม 6 ประเภท) จากนั้นกด **บันทึก**
  - แถวของคนอื่นที่คุณแก้ไม่ได้มีรูปกุญแจ — แตะแล้วจะเห็นสถานะและเหตุผลว่าทำไมแก้ไม่ได้
- **ย้ายไปอยู่ใน เมนู**: **เปลี่ยนรหัสผ่าน** (เดิมเป็นปุ่มในแถวของตนเองในหน้าการลา), ตรวจสอบการเชื่อมต่อ, มีอะไรใหม่, เวอร์ชัน, ออกจากระบบ
  — สำหรับ Supervisor: **รายชื่อบุคลากร** (เดิมแท็บ "รายชื่อ") และ **รายงานและส่งออก** (เดิมแท็บ "สรุป/ส่งออก")
- **Supervisor บนหน้าวันนี้** — ปุ่ม **บันทึก** อยู่ติดด้านล่างของจอเสมอ (มีป้าย "ยังไม่ได้บันทึก" เมื่อแก้ไขค้างไว้),
  เครื่องมือของวัน (คัดลอก / วาง / แชร์ภาพ JPG / ล้างข้อมูล) อยู่ใต้ปุ่ม **⋯** ข้างปุ่มบันทึก,
  ปุ่ม **จำนวนคน** (ตั้งค่าจำนวนคนแต่ละ Station) อยู่ที่หัวรายการ Station และประวัติการแก้ไขพับไว้ท้ายหน้า (บอกจำนวนรายการ)
- คำถามยืนยัน (เช่น ออกจากระบบ, ล้างข้อมูล) แสดงในแอปแทนหน้าต่างของเบราว์เซอร์ · ปุ่มย้อนกลับของ Android ปิดหน้าต่างที่เปิดอยู่ก่อน
- **ไอคอนบนหน้าจอโฮม**
  - **iPhone / iPad:** ไอคอนเดิมจะไม่เปลี่ยนเอง — ลบไอคอนเดิมออก แล้วเปิดลิงก์แอปใน **Safari** → ปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม** ใหม่
    (อาจต้องเข้าสู่ระบบใหม่หนึ่งครั้ง ข้อมูลทั้งหมดอยู่บนเซิร์ฟเวอร์ ไม่หาย)
  - **Android:** ไอคอนมักเปลี่ยนเองภายในไม่กี่วัน ถ้ายังไม่เปลี่ยนให้ถอนการติดตั้งแล้วติดตั้งจาก Chrome ใหม่

### มีอะไรใหม่ใน v2.2

**🗓️ ปฏิทินการลา** — การ์ดแรกของแท็บ **📝 การลา** แสดงทั้งเดือนในหน้าเดียวว่าแต่ละวันมีคนลากี่คน (ทุกคนเห็น ทั้ง Supervisor และ Staff)

- ช่องวันที่มี **"N คน"** และสีแดงเข้มขึ้นตามจำนวนผู้ลา (1 / 2 / 3 / 4 คนขึ้นไป) — วันที่ไม่มีผู้ลาเป็นช่องสีขาว,
  วันอาทิตย์ตัวเลขสีแดง, วันนี้มีวงกลมสีน้ำเงิน, วันที่เลือกอยู่มีกรอบสีน้ำเงิน
- **แตะวันที่** = เลือกวันนั้น (ทั้งแอป) และแสดงรายชื่อผู้ลาของวันนั้นใต้ปฏิทิน พร้อม "(คนที่ N)" ของพักร้อน/Off เวร
  — รายการบันทึกการลาด้านล่างก็เปลี่ยนเป็นวันนั้นด้วย จึงแก้สถานะต่อได้ทันที
- **‹ ›** เลื่อนดูเดือนก่อน/ถัดไป (ไม่เปลี่ยนวันที่ที่เลือก) · **วันนี้** กลับมาเดือนปัจจุบันและเลือกวันนี้
- บรรทัด **"รวมทั้งเดือน"** บอกจำนวนการลาทั้งเดือนแยกตามประเภท
- ปุ่มกรอง **ทั้งหมด / คนประจำ / ทีมแทนเวร** ของแท็บการลา กรองตัวเลขในปฏิทินด้วย
- เดือนที่เครื่องยังไม่มีข้อมูลจะโหลดจากเซิร์ฟเวอร์ให้เอง ถ้าโหลดไม่ได้ ช่องวันที่จะเป็นเส้นประ (ยังไม่มีข้อมูล ไม่ใช่ "ไม่มีคนลา")
  และมีปุ่ม **โหลดอีกครั้ง**

### บั๊กของเวอร์ชันเดิมที่แก้แล้ว

1. **เปิดแอปใหม่แล้วแก้วันลาไม่ได้** — เดิมถ้าจำการล็อกอินไว้ ปุ่มวันลาทุกแถวจะถูกล็อก ต้องออกแล้วเข้าใหม่ → ตอนนี้คำนวณสิทธิ์ใหม่ทุกครั้งที่แสดงผล
2. **วันที่เพี้ยนช่วงหลังเที่ยงคืน** — เดิมใช้วันที่แบบ UTC ทำให้ช่วง 00:00–06:59 น. "วันนี้" กลายเป็นเมื่อวาน, ช่วงเดือนเริ่มต้นกลายเป็น 31 ส.ค.–29 ก.ย. และเวลาบันทึกลาผิดจนลำดับคิวเพี้ยน → ตอนนี้ใช้วันที่ตามเวลาไทยทั้งหมด (และแก้วันที่ของรายการเดิมให้ตอนนำเข้า)
3. **บันทึก Station แล้ววันลาของคนอื่นหาย** — เดิมบันทึกโดยอ่านจากปุ่มบนหน้าจอ หลังโอนสิทธิ์ Supervisor แล้วกดบันทึกครั้งเดียววันลาของทุกคนถูกล้าง → ตอนนี้ข้อมูลอยู่ในหน่วยความจำของแอปและบนเซิร์ฟเวอร์ ไม่อ่านจากหน้าจออีก
4. **ไม่ได้รับเวอร์ชันใหม่ / ออฟไลน์แล้วหน้าตาเพี้ยน** — service worker เดิมใช้แคชตลอดไปและไม่แคชฟอนต์/สไตล์ → เขียนใหม่ (ดูหัวข้อ 4)
5. **ชื่อที่มีอักขระพิเศษทำให้หน้าจอพัง / CSV เพี้ยน / ตัวกรองกลุ่มหลุด** — ตอนนี้ escape ข้อความทุกจุด, ใส่เครื่องหมายคำพูดครอบทุกช่องใน CSV (และกันไม่ให้ Excel ตีความข้อความเป็นสูตร) และตัวกรองกลุ่มจำค่าถูกต้อง
6. **ข้อมูลอยู่เครื่องเดียว, รหัสผ่านไม่เข้ารหัส, ใครก็เป็น Supervisor ได้** — แก้ด้วย backend Google Sheets + การตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์

### ฟีเจอร์ที่เอาออก

| ฟีเจอร์ | เหตุผล |
|---|---|
| ปุ่ม **"↩️ คืนค่ารายชื่อเริ่มต้น"** (แท็บรายชื่อ) | เมื่อข้อมูลเป็นของกลาง ปุ่มนี้จะรีเซ็ตรายชื่อและรหัสผ่าน **ของทุกคน** กลับเป็น 1234 ในกดเดียว อันตรายเกินไป ถ้าจำเป็นให้เพิ่ม/ลบรายชื่อทีละคน หรือแก้ในชีตโดยผู้ดูแล |

## 2. สถาปัตยกรรม

```
[ มือถือ / คอมพิวเตอร์ของเจ้าหน้าที่ ]   แอป PWA "เวร IPD"
    index.html + config.js + css/tailwind.css + js/*.js + sw.js   (ไฟล์หน้าเว็บ โฮสต์บน GitHub Pages)
    เปิดจากสำเนาในเครื่องทันที และเก็บข้อมูลล่าสุดไว้ดูตอนออฟไลน์ (service worker + localStorage)
          │
          │  ① HTTPS POST ไปที่ script.google.com/…/exec
          │     {"action": "...", "token": "...", "requestId": "...", "clientVersion": "3.0.0", ...}
          │     Content-Type: text/plain  (เลี่ยง CORS preflight ที่ Apps Script ตอบไม่ได้)
          │  ② Google ส่งต่อ (redirect) ให้ไปรับคำตอบที่ script.googleusercontent.com
          ▼
[ Google Apps Script Web App ]   URL ลงท้ายด้วย /exec
    Code.gs → doPost / doGet  (+ onEdit ทำงานเองเมื่อมีคนแก้ชีตด้วยมือ)
    ตรวจ token + สิทธิ์ทุกคำสั่ง · LockService กันเขียนชนกัน · Execute as: Me
    Script Cache: เลขเวอร์ชันข้อมูล, ข้อมูลสิทธิ์ (ไม่มีรหัสผ่าน), คำตอบของคำสั่งเขียน 10 นาที (กันบันทึกซ้ำ)
          │
          │  SpreadsheetApp (ทำงานด้วยสิทธิ์ของเจ้าของชีต เข้าถึงได้เฉพาะชีตที่ผูกอยู่)
          ▼
[ Google Sheet ส่วนตัวของหน่วยงาน (ไม่แชร์) ]
    Staff │ Config │ Days │ Leaves │ Audit │ Avatars
```

- **หน้าเว็บ** เป็นไฟล์ static ธรรมดา วางไว้ที่ไหนก็ได้ที่เป็น HTTPS (แนะนำ GitHub Pages ฟรี)
- **Apps Script** ผูกอยู่กับ Google Sheet (container-bound) รันด้วยสิทธิ์ของเจ้าของชีต ผู้ใช้ทั่วไป **ไม่ต้องมีบัญชี Google**
  สคริปต์ขอสิทธิ์เฉพาะ "สเปรดชีตที่ผูกอยู่" (`spreadsheets.currentonly`) ไม่ใช่ทุกไฟล์ของบัญชีเจ้าของ
- **Google Sheet** เป็นฐานข้อมูล มี 6 ชีต: `Staff` รายชื่อ/รหัสผ่าน (hash + salt คือรหัสจริง และคอลัมน์ `password` เป็นสำเนาแบบอ่านได้), `Config` ใครเป็น Supervisor และจำนวนคนที่แต่ละ Station ต้องการ, `Days` การจัด Station + หมายเหตุรายวัน, `Leaves` วันลา (พร้อมสถานะการอนุมัติ), `Audit` ประวัติการแก้ไข, `Avatars` รูปโปรไฟล์
- **เครือข่าย:** มือถือต้องเข้าถึงได้ 3 โดเมน — โฮสต์ของหน้าเว็บ (เช่น `<ชื่อผู้ใช้>.github.io`), `script.google.com` และ `script.googleusercontent.com`
  (ที่เหลือไม่จำเป็น — ดู [ใช้งานผ่าน Wi-Fi ของโรงพยาบาล](#ใช้งานผ่าน-wi-fi-ของโรงพยาบาล))

- ไฟล์ของโปรเจกต์นี้ทั้งโฟลเดอร์ (เก็บไว้ในเครื่อง — ขึ้น GitHub เฉพาะไฟล์ในรายการของขั้นที่ 7)

> ถ้าเมนูของ Google แสดงเป็นภาษาไทย ให้ดูจากตำแหน่ง/ไอคอนเดียวกัน เช่น *Extensions* = *ส่วนขยาย*, *Deploy* = *การทำให้ใช้งานได้*

### ขั้นที่ 1 — สร้าง Google Sheet

1. เข้า <https://sheets.google.com> ด้วยบัญชีเจ้าของ → สร้างสเปรดชีตเปล่า (**Blank spreadsheet**)
2. ตั้งชื่อไฟล์ เช่น `เวร IPD — ฐานข้อมูล`
3. ตั้งเขตเวลา: **File > Settings > General > Time zone** เลือก **(GMT+07:00) Bangkok** → **Save settings**
4. ไม่ต้องสร้างชีตหรือหัวคอลัมน์เอง — ขั้นที่ 4 จะสร้างให้อัตโนมัติ

### ขั้นที่ 2 — เปิด Apps Script แล้ววาง `Code.gs`

1. ในสเปรดชีต ไปที่เมนู **Extensions > Apps Script** (จะเปิดแท็บใหม่)
   - ต้องเปิดจากเมนูในชีตเท่านั้น ห้ามสร้างโปรเจกต์ใหม่จาก script.google.com เพราะโค้ดใช้ชีตที่ผูกอยู่ (`getActiveSpreadsheet`)
2. คลิกชื่อ *Untitled project* ด้านบน เปลี่ยนเป็น `เวร IPD Backend`
3. ในไฟล์ `Code.gs` ที่เปิดอยู่ ลบโค้ดเดิม (`function myFunction() {...}`) ออกให้หมด
4. เปิดไฟล์ `apps-script/Code.gs` จากโปรเจกต์นี้ด้วย Notepad → **Ctrl+A**, **Ctrl+C** → กลับไปวางในหน้า Apps Script (**Ctrl+V**)
   - บรรทัดแรกของโค้ดต้องเป็น `/** @OnlyCurrentDoc */` (จำกัดสิทธิ์ให้เข้าถึงเฉพาะชีตนี้) — อย่าลบทิ้ง
5. กด **Ctrl+S** (หรือไอคอน 💾 **Save project**)

### ขั้นที่ 3 — วาง `appsscript.json`

1. แถบซ้ายสุด คลิกไอคอนฟันเฟือง ⚙️ **Project Settings**
2. ติ๊ก **Show "appsscript.json" manifest file in editor**
3. กลับไปที่ไอคอน `< >` **Editor** → จะเห็นไฟล์ `appsscript.json` เพิ่มขึ้นมา คลิกเปิด
4. ลบเนื้อหาเดิม แล้ววางเนื้อหาจากไฟล์ `apps-script/appsscript.json` ของโปรเจกต์ → **Ctrl+S**
   (ไฟล์นี้กำหนด `timeZone` = `Asia/Bangkok`, runtime `V8`, ค่าเริ่มต้นของ Web App = Execute as: Me / Who has access: Anyone
   และสิทธิ์ที่ขอ `oauthScopes` = `spreadsheets.currentonly` คือเฉพาะสเปรดชีตที่ผูกอยู่)

### ขั้นที่ 4 — รัน `setup` ครั้งแรก (อนุญาตสิทธิ์)

1. กลับไปที่ไฟล์ `Code.gs` บนแถบเครื่องมือด้านบนจะมีช่องเลือกฟังก์ชัน → เลือก **`setup`**
   (ในรายการจะเห็นเฉพาะฟังก์ชันสาธารณะ: `doGet`, `doPost`, `onEdit`, `setup`, `adminResetSupervisorPassword`, `resetAllSessions`, `prepareRollback`,
   `selfTest`, `selfTestCleanup`, `allowSelfTestHere` — **ห้ามรัน** `doGet`/`doPost` เอง · `selfTest` ใช้เฉพาะตอนอัปเดตและเฉพาะในสำเนาของชีต (หัวข้อ 4) ·
   `prepareRollback` ใช้เฉพาะตอนย้อนเวอร์ชัน (หัวข้อ 4) · `onEdit` ไม่ต้องรัน Google เรียกให้เองทุกครั้งที่มีคนแก้ชีตด้วยมือ เพื่อให้แอปเห็นการแก้นั้นในการดึงข้อมูลครั้งถัดไป
   และเพื่อคืนค่าคอลัมน์ `password` ถ้ามีคนพิมพ์ทับ — คอลัมน์นั้นใช้แสดงรหัสเท่านั้น หัวข้อ 6)
2. กด **▷ Run**
3. จะขึ้นหน้าต่าง **Authorization required** → กด **Review permissions** → เลือกบัญชีเจ้าของ
4. จะเจอหน้าเตือน **"Google hasn't verified this app"** — เป็นเรื่องปกติ เพราะเป็นสคริปต์ที่เราเขียนใช้เอง ไม่ได้ส่งให้ Google ตรวจ
   - กด **Advanced** (ตัวเล็กด้านล่างซ้าย) → กด **Go to เวร IPD Backend (unsafe)**
5. หน้าถัดไปแสดงสิทธิ์ที่ขอ ซึ่งควรเป็น
   **"View and manage spreadsheets that this application has been installed in"** (ดูและจัดการสเปรดชีตที่ติดตั้งแอปนี้ไว้ = เฉพาะชีตนี้)
   → ถ้ามีช่องให้ติ๊ก ให้ติ๊ก → กด **Allow** / **Continue**
   - ถ้าหน้านี้ขอ **"See, edit, create, and delete all your Google Sheets spreadsheets"** (ทุกไฟล์ในบัญชี) แปลว่าโค้ดที่วางไม่ครบ/เป็นรุ่นเก่า
     ให้กดยกเลิก แล้วตรวจขั้นที่ 2 (บรรทัดแรก `/** @OnlyCurrentDoc */`) และขั้นที่ 3 ก่อนรันใหม่
6. รอจน *Execution log* แสดง **Execution completed** และข้อความ `พร้อมใช้งาน: พนักงาน … คน, Supervisor = "…"`
7. กลับไปที่แท็บ Google Sheet จะเห็นชีตใหม่ 6 ชีต: `Staff`, `Config`, `Days`, `Leaves`, `Audit`, `Avatars`
   - ชีต `Staff` มีรายชื่อเริ่มต้น 21 คน (คนประจำ 15 + ทีมแทนเวร 6) ทุกคนรหัส `1234`
   - ชีต `Config` มี `supervisor` = ชื่อ Supervisor เริ่มต้น (`DEFAULT_SUPERVISOR` ใน `Code.gs`), `schema_version` = `4` และ 7 แถว `station_count:portable` … `station_count:supervisor`
     (จำนวนคนที่แต่ละ Station ต้องการ ค่าเริ่มต้น 3, 3, 2, 2, 3, 1, 1 — ให้ Supervisor แก้ผ่านปุ่ม **⚙️ ตั้งค่าจำนวนคน** ในแอป)
   - ชีตว่างเดิม (*Sheet1* / *ชีต1*) จะปล่อยไว้หรือลบทิ้งก็ได้

> `setup` รันซ้ำได้อย่างปลอดภัย จะไม่ลบหรือเขียนทับข้อมูลที่มีอยู่แล้ว — ถ้ามีคนลบชีตหรือค่าใน `Config` ไป รัน `setup` อีกครั้งเพื่อสร้างส่วนที่ขาดคืน

### ขั้นที่ 5 — Deploy เป็น Web App

1. มุมขวาบนของ Apps Script กด **Deploy > New deployment**
2. ข้าง *Select type* กดไอคอนฟันเฟือง ⚙️ → เลือก **Web app**
3. กรอก:

   | ช่อง | ค่าที่ต้องเลือก |
   |---|---|
   | Description | `v3.0.0` (อะไรก็ได้) |
   | Execute as | **Me** (อีเมลเจ้าของ) |
   | Who has access | **Anyone** — *ไม่ใช่* "Anyone with Google account" และ *ไม่ใช่* "Only myself" |

4. กด **Deploy** (ถ้าถามสิทธิ์อีกครั้ง ให้ทำแบบขั้นที่ 4)
5. คัดลอก **Web app URL** — รูปแบบ `https://script.google.com/macros/s/AKfy..../exec` (ต้องลงท้ายด้วย **`/exec`**) → กด **Done**
6. ทดสอบ: เปิด **หน้าต่างไม่ระบุตัวตน** (Chrome: Ctrl+Shift+N · Edge: Ctrl+Shift+N = InPrivate) หรือใช้มือถือที่ไม่ได้ล็อกอิน Google
   แล้ววาง URL ต้องเห็นข้อความ JSON ประมาณนี้

   ```json
   {"ok":true,"data":{"version":"3.0.0","timeZone":"Asia/Bangkok","now":"...","schema":4,"features":[...]},"serverTime":"...","action":"ping"}
   ```

   (`"version"` บอกเวอร์ชันของ `Code.gs` ที่ deploy อยู่ — เวอร์ชันนี้คือ `3.0.0`)

   - ถ้าเห็นหน้าล็อกอิน Google หรือข้อความว่าไม่มีสิทธิ์ แปลว่า *Who has access* ไม่ใช่ **Anyone** (แก้ตามหัวข้อ 7 "ตรวจการตั้งค่า Web App")
   - ⚠️ **อย่าทดสอบในเบราว์เซอร์ที่ล็อกอินบัญชีเจ้าของอยู่** — เจ้าของจะเห็น JSON เสมอแม้ตั้งค่าเป็น "Only myself" หรือ "Anyone with Google account"
     ซึ่งมือถือของทุกคนจะเชื่อมต่อไม่ได้

### ขั้นที่ 6 — ใส่ URL ให้แอป (เลือกวิธีใดวิธีหนึ่ง)

**วิธี ก (แนะนำ) — แก้ `config.js`** ก่อนอัปโหลด:

```js
window.APP_CONFIG = { API_URL: "https://script.google.com/macros/s/AKfy..../exec" };
```

**วิธี ข — ปล่อย `config.js` ว่างไว้** (`API_URL: ""`) แล้วตอนเปิดแอปครั้งแรกในแต่ละเครื่อง แอปจะแสดงหน้าตั้งค่า
ให้วาง URL แล้วกด **"ทดสอบและบันทึก"** (URL จะถูกจำไว้ในเครื่องนั้น และในหน้าล็อกอินจะมีลิงก์ **"⚙️ ตั้งค่าการเชื่อมต่อ"** ไว้แก้ภายหลัง)
เหมาะถ้าไม่อยากให้ URL ปรากฏในไฟล์สาธารณะ แต่ทุกเครื่องต้องวาง URL เอง
- URL ต้องขึ้นต้นด้วย `https://` ถ้าไม่ใช่รูปแบบ `https://script.google.com/macros/s/.../exec` แอปจะเตือนแต่ยังลองเชื่อมต่อให้
- ถ้าขึ้น **"เชื่อมต่อไม่ได้ — ตรวจสอบอินเทอร์เน็ต หรือ URL / การตั้งค่า Who has access ต้องเป็น Anyone"** ให้ตรวจตามหัวข้อ 7 "ตรวจการตั้งค่า Web App"
  (ในหน้าตั้งค่ามีลิงก์ **🩺 ตรวจสอบการเชื่อมต่อ** ไว้ตรวจว่าเครื่อง/เครือข่ายใช้อินเทอร์เน็ตได้หรือไม่)

### ขั้นที่ 8 — เข้าสู่ระบบครั้งแรก

1. เปิดแอป → เลือกชื่อที่มี **⭐ (Supervisor)** (Supervisor เริ่มต้นตาม `DEFAULT_SUPERVISOR` ใน `Code.gs`) → รหัส **`1234`** → **เข้าสู่ระบบ**
   (ถ้ารายชื่อไม่ขึ้น กด **"🔄 โหลดรายชื่อใหม่"** เหนือช่องเลือกชื่อ)
2. แอปจะบังคับเปิดหน้าต่างเปลี่ยนรหัส (ปิดไม่ได้ มีแค่ปุ่ม "ออกจากระบบ"): ใส่รหัสเดิม `1234` → รหัสใหม่ (4–64 ตัวอักษร ห้ามเป็น `1234`) → ยืนยัน → บันทึก
   - จนกว่าจะเปลี่ยนรหัสสำเร็จ เซิร์ฟเวอร์จะไม่ยอมทำคำสั่งอื่น (อ่านข้อมูลก็ไม่ได้) — แอปจะโหลดข้อมูลต่อให้เองหลังเปลี่ยนรหัส
3. แจ้งทุกคน: **ทุกคนเริ่มที่รหัส `1234`** ให้เข้าด้วยชื่อตัวเอง แล้วตั้งรหัสใหม่ทันที
4. ถ้ารายชื่อไม่ตรงกับหน่วยงาน ให้แก้ในแท็บ **👥 รายชื่อ** (หรือนำเข้าข้อมูลเดิมตามขั้นที่ 9 ซึ่งจะเพิ่มรายชื่อที่ขาดให้เอง)

### ขั้นที่ 9 — ย้ายข้อมูลเดิมจากเครื่อง (ถ้ามี)

ข้อมูลของเวอร์ชันเดิมอยู่ใน **localStorage ของเบราว์เซอร์** ซึ่ง **ผูกกับโดเมน (origin)** ที่เปิดแอป
เช่น ข้อมูลที่บันทึกจาก `https://abc.github.io/...` จะอ่านได้เฉพาะหน้าเว็บที่อยู่บน `https://abc.github.io` เท่านั้น
(origin = `https://` + ชื่อโดเมน + พอร์ต — ส่วน path หลังโดเมนไม่มีผล)
ดังนั้น **ต้องเปิดแอปเวอร์ชันใหม่บนโดเมนเดียวกับเวอร์ชันเก่า และบนเครื่อง/เบราว์เซอร์เดียวกับที่มีข้อมูล** ปุ่มนำเข้าจึงจะเห็นข้อมูล

> เมื่อเปิดเวอร์ชัน 2 ครั้งแรก แอปจะลบ **รหัสผ่านเดิมที่เก็บเป็นข้อความธรรมดา** (`rad_passwords`, `rad_current_user`) ออกจากเครื่องทันที
> ส่วนตารางเวร/วันลา/รายชื่อเดิม (`rad_schedules`, `rad_staff`) ยังอยู่จนกว่าจะกดลบเองในข้อ 7 ด้านล่าง

1. วางไฟล์เวอร์ชันใหม่ให้เปิดได้บนโดเมนเดียวกับเวอร์ชันเก่า
   - **วิธีที่ใช้ได้ทุกกรณี (แนะนำ):** อัปโหลดไฟล์ใหม่ **ทับใน repository เดิม** (URL เดิมทุกตัวอักษร) แล้วเปิดจาก URL/ไอคอนเดิม
   - ใช้ **repository ใหม่** ภายใต้บัญชี GitHub เดิม (`<ชื่อผู้ใช้>.github.io` เดียวกัน) ได้เฉพาะเครื่อง **Android (Chrome) / คอมพิวเตอร์**:
     ต้องเปิด **URL ใหม่** ในเบราว์เซอร์ตัวเดียวกับที่เคยใช้เวอร์ชันเดิม (URL/ไอคอนเดิมยังเป็นแอปเก่าที่ไม่มีปุ่มนำเข้า)
   - ⚠️ **iPhone ที่ใช้แอปจากไอคอนบนหน้าจอโฮม ต้องใช้วิธีอัปโหลดทับเท่านั้น** — iOS แยกพื้นที่เก็บข้อมูลของไอคอนหน้าจอโฮมออกจาก Safari
     ข้อมูลเดิมจึงเปิดได้จากไอคอนเดิมเท่านั้น (Safari หรือไอคอนใหม่ของ URL ใหม่มองไม่เห็น)
2. บนเครื่องที่มีข้อมูลเดิม (ปกติคือเครื่องของ Supervisor) เปิดแอปจาก URL/ไอคอนเดิม (หรือ URL ใหม่ตามเงื่อนไขในข้อ 1)
   - ถ้ายังเห็นหน้าตาเวอร์ชันเก่า ให้ปิดแอปทั้งหมดแล้วเปิดใหม่ 1–2 ครั้ง (ดูหัวข้อ 7 "เห็นเวอร์ชันเก่า")
   - **ห้าม** กด "ล้างข้อมูลเว็บไซต์ / Clear site data" ก่อนนำเข้าเสร็จ ข้อมูลเดิมจะหายถาวร
3. ล็อกอินเป็น Supervisor
4. ไปแท็บ **👥 รายชื่อ** → จะมีการ์ด **"📦 นำเข้าข้อมูลจากเวอร์ชันเดิม (เครื่องนี้)"** บอกจำนวนวันและรายชื่อที่พบในเครื่อง (การ์ดนี้แสดงเฉพาะเมื่อเครื่องมีข้อมูลเวอร์ชันเดิม)
5. เลือกว่าจะติ๊ก **"เขียนทับข้อมูลที่มีอยู่แล้ว"** หรือไม่
   - ไม่ติ๊ก (ค่าเริ่มต้น): วัน/วันลาที่มีบนเซิร์ฟเวอร์แล้วจะถูกข้าม — ปลอดภัยที่สุด (วันที่บนเซิร์ฟเวอร์ว่างอยู่ เช่น เคยกดล้างข้อมูลทั้งวัน ถือว่ายังไม่มีข้อมูล จะถูกเติมให้)
   - ติ๊ก: ข้อมูลจากเครื่องนี้จะทับของบนเซิร์ฟเวอร์ในวันเดียวกัน (วันลาประเภทเดียวกันที่มีอยู่แล้วไม่ถูกแตะ คิวเดิมคงอยู่
     และวันที่ในเครื่องไม่มีการจัด Station/หมายเหตุ จะไม่ลบ Station ของวันนั้นบนเซิร์ฟเวอร์)
6. กดปุ่ม **"⬆️ นำเข้าข้อมูลขึ้นระบบกลาง"** (ข้อมูลเยอะอาจใช้เวลาเป็นนาที) → แอปแสดงสรุป: รายชื่อที่เพิ่ม, จำนวนวัน, จำนวนวันลา,
   จำนวนคนที่ถูกนำออกจาก Station ที่มีอยู่แล้ว และรายการที่ข้าม (พร้อมเหตุผล)
7. ตรวจข้อมูลโดย **สลับแท็บในแอปนี้** (หรือเปิดจากอีกเครื่อง/เปิดชีตดู) แล้ว (ถ้าต้องการ) กด **"🧹 ลบข้อมูลเดิมในเครื่องนี้"** เพื่อลบข้อมูลเก่าในเครื่อง
   - ปุ่มนี้ **แสดงเฉพาะหลังกดนำเข้าในรอบนั้น** และหายไปเมื่อปิด/โหลดแอปใหม่หรือออกจากระบบ — ถ้าปุ่มหายไป ให้กดนำเข้าอีกครั้งแบบ **ไม่ติ๊ก** เขียนทับ
     แล้วจึงกดลบ (ข้อมูลที่นำเข้าแล้วจะไม่ซ้ำ แต่วันลา/วันที่ที่ถูกลบหรือล้างบนเซิร์ฟเวอร์หลังการนำเข้าครั้งแรกจะถูกนำเข้ากลับมา — ตรวจอีกครั้งหลังกด)

สิ่งที่ควรรู้เกี่ยวกับการนำเข้า:

- รายชื่อในเครื่องที่ยังไม่มีบนเซิร์ฟเวอร์จะถูกเพิ่ม (รหัส `1234`, บังคับเปลี่ยนรหัส) ชื่อที่ผิดกฎ (เช่น มีเครื่องหมายจุลภาค หรือเป็นคำสงวน) จะถูกข้ามและแสดงในสรุป
- วันลานำเข้าเฉพาะของคนที่ยังใช้งานอยู่ และเฉพาะประเภทที่รู้จัก ผู้บันทึก/เวลาบันทึกเดิมถูกเก็บไว้ (ใช้เรียงคิว)
  รายการที่เวอร์ชันเดิมบันทึกช่วง 00:00–06:59 น. มีวันที่เพี้ยนไป 1 วัน (บั๊กข้อ 2) — ตอนนำเข้าแอปแก้วันที่ให้อัตโนมัติ ลำดับคิวจึงถูกต้อง
- **คนที่มีวันลาในวันใด จะไม่อยู่ใน Station ของวันนั้น** ทั้งในวันที่นำเข้าจากเครื่องนี้ และในวันที่มีข้อมูลบนเซิร์ฟเวอร์อยู่แล้ว
  (คนที่วันลาเพิ่งถูกนำเข้าจะถูกนำออกจาก Station เดิม พร้อมบันทึก `AUTO_UNASSIGN` ในชีต `Audit` เหมือนตอนกดลาในแอป)
- ถ้าเวอร์ชันเดิมถูกใช้บนหลายเครื่อง: นำเข้าจากเครื่องหลักก่อน แล้วค่อยนำเข้าจากเครื่องอื่นแบบ **ไม่ติ๊ก** เขียนทับ เพื่อเติมเฉพาะส่วนที่ขาด (ต้องล็อกอินเป็น Supervisor บนเครื่องนั้น แล้วออกจากระบบเมื่อเสร็จ)
- ถ้าเปิดเวอร์ชันใหม่บนโดเมนเดิมไม่ได้ (เช่น เดิมเปิดจากไฟล์ในเครื่อง) ปุ่มนำเข้าจะมองไม่เห็นข้อมูล ต้องกรอกข้อมูลใหม่ หรือให้นักพัฒนาดึงข้อมูลจาก localStorage ให้

## 4. การอัปเดตเวอร์ชัน

### อัปเดตจาก v3.1 เป็น v3.2

รอบนี้เปลี่ยนทั้ง **`Code.gs`** (เซิร์ฟเวอร์ 3.2.0 — เพิ่มชีตใหม่ 4 ชีต ไม่แก้ชีตเดิม) และ **ไฟล์หน้าเว็บ** — ขั้นตอนเหมือน [อัปเดตจาก v3.0 เป็น v3.1](#อัปเดตจาก-v30-เป็น-v31) ทุกข้อ
(เซิร์ฟเวอร์ที่ยังเป็น 3.0 อัปเดตเป็น 3.2 ได้ทันทีด้วยขั้นตอนเดียวกันนี้ ระบบสร้างชีตของ v3.1 และ v3.2 ให้ครบในครั้งเดียว)
**ทดสอบกับสำเนาของชีตก่อนทุกครั้ง** ห้ามวางโค้ดใหม่ลงชีตจริงก่อนที่การทดสอบในสำเนาจะผ่าน

1. **ทำสำเนาของ Google Sheet** (ไฟล์ → ทำสำเนา ชื่อมีคำว่า "สำเนา") — จากนี้ไปจนจบข้อ 3 ทำในสำเนาเท่านั้น
2. ในสำเนา: **ส่วนขยาย → Apps Script** → วาง `Code.gs` ฉบับ 3.2.0 ทับทั้งไฟล์ → **บันทึก** (`appsscript.json` ไม่เปลี่ยน)
   — ไฟล์ยาวขึ้นมาก ให้เลื่อนดูบรรทัดสุดท้ายว่าวางครบ (ผู้พัฒนาให้ค่า SHA-256 ของไฟล์ไว้ตรวจได้)
3. ในสำเนา: เลือกฟังก์ชัน **`selfTest`** → **เรียกใช้** → ชีต `SelfTest` ของสำเนาต้องบอก **PASS** ทุกขั้น (34 ขั้น · รายละเอียดการอ่านผลอยู่ในส่วน ข ของหัวข้อ v3.0)
   - ขั้นที่ 28–33 ตรวจของใหม่: ชีตใหม่ 4 ชีต (หัวคอลัมน์ เครื่องหมายใน `Config` และจำนวนคอลัมน์พอดีกับหัวคอลัมน์), `ping`/`getData` บอกว่ามี Dashboard แจ้งปัญหา และแชท,
     แจ้งปัญหาพร้อมรูป (ส่งซ้ำได้รูปเดียว คนอื่นแนบรูปไม่ได้ แก้แล้ว เปิดอีกครั้ง ล้างรูป ลบเรื่อง), แชท (ส่งซ้ำได้ข้อความเดียว คนที่สามไม่เห็น อ่านแล้ว ไม่มีบันทึกใน `Audit` จำกัด 20 ข้อความต่อนาที),
     ยอดพักร้อน/คะแนนใบประกอบ (แก้ของตนเองได้ ของคนอื่นไม่ได้ เห็นเฉพาะของตนเอง Supervisor เห็นทุกคน) และการเก็บกวาด — ข้อมูลทดสอบทั้งหมด (ผู้ทดสอบชั่วคราว เรื่องที่แจ้ง รูป ข้อความแชท) ถูกลบเองเมื่อจบ
   - ขั้นที่ 31 อาจบอกว่า "การจำกัด 20 ข้อความต่อนาทีไม่ได้ตรวจ" ถ้าการส่ง 20 ข้อความใช้เวลาเกิน 1 นาที (ยังเป็น PASS)
   - **FAIL** → **หยุด ห้ามวางโค้ดลงชีตจริง** ส่งภาพหน้าจอชีต `SelfTest` ให้ผู้พัฒนา · เสร็จแล้ว **ลบสำเนาทิ้ง**
4. **หลัง PASS เท่านั้น:** เปิด **ชีตจริง** → **ส่วนขยาย → Apps Script** → วาง `Code.gs` **ไฟล์เดียวกับที่ทดสอบผ่าน** ทับทั้งไฟล์ → **บันทึก**
   - ⚠️ **ห้ามรัน `setup` หรือ `selfTest` ในชีตจริง ก่อนที่ Web App จะตอบเวอร์ชัน 3.2.0** (ข้อ 6) — และหลังจากนั้นก็ไม่ต้องรัน (คำขอแรกหลัง Deploy ปรับชีตให้เอง)
5. **ทำให้ใช้งาน (Deploy) → จัดการการทำให้ใช้งาน (Manage deployments)** → deployment เดิม → ✏️ **Edit** → **เวอร์ชัน: เวอร์ชันใหม่ (New version)** → **ทำให้ใช้งาน (Deploy)**
   — ตรวจว่า **Execute as = ฉัน (Me)** และ **Who has access = ทุกคน (Anyone)** · URL `/exec` เหมือนเดิม (**ห้ามกด New deployment**)
6. **ตรวจเวอร์ชันทันที:** ในแอป **เมนู → ตรวจสอบการเชื่อมต่อ (🩺) → ▶️ เริ่มตรวจสอบ** ต้องบอก **"เวอร์ชัน 3.2.0"**
   (หรือเปิด URL `/exec` ในหน้าต่างไม่ระบุตัวตน ต้องเห็น `"version":"3.2.0"`, `"schema":6` และ `"plan"`, `"stats"`, `"problem"`, `"chat"` ใน `features`) — ยังเห็น 3.1.0: ทำข้อ 5 ใหม่
7. ไฟล์หน้าเว็บ v3.2 ผู้พัฒนาเป็นผู้อัปโหลด (รายการไฟล์อยู่ที่ [ขั้นที่ 7](#ขั้นที่-7--โฮสต์หน้าเว็บบน-github-pages)) — แต่ละเครื่องเปิดแอปขณะต่อเน็ตแล้วแตะ "🔄 มีเวอร์ชันใหม่"
8. **เริ่มใช้ครั้งแรก:** แต่ละคนกรอกยอดพักร้อน "ณ สิ้นวันที่ …" ใน **Dashboard ของฉัน** (หรือ Supervisor กรอกให้ใน **Dashboard ทีม**)

**สิ่งที่เกิดกับชีตจริงหลัง Deploy** (คำขอแรกทำครั้งเดียว · ไม่มีอะไรถูกลบ แถวเดิมไม่ถูกแก้ ไม่มีใครถูกออกจากระบบ):

| ชีต | สิ่งที่เปลี่ยน |
|---|---|
| `Problems` (ใหม่) | เรื่องที่แจ้ง: เลขที่, Station, รายละเอียด, สถานะ (`open` / `resolved` / `deleted`), ผู้แจ้ง, ผู้แก้, หมายเหตุการแก้, รหัสรูป |
| `Files` (ใหม่) | รูปของเรื่องที่แจ้ง เก็บเป็นข้อความยาว (base64) แบ่ง 4 ช่อง `d1`–`d4` — **ห้ามเปิดแก้ช่องในชีตนี้** (ข้อความยาวมาก ชีตอาจค้าง) |
| `Chat` (ใหม่) | ข้อความแชท (ผู้ส่ง ผู้รับ ข้อความ เวลา) — เก็บถาวร |
| `ChatReads` (ใหม่) | "อ่านถึงข้อความไหนแล้ว" ของแต่ละคู่ |
| `Profiles` | เริ่มใช้คอลัมน์ `vac_balance`, `vac_asof`, `ce_points`, `ce_target`, `licence_expiry` (ยอดพักร้อน คะแนนใบประกอบ วันหมดอายุใบประกอบ) |
| `Config` | `schema_version` เป็น 6 · แถวใหม่ `owned_sheet:Problems` … `owned_sheet:ChatReads` (= `6:` ตามด้วยรหัสของชีตนั้น) — **ห้ามลบแถวเหล่านี้** · แถว `owned_sheet:` ของ 6 ชีตระบบจัดเวรยังเป็น `5:…` เหมือนเดิม (ถูกต้อง) |

- ชีตใหม่ทั้ง 4 มีจำนวนคอลัมน์พอดีกับหัวคอลัมน์ (ไฟล์ Google Sheets หนึ่งไฟล์มีได้ไม่เกิน 10 ล้านช่อง จึงไม่เผื่อคอลัมน์ว่าง) และมีการป้องกันแบบเตือนเหมือนชีตเดิม
- **ห้ามเปลี่ยนชื่อ เรียงข้อมูล แก้ หรือวางข้อมูลลงในชีต `Problems`, `Files`, `Chat`, `ChatReads`** — ใช้ผ่านแอปเท่านั้น ·
  ถ้าเห็นชีต "… (เดิม)" เช่น "Chat (เดิม)" คือชีตชื่อเดียวกันที่เจ้าของไฟล์เคยทำไว้เอง ระบบเปลี่ยนชื่อให้โดยไม่แตะข้อมูลข้างใน
- **พื้นที่เก็บรูป:** รวมกันได้ไม่เกิน 30 ล้านตัวอักษร (ประมาณ 200–300 รูป) — Supervisor ดูปริมาณที่ใช้และล้างรูปของเรื่องที่แก้แล้วได้ในแอป (**แจ้งปัญหา → ล้างรูปเก่า**) ·
  ข้อความในเรื่องยังอยู่ · เต็มแล้วแอปจะบอกและไม่รับรูปใหม่ (ข้อความแจ้งปัญหายังบันทึกได้) · ดูขนาดไฟล์ชีตเป็นระยะ (ไฟล์หนึ่งมีได้ไม่เกิน 10 ล้านช่อง;
  แชทใช้ 6 ช่องต่อข้อความ — ต่อให้มีวันละ 1,000 ข้อความก็ประมาณ 2.2 ล้านช่องต่อปี)
- **ความเป็นส่วนตัว:** ข้อความแชทและรูปแจ้งปัญหาอยู่ในชีตนี้ **ใครเปิดชีตได้ก็อ่านได้ — อย่าแชร์ชีตให้คนอื่น** · ห้ามมีใบหน้า ชื่อ หรือ HN ของผู้ป่วยในรูปหรือในแชท ·

### อัปเดตจาก v2.9 เป็น v3.0

รอบนี้เปลี่ยนทั้ง **`Code.gs`** (เซิร์ฟเวอร์ 3.0.0 — เพิ่มคอลัมน์ในชีต) และ **ไฟล์หน้าเว็บ** — ใช้เวลาประมาณ 30 นาที
**ทดสอบกับสำเนาของชีตก่อนทุกครั้ง** ห้ามวางโค้ดใหม่ลงชีตจริงก่อนที่การทดสอบในสำเนาจะผ่าน

**ก. ทำสำเนาของ Google Sheet**

1. เปิด Google Sheet ตัวจริงของหน่วยงาน → เมนู **ไฟล์ → ทำสำเนา** (File → Make a copy)
2. ตั้งชื่อให้รู้ว่าเป็นสำเนา เช่น "ทดสอบ v3.0 — สำเนา" → **ทำสำเนา** (Apps Script ที่ผูกกับชีตจะถูกคัดลอกมาด้วย)
3. จากนี้ไปจนจบส่วน ข **ทำในสำเนาเท่านั้น** (ดูชื่อไฟล์มุมซ้ายบนให้แน่ใจทุกครั้ง)

**ข. ในสำเนา: วาง `Code.gs` ใหม่ แล้วรัน `selfTest`**

1. ในสำเนา: **ส่วนขยาย → Apps Script** (Extensions → Apps Script)
2. คลิกไฟล์ `Code.gs` → เลือกข้อความทั้งหมด (Ctrl+A) → ลบ → วาง `Code.gs` ฉบับ 3.0.0 ที่ได้จากผู้พัฒนาทั้งไฟล์ → กดรูปแผ่นดิสก์ (**บันทึก** / Ctrl+S)
   (`appsscript.json` ไม่เปลี่ยน ไม่ต้องแตะ)
3. ด้านบนของหน้าจอ ข้างปุ่ม **เรียกใช้ (Run)** มีช่องเลือกฟังก์ชัน → เลือก **`selfTest`** → กด **เรียกใช้**
   - `selfTest` ทำงานเฉพาะในไฟล์ที่ **ชื่อมีคำว่า "สำเนา" หรือ "Copy"** (Google ตั้งชื่อสำเนาให้แบบนี้อยู่แล้ว เช่น "สำเนาของ …" หรือ "Copy of …")
     ถ้าขึ้นข้อความสีแดง **"selfTest ไม่ได้ทำงาน: ชื่อไฟล์ … ไม่มีคำว่า "สำเนา" หรือ "Copy" …"** แปลว่าไฟล์นี้อาจเป็นชีตจริง — ไม่มีอะไรถูกแตะ
     ให้ดูชื่อไฟล์ที่มุมซ้ายบนของแท็บชีต: ถ้าเป็น **ชีตจริง** หยุดทันทีแล้วกลับไปทำส่วน ก · ถ้าเป็นสำเนาที่ตั้งชื่อเองโดยไม่มีคำว่า "สำเนา"
     หรือ Google ตั้งชื่อเป็นภาษาอื่น (เช่น "Copia de …", "Kopie von …") ให้คลิกที่ชื่อไฟล์ เติมคำว่า "สำเนา" แล้วรันใหม่
4. **ครั้งแรก Google จะขอสิทธิ์** (เพราะสำเนาเป็นสคริปต์ใหม่): กด **ตรวจสอบสิทธิ์ (Review permissions)** → เลือกบัญชีเจ้าของชีต
   → ถ้าขึ้น "Google ยังไม่ได้ยืนยันแอปนี้" ให้กด **ขั้นสูง (Advanced)** → **ไปที่ … (ไม่ปลอดภัย)** → **อนุญาต (Allow)**
   - สิทธิ์ที่ขอมีข้อเดียวเหมือนเดิม คือ "ดู แก้ไข สร้าง และลบ **เฉพาะ** สเปรดชีตที่ติดตั้งแอปพลิเคชันนี้ไว้"
     (ภาษาอังกฤษ: *See, edit, create and delete only the specific Google Sheets spreadsheets that this application has been installed in*)
     — ถ้าเห็นการขอสิทธิ์อื่น (เช่น Google Drive ทั้งหมด หรืออีเมล) ให้หยุดและติดต่อผู้พัฒนา
   - หลังอนุญาต ถ้าการทดสอบยังไม่เริ่ม ให้กด **เรียกใช้** อีกครั้ง
5. รอจนช่อง **บันทึกการดำเนินการ (Execution log)** ด้านล่างขึ้น "การดำเนินการเสร็จสมบูรณ์" (Execution completed) — อาจใช้ 1–3 นาที
6. กลับไปที่แท็บของ **สำเนา** จะมีชีตชื่อ **`SelfTest`** (แท็บด้านล่าง) — แถว **ผลรวม** (แถวที่ 4) บอก **PASS**, **FAIL** หรือ **กำลังทดสอบ…**
   และแต่ละขั้นตอนด้านล่างมี PASS/FAIL พร้อมคำอธิบายภาษาไทย (ข้อความเดียวกันอยู่ใน Execution log ด้วย)
   - **PASS** ("ผ่านทั้งหมด — พร้อมนำ Code.gs ไปใช้กับชีตจริง") → ไปส่วน ค
   - **FAIL** → **หยุด ห้ามวางโค้ดลงชีตจริง** ถ่ายภาพหน้าจอชีต `SelfTest` ส่งให้ผู้พัฒนา (ชีตจริงยังไม่ถูกแตะ ทุกอย่างใช้งานได้ตามเดิม)
     — ขั้นที่ 1 ตรวจว่าข้อมูลเดิมทุกช่องยังอยู่ครบหลังปรับรุ่น และขั้นที่ 3 ตรวจว่ารหัสในคอลัมน์ `password` ตรงกับรหัสจริง (รายงานบอกเฉพาะชื่อช่อง/ชื่อคน/จำนวน ไม่มีตัวรหัส)
   - ขั้นที่ 4 (การป้องกันชีต) อาจขึ้น **คำเตือน** โดยยังเป็น PASS — แปลว่า Google ไม่ยอมใส่การป้องกันแบบเตือน แอปยังใช้งานได้ตามปกติ
   - ขั้นที่ 14–16 อาจขึ้น **"ข้าม —"** ถ้าแถว `vacation_auto_slots` ในชีต `Config` มีค่ามากกว่า 5 (เป็น PASS) — หลังอัปเดตให้ลองขอพักร้อนเกินโควตาในแอปดูเอง
   - **กำลังทดสอบ…** (ยังเป็นข้อความนี้หลังจาก Execution log จบแล้ว) = การทดสอบไม่จบ → ทำตาม [ถ้า selfTest ไม่จบ](#ถ้า-selftest-ไม่จบ)
   - ถ้ารายงานบอกให้รัน **`selfTestCleanup`** (มีผู้ทดสอบชั่วคราวค้างจากครั้งก่อน): เลือก `selfTestCleanup` ในช่องเดิม → **เรียกใช้** → แล้วรัน `selfTest` ใหม่
   - ถ้าขั้นที่ 5 ไม่ผ่านเพราะ Supervisor ยังใช้รหัส 1234: ให้ Supervisor เปลี่ยนรหัสในแอปก่อน แล้วทำสำเนาใหม่ตั้งแต่ส่วน ก
7. การทดสอบสร้างผู้ทดสอบชั่วคราวชื่อ "ทดสอบระบบ 1", "ทดสอบระบบ 2", … (รหัสสุ่ม ใช้เข้าสู่ระบบจากแอปไม่ได้) แล้วลบออกเองเมื่อจบ
   (บันทึกในชีต `Audit` ของสำเนายังอยู่ เป็นเรื่องปกติ) — เมื่อเสร็จทั้งหมดแล้ว **ลบสำเนาทิ้ง** (สำเนามีข้อมูลบุคลากรและรหัสผ่านเหมือนชีตจริง)

**ค. หลังจาก PASS เท่านั้น: วางโค้ดเดียวกันในชีตจริง → Deploy (URL เดิม) → ตรวจเวอร์ชันทันที**

1. เปิด **ชีตจริง** → **ส่วนขยาย → Apps Script** → วาง `Code.gs` **ไฟล์เดียวกับที่ทดสอบผ่าน** ทับทั้งไฟล์ → **บันทึก**
   - ⚠️ ตั้งแต่ข้อนี้จนถึงข้อ 4 **ห้ามรัน `setup` หรือฟังก์ชันใดในชีตจริง** — ถ้ารันตอนที่ Web App ยังเป็นเวอร์ชันเก่า ชีตจะถูกปรับรุ่น
     ขณะที่แอปทุกเครื่องยังคุยกับโค้ดเก่า (`selfTest` จะไม่ยอมทำงานในชีตจริงอยู่แล้ว)
2. **ทำให้ใช้งาน (Deploy) → จัดการการทำให้ใช้งาน (Manage deployments)** → เลือก deployment ที่ใช้อยู่ → กดไอคอนดินสอ ✏️ (**Edit**)
   — ตรวจว่า **ดำเนินการในฐานะ (Execute as) = ฉัน (Me)** และ **ผู้มีสิทธิ์เข้าถึง (Who has access) = ทุกคน (Anyone)** ก่อนกด Deploy
3. ช่อง **เวอร์ชัน (Version)** เลือก **เวอร์ชันใหม่ (New version)** → **ทำให้ใช้งาน (Deploy)** — URL `/exec` **เหมือนเดิม** ไม่ต้องแก้อะไรในแอป
   (**ห้ามกด New deployment** — จะได้ URL ใหม่)
4. **ตรวจเวอร์ชันทันที:** ในแอปบนเครื่องใดก็ได้ **เมนู → ตรวจสอบการเชื่อมต่อ (🩺) → ▶️ เริ่มตรวจสอบ** บรรทัดที่ 4 ต้องบอก **"เวอร์ชัน 3.0.0"**
   — หรือเปิด URL `/exec` ใน **หน้าต่างไม่ระบุตัวตน** ต้องเห็น `"version":"3.0.0"`
   - ยังเห็น **2.1.0**: ข้อ 3 ไม่ได้เลือก **New version** (หรือกดบันทึกแต่ไม่ได้ Deploy) → ทำข้อ 2–3 ใหม่ แล้วตรวจอีกครั้ง
     (ระหว่างนี้ไม่มีอะไรเสียหาย ตราบใดที่ยังไม่ได้รันอะไรในชีตจริง)
   - ถ้า **เผลอกด New deployment**: ใน **Manage deployments** เลือก deployment ใหม่ที่เพิ่งสร้าง → **Archive** (เก็บถาวร) — **ห้ามเปิด URL ของมัน**
     และห้ามนำไปใส่ในแอป — แล้วทำข้อ 2–3 กับ deployment เดิม · ถ้าเปิดไปแล้ว ให้ทำข้อ 2–3 ให้เสร็จโดยเร็ว (รหัสผ่านจริงของทุกคนไม่เสีย ระบบจัดการให้เอง)
5. **ไม่ต้อง** รัน `setup` (คำขอแรกหลัง Deploy ปรับชีตให้เอง) และ **อย่ารัน `selfTest` ในชีตจริง**
6. แอป v2.9 ที่ทุกคนใช้อยู่ยังทำงานได้ตามปกติกับเซิร์ฟเวอร์ 3.0 (แต่ยังไม่เห็นของใหม่) — ยกเว้น Staff ที่ขอพักร้อนเป็นคนที่ 3 ของวัน
  จะขึ้น "แอปในเครื่องนี้เป็นเวอร์ชันเก่า…" จนกว่าเครื่องนั้นจะได้แอป v3.0 ในส่วน ง

**จ. สิ่งที่เกิดกับชีตจริงหลัง Deploy**

คำขอแรกหลัง Deploy ปรับชีตให้เองครั้งเดียว (คำขออื่นในช่วงไม่กี่วินาทีนั้นอาจต้องรอ — แอปลองใหม่ให้เอง):

| ชีต | สิ่งที่เปลี่ยน |
|---|---|
| `Staff` | เพิ่มคอลัมน์ `password` ต่อท้าย (คอลัมน์ J) — คนที่ยังใช้รหัสเริ่มต้นจะมี `1234` ทันที คนอื่นว่างไว้จนกว่าจะเข้าสู่ระบบครั้งถัดไป (หรือยืนยันในหน้าโปรไฟล์) แล้วระบบจะเก็บรหัสให้เอง |
| `Leaves` | เพิ่ม 5 คอลัมน์ต่อท้าย (F–J): `detail` (ช่วงเวลาลาหาหมอ), `status` (`approved` / `pending` / `rejected`), `decided_by`, `decided_at`, `note` (เหตุผล) — แถวเดิมมี `status` ว่าง ซึ่งหมายถึงอนุมัติแล้ว |
| `Avatars` (ชีตใหม่) | รูปโปรไฟล์: `name`, `v`, `mime`, `data`, `updated_at` |
| `Config` | `schema_version` เป็น 4 · แถวใหม่ `claimed_columns:Staff` และ `claimed_columns:Leaves` (= 10) บอกว่าคอลัมน์ใหม่เป็นของระบบ — **ห้ามลบสองแถวนี้** |

- **ไม่มีอะไรถูกลบ** แถวเดิมไม่ถูกแก้ ไม่มีใครถูกออกจากระบบ · คอลัมน์ที่เคยพิมพ์เพิ่มเองไว้ทางขวาของ `Staff`/`Leaves` (ตรงตำแหน่งที่ระบบต้องใช้) จะถูกย้ายไปทางขวาโดยไม่ถูกทับ (ย้ายทั้งคอลัมน์)
- **รหัสผ่านจริงคือ hash** (`password_hash` + `password_salt`) คอลัมน์ `password` เป็นเพียงสำเนาที่อ่านได้ — ค่าที่ไม่ตรงกับรหัสจริงไม่มีผลใด ๆ (ดู [ความปลอดภัย](#ความปลอดภัย))

**ย้อนกลับไปใช้ `Code.gs` เวอร์ชันก่อน** (เช่น พบปัญหาร้ายแรงหลัง Deploy) — ทำตามลำดับนี้:

1. ใน **ชีตจริง** → **ส่วนขยาย → Apps Script** (หน้านี้ยังเป็นโค้ด 3.0) → เลือกฟังก์ชัน **`prepareRollback`** → **เรียกใช้**
   → Execution log ขึ้น "เตรียมย้อนกลับแล้ว: ล้างรหัสผ่านที่อ่านได้ในชีต N ช่อง (รหัสผ่านจริงของทุกคนไม่เปลี่ยน) …"
   (โค้ดเก่าเก็บรหัสเฉพาะแบบ hash จึงต้องล้างสำเนาที่อ่านได้ก่อน ไม่อย่างนั้นสำเนาจะไม่ตรงกับรหัสที่เปลี่ยนระหว่างย้อนกลับ)
2. ทันที: **Deploy → Manage deployments → ✏️ Edit → Version** เลือกหมายเลขเวอร์ชันที่ใช้ก่อนอัปเดต → **Deploy**
   (URL เดิม แอป v3.0 จะกลับไปทำงานแบบ v2.9 เองโดยไม่ต้องแก้ไฟล์หน้าเว็บ)
3. รัน **`prepareRollback`** อีกครั้ง (ล้างสำเนาที่อาจถูกเก็บระหว่างข้อ 1–2)
4. ตรวจ: 🩺 ตรวจสอบการเชื่อมต่อ หรือ URL `/exec` ต้องบอกเวอร์ชันเดิม (`2.1.0`)
   - ⚠️ **ห้ามรัน `setup`** ระหว่างที่ย้อนกลับ (`setup` ในหน้า editor เป็นโค้ด 3.0 จะปรับรุ่นชีตกลับทันที) และไม่ต้องลบอะไรเพิ่ม:
     คอลัมน์ใหม่และชีต `Avatars` ปล่อยไว้ได้ โค้ดเก่าไม่อ่าน
   - ถ้าในช่องเลือกฟังก์ชันไม่มี `prepareRollback` (เช่น วางโค้ดเก่าทับในหน้า editor ไปแล้ว) ให้ข้ามข้อ 1 และ 3 — รหัสผ่านจริงไม่เสีย
     แต่ค่าในคอลัมน์ `password` อาจไม่ตรงจนกว่าจะอัปเดตกลับเป็น 3.0 (ระหว่างนั้นอย่าใช้ค่าในคอลัมน์นั้นบอกรหัสให้ใคร)
   - ระหว่างย้อนกลับ คอลัมน์ `password` ว่าง ทุกคนเข้าสู่ระบบด้วยรหัสปัจจุบันตามปกติ · อย่าพิมพ์อะไรลงคอลัมน์นั้น (ไม่มีผลกับรหัสผ่านของใคร) — ตั้งรหัสใหม่ให้ใครให้ใช้ปุ่ม 🔑 ในแอป
   - โค้ดเก่าไม่รู้จักสถานะคำขอ — คำขอที่ **รออนุมัติ / ไม่อนุมัติ** และ **ลาหาหมอ** ที่บันทึกไปแล้วจะกลายเป็นวันลาปกติในเวอร์ชันเก่า
     ถ้าย้อนกลับหลังใช้งานไปแล้ว ให้ Supervisor ตรวจวันลาเหล่านั้นและลบที่ไม่ใช่วันลาจริง (หรือปรึกษาผู้พัฒนาก่อน)
5. **อัปเดตกลับเป็น 3.0 ภายหลัง:** ใน **Manage deployments → ✏️ Edit → Version** เลือก **หมายเลขเวอร์ชันของ 3.0.0** (ไม่ใช่ New version) → Deploy แล้วตรวจเวอร์ชัน (ส่วน ค ข้อ 4)
   — ถ้าในหน้า editor เป็นโค้ดเก่าอยู่ (วางโค้ดเก่าทับไปแล้ว) ให้วาง `Code.gs` 3.0.0 กลับก่อน (ส่วน ค ข้อ 1) แล้วจึงทำข้อ 2–4 เพราะ "New version" จะ Deploy โค้ดที่อยู่ในหน้า editor ตอนนั้น
   — ทุกคนเข้าสู่ระบบด้วยรหัสปัจจุบัน
   ระบบเก็บสำเนาที่อ่านได้ใหม่เมื่อแต่ละคนเข้าสู่ระบบ และวันลาที่โค้ดเก่าบันทึกทับระหว่างนั้นถูกนับตามที่บันทึกล่าสุด (สถานะเก่าที่ค้างถูกล้างให้เอง)

แอปตรวจข้อมูลใหม่อัตโนมัติทุก 90 วินาทีขณะเปิดหน้าจอ (ถามเซิร์ฟเวอร์ก่อนว่ามีอะไรเปลี่ยนไหม จึงเบามาก), เมื่อกลับเข้าแอป (ถ้าข้อมูลเก่ากว่า 30 วินาที)
และเมื่อเน็ตกลับมา — ถ้าดึงไม่สำเร็จจะลองใหม่เองหลัง 5, 15, 30 และ 60 วินาที

ข้อมูลของแต่ละวันต้องโหลดจากเซิร์ฟเวอร์ก่อน (ถ้าเครื่องยังไม่มีข้อมูลวันนั้นจะขึ้น **"⏳ กำลังโหลดข้อมูล…"** ถ้ามีสำเนาเดิมในเครื่องจะแสดงสำเนานั้นแบบอ่านอย่างเดียวไปก่อน)
ระหว่างนั้นการแก้ Station/หมายเหตุ และปุ่มบันทึก, คัดลอก, วาง, ล้างข้อมูล จะยังกดไม่ได้ — เพื่อไม่ให้บันทึกทับข้อมูลจริงด้วยหน้าจอที่ยังว่างหรือเก่า

### ใหม่ใน v3.0: คำขอลาพักร้อน การอนุมัติ และโปรไฟล์

| ใคร | ทำอะไรได้ |
|---|---|
| ทุกคน | **การลา** → แตะชื่อตัวเอง → เลือก **ลาหาหมอตอนเช้า/บ่าย** แล้วเลือกช่วงเวลา → **บันทึก** · ถ้าวันนั้นมีพักร้อนครบจำนวนแล้ว เลือก **พักร้อน** จะเห็นคำเตือน และปุ่มเป็น **ส่งคำขอ** · ดูผลที่ **คำขอของฉัน** (ขอใหม่ / ลบคำขอ) · **เมนู → โปรไฟล์ของฉัน** (แตะการ์ดชื่อ): รูปโปรไฟล์, แสดง/เปลี่ยนรหัสผ่าน |
| Supervisor | ข้อความ "มีคำขอพักร้อนรออนุมัติ" (หน้าวันนี้และการลา) → **ดูคำขอ** หรือ **เมนู → งานหัวหน้า → อนุมัติการลา** → **อนุมัติ** / **ไม่อนุมัติ** (ใส่เหตุผลได้) · หรือแตะชื่อคนที่ "รออนุมัติ" ในหน้าการลา · พักร้อนที่ Supervisor บันทึกให้ อนุมัติทันที · ลบรูปโปรไฟล์ที่ไม่เหมาะสมได้ที่ **โปรไฟล์ของฉัน → รูปโปรไฟล์ของทีม** |

- คำขอที่ **รออนุมัติ** และ **ลาหาหมอ** ไม่ทำให้ชื่อถูกตัดออกจาก Station — การ **อนุมัติ** พักร้อนจะนำคนนั้นออกจาก Station ของวันนั้นให้อัตโนมัติ (แอปถามก่อน)
- ตารางด้านล่างของหัวข้อนี้เขียนตั้งแต่ v2.2 (ชื่อแท็บเดิม: 🏥 Station = **วันนี้**, 👥 รายชื่อ / 📊 สรุป/ส่งออก = อยู่ใน **เมนู**)

### Supervisor (มี 1 คน — สิทธิ์เต็ม)

| แท็บ | ทำอะไรได้ |
|---|---|
| 🏥 Station | เลือกคนลงแต่ละช่อง (รายชื่อในช่องจะไม่แสดงคนที่ลา หรือถูกเลือกไปแล้วในช่องอื่น) · พิมพ์หมายเหตุ · เมื่อมีป้าย **"ยังไม่ได้บันทึก"** ให้กด **💾 บันทึก Station & หมายเหตุ** (ระหว่างบันทึก ช่องต่าง ๆ ของวันนั้นจะล็อกไว้ชั่วคราว) · การ์ด **📋 สรุปรายชื่อผู้ลา / สถานะพิเศษ** ของวันนั้น · **⚙️ ตั้งค่าจำนวนคน** ของแต่ละ Station · ดูประวัติการแก้ไข 20 รายการล่าสุดของวันนั้น (การจัดการรายชื่อ/รหัสผ่าน/จำนวนคนจะอยู่ในประวัติของวันที่ทำรายการ) |
| 📝 การลา | **🗓️ ปฏิทินการลา** (จำนวนผู้ลาแต่ละวันของเดือน — แตะวันที่เพื่อดูรายชื่อและเลือกวันนั้น) · บันทึกวันลา/สถานะให้ **ทุกคน** · ดูสรุปวันลาของทุกคนหรือรายคนตามช่วงวันที่ (ไม่เกิน 2 ปีต่อครั้ง) — คนที่ถูกลบไปแล้วแต่มีวันลาในช่วงนั้นแสดงเป็น "ชื่อ (ลบแล้ว)" |
| 👥 รายชื่อ | เพิ่มรายชื่อ (รหัสเริ่มต้นเว้นว่าง = `1234`) · 🔑 ตั้งรหัสใหม่ให้ผู้อื่น (ที่แถวตัวเอง = เปลี่ยนรหัสของตัวเอง) · ↔️ ย้ายกลุ่มคนประจำ/ทีมแทนเวร · 🗑️ ลบ · 👑 โอนสิทธิ์ Supervisor · นำเข้าข้อมูลเดิม |
| 📊 สรุป/ส่งออก | ดาวน์โหลดรายงาน CSV (เปิดด้วย Excel; ไม่เกิน 2 ปีต่อไฟล์) · ดู/แชร์/บันทึกภาพตารางเป็น JPG · 📋 คัดลอกวันนี้ → 📌 วางลงอีกวัน (บันทึกทันที และตัดคนที่ลาในวันปลายทางออกให้) · 🗑️ ล้างข้อมูลทั้งวัน (ลบ Station, หมายเหตุ และ **วันลาทุกคน** ของวันนั้น) |

- **⚙️ ตั้งค่าจำนวนคน** (ปุ่มในการ์ดแรกของแท็บ Station): กด − / + ของแต่ละ Station (1–10 คน) → **บันทึก** → "✅ บันทึกจำนวนคนแล้ว" (กด **ยกเลิก** = ไม่ส่งอะไร)
  - มีผลกับ **ทุกวันและทุกเครื่อง**: จำนวนช่องให้เลือกคน, "ต้องการ N คน", "(ขาด N)", ภาพ JPG และการวางข้อมูลลงวันอื่น
  - ลดจำนวนแล้ว **วันที่จัดคนไว้เกินจำนวนใหม่ยังเก็บรายชื่อครบ** (แสดงช่องเท่าที่บันทึกไว้) แต่จะเพิ่มคนในวันนั้นเกินจำนวนเดิมไม่ได้
  - ทุกเครื่องที่ใช้บันทึก Station ต้องเป็นแอป v2.1 (ดู [อัปเดตจาก v2.0 เป็น v2.1](#อัปเดตจาก-v20-เป็น-v21) ส่วน ค)
- **ถ้ามีคนอื่นแก้วันเดียวกันก่อนกดบันทึก** แอปจะถาม: **OK** = บันทึกทับด้วยข้อมูลของคุณ, **Cancel** = ทิ้งการแก้ไขแล้วโหลดข้อมูลล่าสุด
  (ใน v2.1 การที่แอปส่งซ้ำให้เองตอนเน็ตช้า ไม่ทำให้ขึ้นคำถามนี้หลอกแล้ว)
- ถ้าคนที่จัดลง Station มีวันลาในวันนั้น เซิร์ฟเวอร์จะตัดชื่อออกให้และแจ้งเตือน (แล้วแอปโหลดข้อมูลวันนั้นใหม่ให้)
- **ลบรายชื่อ** = ปิดการใช้งาน: ชื่อหายจากรายชื่อ, ถูกตัดออกจากเวรและวันลาตั้งแต่วันนี้เป็นต้นไป, ข้อมูลในอดีตยังอยู่ และเครื่องของคนนั้นจะออกจากระบบ
  - ในวันที่ผ่านมา ชื่อนั้นยังอยู่ในช่องเดิมเป็น **"ชื่อ (ลบแล้ว)"** — แก้วันนั้นแล้วบันทึกได้ตามปกติ (ชื่อเดิมยังคงอยู่ หรือเลือกเอาออกได้) แต่เลือกคนที่ถูกลบลงช่องใหม่ไม่ได้
  - ถ้าเพิ่มชื่อเดิมกลับมา ระบบจะเปิดใช้งานชื่อเดิม (รหัสใหม่ + บังคับเปลี่ยนรหัส) ประวัติเดิมยังผูกกับชื่อนั้น
  - ตั้งแต่ v3.2 ชื่อที่เพิ่มกลับมา **เริ่มแชทว่างเปล่า** (ไม่เห็นข้อความเก่าของชื่อนั้น เพราะอาจเป็นคนละคน) และเพิ่ม/ลบรูปในเรื่องที่ชื่อนั้นเคยแจ้งไว้ไม่ได้ —
    คนที่เคยคุยด้วยยังเห็นข้อความเก่าในเครื่องของตน (ระบบจดไว้ในชีต `Config` แถว `chat_since:ชื่อ` — ห้ามลบหรือแก้แถวนี้)
- **โอนสิทธิ์** แล้วคุณจะกลายเป็น Staff ทันที ถ้ามีการแก้ Station ที่ยังไม่ได้บันทึก แอปจะถามก่อนว่าจะบันทึกก่อนโอน (OK) หรือทิ้งการแก้ไข · ลบรายชื่อของ Supervisor ไม่ได้ ต้องโอนสิทธิ์ก่อน
- กฎการตั้งชื่อ: 1–40 ตัวอักษร, ห้ามมี `,` `<` `>` `"` `'` `\` `|` `;` หรือขึ้นบรรทัดใหม่/แท็บ, ห้ามขึ้นต้นด้วย `=` `+` `-` `@` หรือ `__`,
  ห้ามเป็นคำสงวนของระบบ (เช่น `constructor`, `toString`), ห้ามซ้ำกับชื่อที่ใช้งานอยู่ (ถ้าเป็นชื่อที่เคยถูกลบ ระบบจะเปิดใช้งานชื่อเดิมแทนการสร้างใหม่)
- รายงาน CSV: คอลัมน์ `วันที่, ชื่อ, กลุ่ม, สถานะการลา, Station ที่ปฏิบัติงาน, หมายเหตุประจำวัน` (วันที่ไม่ได้อยู่ Station ใดแสดง `—`)
  คนที่ถูกลบแล้วแต่มีข้อมูลในช่วงนั้นแสดงเป็น "ชื่อ (ลบแล้ว)" กลุ่ม "ไม่อยู่ในระบบ" · ข้อความที่ขึ้นต้นด้วย `=` `+` `-` `@` จะมี `'` นำหน้า เพื่อไม่ให้ Excel ตีความเป็นสูตร
- สรุปวันลาและรายงาน CSV ดึงข้อมูลช่วงนั้นจากเซิร์ฟเวอร์ใหม่ทุกครั้งที่กด (ข้อมูลล่าสุดเสมอ)
- **iPhone (แอปบนหน้าจอโฮม):** ส่งออก CSV และบันทึกภาพจะเปิดหน้าต่างแชร์ของ iOS → เลือก **บันทึกไปยังไฟล์ (Save to Files)** ถ้าแชร์ไม่สำเร็จแอปจะดาวน์โหลดไฟล์แทน
- เครื่องมือสร้างภาพ JPG (html2canvas จาก `cdnjs.cloudflare.com`) โหลดตอนกดบันทึก/แชร์ภาพครั้งแรก (แอปพยายามเก็บสำเนาไว้ใช้ตอนออฟไลน์ตั้งแต่ติดตั้ง)
  ถ้าโหลดไม่ได้จะขึ้น **"⚠️ โหลดเครื่องมือสร้างภาพไม่สำเร็จ — ตรวจสอบอินเทอร์เน็ตแล้วลองใหม่"** — กดใหม่ได้เมื่อเน็ตกลับมา

### Staff (ทุกคนที่ไม่ใช่ Supervisor)

| แท็บ | ทำอะไรได้ |
|---|---|
| 🏥 Station | ดูการจัดเวร, การ์ด **📋 สรุปรายชื่อผู้ลา / สถานะพิเศษ** (เรียงตามรายชื่อ พร้อม "(คนที่ N)" ของพักร้อน/Off เวร) และ **หมายเหตุ** ของแต่ละวัน (อ่านอย่างเดียว — วันที่ไม่มีจะขึ้น "ไม่มีรายการลาวันนี้" / "ไม่มีหมายเหตุสำหรับวันนี้") |
| 📝 การลา | **🗓️ ปฏิทินการลา** ของทุกคน (ดูได้ว่าวันไหนมีคนลากี่คนก่อนขอลา — แตะวันที่เพื่อดูรายชื่อ) · แถวของตัวเองอยู่บนสุด (ขอบสีฟ้า **"คุณ (ของฉัน)"**) กดสถานะ (ปกติ, พักร้อน, Off เวร, Off In charge, ลาป่วย, **ลากิจ**, ลาประชุม) → ยืนยัน → บันทึกทันที · แถวของคนอื่นขึ้น 🔒 ล็อก · ดูสรุปวันลาของตัวเอง · 🔑 **เปลี่ยนรหัส** ที่แถวของตัวเอง |

- **คิว "(คนที่ N)"** ของ *พักร้อน* และ *Off เวร* เรียงตามเวลาที่ **เซิร์ฟเวอร์ได้รับ** การบันทึก
  กดสถานะเดิมซ้ำ = ไม่เปลี่ยนอะไร (คิวเดิม) แต่ถ้าเปลี่ยนเป็นประเภทอื่นแล้วเปลี่ยนกลับ จะได้คิวใหม่ต่อท้าย
- เมื่อบันทึกวันลา ถ้าคุณถูกจัดลง Station ของวันนั้นอยู่ ระบบจะตัดชื่อออกจาก Station ให้อัตโนมัติ
- เปลี่ยนรหัสแล้ว เครื่องอื่นที่ล็อกอินชื่อคุณอยู่จะถูกออกจากระบบ
- ถ้ายังใช้รหัสเริ่มต้นหรือรหัสที่ Supervisor ตั้งให้ แอปจะเปิดหน้าต่างเปลี่ยนรหัสให้เอง และใช้งานอย่างอื่นไม่ได้จนกว่าจะเปลี่ยน

### เมื่อเน็ตไม่ดี / ออฟไลน์

| สิ่งที่เห็น | ความหมาย | ทำอะไรได้ |
|---|---|---|
| 🟡 **กำลังเชื่อมต่อใหม่…** ที่แถบบน (ไม่มีแถบเตือน) | คำขอล่าสุดล้มเหลวหรือช้าเกิน 1–2 ครั้ง แอปกำลังลองใหม่เอง | ใช้งานต่อได้ตามปกติ ข้อมูลยังอยู่ แก้ไขและกดบันทึกได้ (แอปส่งซ้ำให้เอง) |
| ⚪ **ออฟไลน์** + แถบ **"📴 เชื่อมต่อเซิร์ฟเวอร์ไม่ได้ — แสดงข้อมูลล่าสุดเมื่อ … • ระบบกำลังลองใหม่อัตโนมัติ"** | ล้มเหลว 3 ครั้งติดกัน — เครื่องมีเน็ต แต่ติดต่อเซิร์ฟเวอร์ไม่ได้ | ดูข้อมูลล่าสุดได้ · กด **ลองใหม่** หรือ **🩺 ตรวจสอบการเชื่อมต่อ** ในแถบนั้น · ยังกดบันทึกได้ (แอปจะพยายามส่ง) · กลับเป็นออนไลน์เองเมื่อติดต่อได้ |
| ⚪ **ออฟไลน์** + แถบ **"📴 ไม่มีอินเทอร์เน็ต — แสดงข้อมูลล่าสุดเมื่อ …"** | เครื่องไม่ได้ต่อ Wi-Fi หรือเน็ตมือถือ | ดูข้อมูลที่โหลดไว้ได้อย่างเดียว · กดบันทึกจะขึ้น **"ไม่มีอินเทอร์เน็ต — ยังบันทึกไม่ได้"** · เมื่อเน็ตกลับมาแอปดึงข้อมูลใหม่ทันที |

- ระหว่างที่แอปส่งคำสั่งบันทึกซ้ำ จะขึ้น **"เซิร์ฟเวอร์ตอบช้า กำลังลองใหม่…"** — รอได้เลย ไม่ต้องกดซ้ำ

  ถ้าป้ายยังอยู่ ให้กดบันทึกอีกครั้งเมื่อเชื่อมต่อได้

## 6. ความปลอดภัยและข้อจำกัด

### ความปลอดภัย

- **Web App ตั้งเป็น *Anyone* แต่ไม่ได้เปิดโล่ง:** ใครก็เรียก URL ได้ แต่ทุกคำสั่งที่อ่าน/เขียนข้อมูลต้องมี token ที่ได้จากการล็อกอิน
  คำสั่งที่ไม่ต้องล็อกอินมีแค่ `ping`, รายชื่อผู้ใช้ (สำหรับหน้าล็อกอิน) และ `login`
  → คนที่รู้ URL จะเห็น **รายชื่อบุคลากร** ได้ และลองเดารหัสได้ — **ให้ทุกคนเปลี่ยนรหัสจาก 1234 โดยเร็ว**
  (ชื่อที่ยังใช้ 1234 อยู่ คนที่รู้ URL ล็อกอินแล้วตั้งรหัสใหม่แทนเจ้าของได้ · เพิ่มคน/ตั้งรหัสใหม่ให้ใคร ให้บอกให้เปลี่ยนรหัสทันที)
- **จำกัดการเดารหัส:** ใส่รหัสผิด 5 ครั้งต่อชื่อ (นับทั้งการล็อกอินและ "รหัสเดิม" ในหน้าต่างเปลี่ยนรหัส) → ชื่อนั้นถูกล็อก 10 นาทีนับจากครั้งที่ 5 (ความพยายามระหว่างที่ถูกล็อกไม่นับเพิ่ม และไม่ต่อเวลา)
  (ระหว่างล็อก แม้ใส่รหัสถูกก็เข้าไม่ได้) การนับทำภายใต้ล็อกของเซิร์ฟเวอร์ ส่งคำขอพร้อมกันหลายอันก็ได้ไม่เกิน 5 ครั้ง
  ปลดล็อกทันทีได้เมื่อ Supervisor ตั้งรหัสใหม่ให้ (🔑), เจ้าของชีตรัน `adminResetSupervisorPassword` (สำหรับ Supervisor) หรือเพิ่มชื่อที่เคยลบกลับมา
  - ข้อจำกัดที่เลี่ยงไม่ได้ของการล็อกรายชื่อ: คนที่รู้ URL สามารถ **จงใจใส่รหัสผิดให้ชื่อใดชื่อหนึ่งถูกล็อก** ได้ครั้งละ 10 นาที (ไม่ได้ข้อมูลอะไร แต่เจ้าของชื่อเข้าไม่ได้ชั่วคราว)
    ถ้าเกิดซ้ำ ๆ ให้สร้าง deployment ใหม่ (**Deploy > New deployment** ได้ URL ใหม่) แจ้งเฉพาะคนในหน่วยงาน แล้ว **Archive** deployment เดิมใน Manage deployments
- สิทธิ์ Supervisor ตรวจจากชีต `Config` ทุกคำสั่ง ไม่ได้เชื่อข้อมูลจากเครื่องผู้ใช้
  (คำสั่งอ่านใช้สำเนาข้อมูลสิทธิ์ในแคชของสคริปต์ ซึ่งถูกทิ้งทันทีเมื่อมีการบันทึกผ่านแอปหรือมีคนพิมพ์แก้ชีต — คำสั่งบันทึกอ่านชีตจริงทุกครั้ง
  ดังนั้นการลบรายชื่อ/เปลี่ยนรหัส/โอนสิทธิ์ผ่านแอปมีผลทันทีเหมือนเดิม)
- สคริปต์ได้สิทธิ์เฉพาะสเปรดชีตที่ผูกอยู่ (`spreadsheets.currentonly` + `@OnlyCurrentDoc`) — ไฟล์อื่นในบัญชีเจ้าของเข้าไม่ถึง
- **เก็บ Google Sheet เป็นส่วนตัว — อย่าแชร์สิทธิ์แก้ไข (Editor) ให้คนทั่วไป** ผู้มีสิทธิ์แก้ไขชีตจะ
  เปิด Apps Script ที่ผูกอยู่ได้ แก้โค้ดได้ และอ่านกุญแจลับที่ใช้สร้าง token ได้ (= ปลอมตัวเป็นใครก็ได้)
  ถ้าต้องการรายงาน ให้ใช้ปุ่มส่งออก CSV ในแอปแทนการแชร์ชีต
- **ตั้งแต่ v3.0 มีสำเนารหัสผ่านแบบอ่านได้** ในคอลัมน์ `password` ของชีต `Staff` (การตัดสินใจของหน่วยงาน เพื่อให้ผู้ใช้ดูรหัสของตัวเองได้)
  - **ใครเห็นได้บ้าง:** ทุกคนที่เปิดชีตได้ (เจ้าของชีต และใครก็ตามที่ได้รับแชร์ แม้เป็นสิทธิ์ Viewer) และประวัติเวอร์ชันของชีต (File → Version history)
    ยังเก็บรหัสเก่าไว้ด้วย — **ห้ามแชร์ชีตให้ใครเพิ่ม** และตรวจรายชื่อผู้ที่ได้รับแชร์ (ปุ่ม Share) เป็นระยะ
  - **อย่าใช้รหัสผ่านเดียวกับที่ใช้ที่อื่น** (อีเมล ธนาคาร ระบบของโรงพยาบาล) เพราะผู้ดูแลชีตเห็นได้ — แอปเตือนเรื่องนี้ในหน้าโปรไฟล์
  - **รหัสจริงคือ hash** (`password_hash` + `password_salt`): ค่าในคอลัมน์ `password` ใช้หรือแสดงเฉพาะเมื่อ **ตรงกับ hash** เท่านั้น — ค่าที่ไม่ตรง
    (เช่น หลังย้อนเวอร์ชัน หลังเรียงข้อมูลผิด หลัง Restore) ใช้เข้าสู่ระบบไม่ได้ ไม่ถูกแสดงในแอป และถูกแก้ให้ตรงเมื่อคนนั้นเข้าสู่ระบบครั้งถัดไป
    (ระบบล้างค่าที่ไม่ตรงให้เองภายในไม่กี่ชั่วโมง)
  - **คอลัมน์ `password` ใช้แสดงรหัสเท่านั้น — พิมพ์ลงไปแล้วไม่เปลี่ยนรหัสผ่านของใคร:** ถ้ามีคนพิมพ์ วาง ลาก (fill-down) ลบ หรือเรียงข้อมูลในคอลัมน์นี้
    ระบบคืนค่าที่ถูกต้องให้ (หรือล้างช่องถ้าไม่รู้ค่าที่ถูก — จะถูกเก็บใหม่เมื่อคนนั้นเข้าสู่ระบบ) และมุมขวาล่างของชีตขึ้นข้อความแจ้ง
    รหัสผ่าน การเข้าสู่ระบบ และเครื่องที่เข้าสู่ระบบอยู่ไม่เปลี่ยน · ถ้าระบบไม่ได้คืนค่าให้ (เช่น แก้จากแอป Google Sheets บนมือถือ)
    ค่าที่พิมพ์ก็ไม่มีผล เพราะรหัสจริงคือ hash และระบบล้างค่าที่ไม่ตรงให้เองภายในไม่กี่ชั่วโมง
    - **ตั้งรหัสใหม่ให้ใคร ให้ใช้แอป:** เมนู → รายชื่อบุคลากร → 🔑 ตั้งรหัสใหม่ (Supervisor ลืมรหัสเอง: ฟังก์ชัน `adminResetSupervisorPassword` — หัวข้อ 7)
  - **"แสดงรหัสผ่าน" ในโปรไฟล์:** แสดงเฉพาะรหัสของตัวเองหลังเข้าสู่ระบบ อ่านจากชีตใหม่ทุกครั้งที่กด แสดง 30 วินาทีแล้วซ่อนเอง
    (และซ่อนทันทีเมื่อออกจากหน้า สลับแอป หรือออกจากระบบ) ไม่ถูกเก็บในเครื่องหรือแคชของเซิร์ฟเวอร์
    - **ทุกครั้งที่แสดง ถูกบันทึกในชีต `Audit`** (`VIEW_PASSWORD` บอกว่าใครและเมื่อไร ไม่มีตัวรหัส — Supervisor ดูได้ในประวัติการแก้ไขของวันนั้นในแอป)
      และดูได้ไม่เกิน **5 ครั้งต่อชั่วโมงต่อคน** (เกินแล้วแอปบอกเวลาที่ดูได้อีก)
    - **ความเสี่ยงของเครื่องที่ยังเข้าสู่ระบบค้างไว้:** ใครก็ตามที่ได้ใช้เครื่องนั้นกดดูรหัสได้ — บนเครื่องส่วนกลางหรือเครื่องที่ยืมคนอื่น **ต้องออกจากระบบทุกครั้ง**
      ถ้าสงสัยว่ามีคนเห็นรหัส ให้เปลี่ยนรหัส (เครื่องอื่นที่เข้าสู่ระบบชื่อนั้นจะหลุดทั้งหมด)
  - รหัสที่ขึ้นต้นด้วย `'` `=` `+` `-` `@` ตั้งใหม่ไม่ได้ (ชีตจะตีความเป็นสูตร) — รหัสเดิมแบบนั้นยังใช้เข้าสู่ระบบได้ แต่แสดงในโปรไฟล์ไม่ได้
    แอปจะแนะนำให้เปลี่ยนรหัส
  - **ลบรายชื่อ** (ในแอป) ลบสำเนารหัสผ่านและรูปโปรไฟล์ของคนนั้นด้วย — ถ้าเพิ่มชื่อเดิมกลับมา จะเริ่มใหม่ทั้งหมด
- รูปโปรไฟล์อยู่ในชีต `Avatars` ทุกคนที่เข้าสู่ระบบแอปเห็นรูปของทุกคน (รายชื่อหน้าเข้าสู่ระบบไม่มีรูป) · ออกจากระบบแล้วรูปที่เก็บไว้ในเครื่องถูกลบด้วย ·
  เซิร์ฟเวอร์รับเฉพาะรูป JPEG ขนาดไม่เกิน 512×512 จุด (แอปแปลงให้เอง) — รูปที่ไม่ผ่านเงื่อนไขนี้ไม่ถูกส่งให้เครื่องใด
- repository GitHub แบบ Public ทำให้ `config.js` (ที่มี URL) เป็นสาธารณะ ถ้าไม่ต้องการ ให้ใช้วิธี ข ในขั้นที่ 6
- token อายุ 30 วัน ถ้ามือถือหาย: Supervisor ตั้งรหัสใหม่ให้คนนั้น (เครื่องเดิมจะหลุดทันที) หรือรัน `resetAllSessions` (ดูหัวข้อ 7)
- รหัสผ่านแบบข้อความธรรมดาของเวอร์ชันเดิมถูกลบออกจากทุกเครื่องที่เปิดเวอร์ชัน 2 และการออกจากระบบจะลบข้อมูลทั้งหมดของผู้ใช้ออกจากหน้าจอและแคช

### ข้อห้ามเมื่อเปิดดูชีตโดยตรง

- **หน้าต่าง "แน่ใจไหม" ของ Google Sheets:** ทุกชีตของแอปมีการป้องกันแบบเตือน (คำอธิบายขึ้นต้นด้วย "เวร IPD") เมื่อจะแก้ค่าหรือเรียงข้อมูลด้วยมือ
  Google จะถามยืนยันก่อน — นั่นคือสัญญาณให้หยุดคิด: ส่วนใหญ่ควรกด **ยกเลิก** แล้วทำผ่านแอปแทน (แอปไม่ถูกป้องกันนี้ขวาง และอย่าลบการป้องกันนี้)
- ❌ **ห้ามแก้หัวคอลัมน์ ห้ามสลับ/แทรก/ลบคอลัมน์ และห้ามเปลี่ยนชื่อชีต** — โค้ดอ้างคอลัมน์ตามลำดับตายตัว
  (ถ้าเผลอแก้หรือลบข้อความหัวคอลัมน์ ระบบจะเขียนแถวหัวคืนให้เองภายในไม่กี่ชั่วโมง **ยกเว้นช่องแรก (A1)** ซึ่งต้องคงเป็น `name` (Staff) / `date` (Leaves, Days) / `key` (Config) ตามเดิม ข้อมูลไม่เสีย — ระบบรู้ว่าคอลัมน์ไหนเป็นของตัวเองจากแถว
  `claimed_columns:Staff` / `claimed_columns:Leaves` ในชีต `Config` — **ห้ามลบสองแถวนี้**)
- ❌ **ชีต `Leaves`: ห้ามเรียงข้อมูล (Sort) หรือย้ายเพียงบางคอลัมน์ — เลือกทั้งแถว (A–J) เสมอ หรือไม่เรียงเลย**
  เหตุผล: สถานะคำขอ (คอลัมน์ F–J: ช่วงเวลา สถานะ ผู้อนุมัติ เวลา เหตุผล) อยู่แถวเดียวกับวันที่และชื่อ (A–E) — ถ้าเรียงเฉพาะ A:E (ความกว้างเดิมของ v2.x)
  สถานะจะไปติดกับวันลาของคนอื่น: พักร้อนที่อนุมัติแล้วอาจกลายเป็น "ไม่อนุมัติ" และคำขอที่ไม่อนุมัติอาจกลายเป็นวันลาจริง โดยไม่มีอะไรเตือน
- ❌ **ชีต `Staff`: ห้ามเรียงข้อมูลหรือย้ายเพียงบางคอลัมน์** (เช่น เลือก A:I แล้วเรียง) — ไม่เรียงเลยดีที่สุด เพราะลำดับแถวคือลำดับที่แสดงในแอป
  ถ้าจำเป็นจริง ๆ ให้เลือกทั้งแถว (A–J) พร้อมกัน (การเรียงผิดไม่ทำให้ใครเข้าสู่ระบบด้วยรหัสคนอื่นได้ แต่ทำให้กลุ่ม/ลำดับ/สำเนารหัสเพี้ยน)
- ❌ ห้ามเปลี่ยนชื่อคนในชีต `Staff` (ชื่อถูกใช้อ้างอิงในชีต `Days`/`Leaves`) และห้ามลบแถวใน `Staff` — ให้ลบผ่านแอป
- ❌ ห้ามลบแถวในชีต `Days` เพื่อ "ล้าง" วัน — ใช้ปุ่ม 🗑️ ล้างข้อมูลทั้งวันในแอป
  (แถวที่ถูกล้างจะยังอยู่เป็นแถวว่างที่มีเลข `version` — ตั้งใจให้เป็นแบบนั้น เพื่อกันเครื่องที่ถือข้อมูลเก่าบันทึกทับ)
- ⚠️ ถ้าจำเป็นต้องแก้ข้อมูลในชีตเอง (เช่น แก้คำผิดในหมายเหตุ): วันที่ต้องเป็นรูปแบบ `YYYY-MM-DD` เท่านั้น, ชื่อต้องตรงเป๊ะ
  การแก้ในชีตโดยตรง **ไม่ถูกบันทึกใน Audit** — ทางที่ดีที่สุดคือแก้ผ่านแอป
- แอปจะเห็นการแก้ในชีตเมื่อไร:
  - **พิมพ์/วาง/ลบค่าในช่อง** → ทุกเครื่องเห็นในการดึงข้อมูลครั้งถัดไป (ภายใน 90 วินาที หรือกด 🔄) เพราะ `onEdit` แจ้งสคริปต์ให้ทันที
  - **แทรก/ลบแถว, Restore เวอร์ชันเก่า, แก้ผ่านสคริปต์อื่น** (Google ไม่เรียก `onEdit` ให้) → ข้อมูลหลัก (`Staff`, `Config`, `Days`, `Leaves`) แอปเห็นภายในประมาณ **10 นาที**
    แต่ชีตระบบจัดเวร (`Profiles`, `Assistants`, `Holidays`, `Rosters`, `Duties`, `BackupMsgs`) อาจใช้เวลา **ถึง 6 ชั่วโมง** —
    หรือ **ทันที** ทั้งหมดหลังรัน `setup` จาก Apps Script editor (การกดบันทึกในแอปตรวจกับชีตจริงเสมอ จึงไม่เขียนทับด้วยข้อมูลเก่า)
- คอลัมน์ `status` ของ `Leaves`: เว้นว่าง = อนุมัติแล้ว · `pending` = รออนุมัติ · `rejected` = ไม่อนุมัติ — ควรอนุมัติ/ไม่อนุมัติผ่านแอป (บันทึก Audit และนำออกจาก Station ให้)
  · `detail` ของลาหาหมอต้องเป็นรูปแบบ `09:00-11:00`
- ❌ **ชีตระบบจัดเวร 6 ชีต (`Profiles`, `Assistants`, `Holidays`, `Rosters`, `Duties`, `BackupMsgs`): ห้ามเปลี่ยนชื่อชีต ห้ามเรียงข้อมูลหรือย้ายเพียงบางคอลัมน์
  และห้ามวางทับแถวที่มีอยู่** — แก้ผ่านแอป (ตารางเวร / ตั้งค่าการจัดเวร) เท่านั้น · ห้ามลบแถว `owned_sheet:…` ในชีต `Config`
  (ถ้าแถวนั้นหาย ระบบจะไม่อ่านชีตนั้นอีก และเมื่อมีการบันทึกครั้งถัดไปจะเปลี่ยนชื่อชีตนั้นเป็น "… (เดิม)" แล้วเริ่มชีตใหม่ — ข้อมูลเดิมยังอยู่ในชีต "(เดิม)")
  · ชีตที่ชื่อลงท้ายด้วย **"(เดิม)"** คือชีตเดิมของเจ้าของไฟล์พร้อมข้อมูลครบ ระบบไม่อ่านและไม่แก้ เก็บไว้หรือลบเองได้
- ❌ **ชีตแจ้งปัญหาและแชท 4 ชีต (`Problems`, `Files`, `Chat`, `ChatReads`, ตั้งแต่ v3.2): ห้ามเปลี่ยนชื่อ เรียงข้อมูล แก้ หรือวางข้อมูลลงไป** — ใช้ผ่านแอปเท่านั้น ·
  ชีต `Files` เก็บรูปเป็นข้อความยาวมาก **ห้ามเปิดแก้ช่องในชีตนี้** · ข้อความแชทและรูปอยู่ในชีตเหล่านี้ ใครเปิดชีตได้ก็อ่านได้ — **อย่าแชร์ชีต** ·
  การแก้ด้วยมือที่ไม่ผ่าน `onEdit` (แทรก/ลบแถว, Restore) อาจใช้เวลาถึง 6 ชั่วโมงกว่าแอปจะเห็น หรือทันทีหลังรัน `setup`
- ❌ ห้ามพิมพ์ข้อมูลเองในชีต `Avatars` (ข้อมูลรูปเป็นรหัสยาว) · ชีต `SelfTest` เป็นรายงานของ `selfTest` แอปไม่อ่าน ลบได้
- ชีต `Config` แถว `vacation_auto_slots` (ถ้ามี) = จำนวนพักร้อนต่อวันที่อนุมัติอัตโนมัติ (จำนวนเต็ม 0–50 ค่าอื่นหรือไม่มีแถว = 2)
- ชีต `Config` แถว `station_count:<id>` คือจำนวนคนที่ Station นั้นต้องการ (จำนวนเต็ม 1–10 ค่าอื่นหรือแถวที่หายไปจะถือเป็นค่าเริ่มต้น)
  — แนะนำให้แก้ผ่านปุ่ม ⚙️ ในแอปซึ่งบันทึก Audit ให้

## 7. กู้คืนและแก้ปัญหา

### ลืมรหัสผ่าน

v3.0: ถ้ายังเข้าสู่ระบบอยู่ในเครื่องใดเครื่องหนึ่ง ดูรหัสของตัวเองได้ที่ **เมนู → โปรไฟล์ของฉัน → แสดงรหัสผ่าน**

| ใครลืม | วิธีแก้ |
|---|---|
| Staff | Supervisor ไปที่ **เมนู → รายชื่อบุคลากร** กด 🔑 ที่ชื่อนั้น → ตั้งรหัสใหม่ (เว้นว่าง = `1234`) → คนนั้นจะถูกบังคับเปลี่ยนรหัสตอนล็อกอิน (ถ้าชื่อนั้นถูกล็อกเพราะใส่รหัสผิด จะปลดล็อกทันที) |
| **Supervisor** | เจ้าของชีตดูรหัสได้ในชีต `Staff` คอลัมน์ `password` (ถ้ามีค่า — ช่องว่างแปลว่ายังไม่ได้เก็บ) · หรือเปิด **Extensions > Apps Script** → เลือกฟังก์ชัน **`adminResetSupervisorPassword`** → **▷ Run** → รหัสของ Supervisor ปัจจุบันกลับเป็น `1234` (ปลดล็อกทันที) และต้องเปลี่ยนตอนล็อกอิน |
| Supervisor ลาออก/ไม่อยู่ | เจ้าของชีตแก้ค่าในชีต `Config` แถว `supervisor` คอลัมน์ `value` เป็นชื่อคนใหม่ (ต้องตรงกับชื่อในชีต `Staff` เป๊ะ) แล้วรัน `adminResetSupervisorPassword` ถ้าคนใหม่จำรหัสไม่ได้ (ถ้าชื่อไม่ตรง ฟังก์ชันจะแจ้งว่าไม่พบ Supervisor ในชีต Staff) |

### บังคับทุกคนออกจากระบบ

เปิด **Extensions > Apps Script** → เลือก **`resetAllSessions`** → **▷ Run**
ทุกเครื่องต้องล็อกอินใหม่ (รหัสผ่านไม่เปลี่ยน) ใช้เมื่อสงสัยว่ามีคนแอบใช้ หรือมือถือหายหลายเครื่อง
ถ้ามีปัญหาเฉพาะคนเดียว ให้ตั้งรหัสใหม่ให้คนนั้นแทน (เครื่องที่ล็อกอินชื่อนั้นจะหลุดเหมือนกัน)

### ตรวจการตั้งค่า Web App (ใช้เมื่อเชื่อมต่อไม่ได้)

เบราว์เซอร์ไม่ยอมให้แอปอ่านหน้าเว็บที่ Google ตอบกลับเมื่อการตั้งค่าผิด (หน้าล็อกอิน/หน้า error ไม่มี CORS header)
แอปจึงรายงานเป็น **"เชื่อมต่อเซิร์ฟเวอร์ไม่ได้"** เหมือนเน็ตหลุด (บางกรณีเป็น **"เซิร์ฟเวอร์ Google ขัดข้องชั่วคราว"** ที่ไม่หายเอง)
ก่อนอื่นให้เปิด [ตรวจสอบการเชื่อมต่อในแอป](#ตรวจสอบการเชื่อมต่อในแอป) — ถ้าเป็นเฉพาะบางเครือข่าย (เช่น Wi-Fi ของโรงพยาบาล แต่เน็ตมือถือใช้ได้)
แปลว่าการตั้งค่าถูกแล้ว ปัญหาอยู่ที่เครือข่าย ([ใช้งานผ่าน Wi-Fi ของโรงพยาบาล](#ใช้งานผ่าน-wi-fi-ของโรงพยาบาล)) — ถ้าเป็นทุกเครือข่ายและทุกเครื่อง ให้ตรวจตามลำดับ:

1. เปิด URL `/exec` ใน **หน้าต่างไม่ระบุตัวตน** (Incognito / InPrivate) หรือบนมือถือที่ไม่ได้ล็อกอิน Google — ต้องเห็น `"ok":true` (และ `"version":"3.0.0"`)
   (อย่าทดสอบในเบราว์เซอร์ที่ล็อกอินบัญชีเจ้าของ เพราะจะผ่านเสมอ)
2. ถ้าเห็นหน้าล็อกอิน Google / "ไม่มีสิทธิ์เข้าถึง" → **Deploy > Manage deployments > ✏️** ตั้ง *Who has access* = **Anyone** และ *Execute as* = **Me** → **Deploy**
3. ถ้าเห็นหน้า "ไม่พบ" / error → URL ผิดหรือ deployment ถูก Archive ไปแล้ว: คัดลอก Web app URL ใหม่จาก Manage deployments (ต้องลงท้าย `/exec` ไม่ใช่ `/dev`)
   แล้วแก้ใน `config.js` หรือ "⚙️ ตั้งค่าการเชื่อมต่อ" ในหน้าล็อกอิน
4. ตรวจว่ากด Save `Code.gs` ก่อนออก Version และดูข้อผิดพลาดใน **Executions** (แถบซ้ายของ Apps Script)
5. บัญชี Workspace ที่ปิดตัวเลือก Anyone → ใช้บัญชี @gmail.com

### ตรวจสอบการเชื่อมต่อในแอป

หน้าจอ **🩺 ตรวจสอบการเชื่อมต่อ** ใช้ได้ **โดยไม่ต้องเข้าสู่ระบบ** เปิดได้ 3 ทาง:

- แตะ **สถานะการเชื่อมต่อ** ที่แถบบน (บนมือถือคือจุดสีข้างวันที่)
- ปุ่ม **🩺 ตรวจสอบการเชื่อมต่อ** ในแถบ "📴 …" ที่ขึ้นตอนออฟไลน์
- ลิงก์ **🩺 ตรวจสอบการเชื่อมต่อ** ในหน้าเข้าสู่ระบบ และในหน้าตั้งค่าการเชื่อมต่อ (ก่อนตั้ง URL จะตรวจได้เฉพาะบรรทัด 1–2)

กด **▶️ เริ่มตรวจสอบ** → แอปตรวจทีละบรรทัด (บรรทัดละไม่เกิน 20 วินาที) พร้อมเวลาที่ใช้ (ms):
✅ ผ่าน · ⚠️ ผ่านแต่มีข้อสังเกต (เช่น **"แต่ตอบช้า"** เมื่อเกิน 10 วินาที) · ❌ ไม่ผ่าน · ➖ ข้าม (ยังไม่ได้ตั้งค่า URL)

| บรรทัด | ตรวจอะไร | ถ้าไม่ผ่าน |
|---|---|---|
| 1. อินเทอร์เน็ตของเครื่อง | เครื่องต่อ Wi-Fi/เน็ตมือถืออยู่หรือไม่ | เปิด Wi-Fi หรือเน็ตมือถือ |
| 2. หน้าเว็บของแอป (`<โฮสต์ของแอป>`) | ดาวน์โหลดไฟล์เล็ก ๆ ของแอปจากเว็บโฮสต์จริง (ไม่ใช้สำเนาในเครื่อง) | เครือข่ายนี้ยังใช้อินเทอร์เน็ตไม่ได้ (เช่น Wi-Fi ต้อง login ใหม่) หรือบล็อกโฮสต์ของแอป |
| 3. เซิร์ฟเวอร์ Google Apps Script (`script.google.com`) | คำขอไปถึงด่านแรกของ Google ได้หรือไม่ | เครือข่ายนี้บล็อก `script.google.com` |
| 4. ช่องทางรับคำตอบ (`script.googleusercontent.com`) | ส่งคำสั่งทดสอบ (ping) ครบทั้งทางเหมือนที่แอปใช้จริง — ถ้าผ่านจะบอกเวอร์ชันของ `Code.gs` เช่น "เซิร์ฟเวอร์ตอบกลับปกติ (เวอร์ชัน 3.0.0)" | ถ้าบรรทัด 3 ผ่านแต่บรรทัดนี้ไม่ผ่าน: **"โดเมน script.googleusercontent.com น่าจะถูกบล็อกโดยเครือข่ายนี้"** · กรณีอื่นแสดงข้อความผิดพลาด เช่น "เซิร์ฟเวอร์ Google ขัดข้องชั่วคราว" |
| 5. (ไม่จำเป็นต่อการใช้งาน) `fonts.googleapis.com`, `cdnjs.cloudflare.com` | ฟอนต์ Sarabun และเครื่องมือสร้างภาพ | ขึ้นแค่ ⚠️ — แอปใช้งานได้ (ใช้ฟอนต์ของเครื่อง และอาจบันทึกภาพ JPG ไม่ได้) |

ใต้ตารางมี **สรุปผล** หนึ่งย่อหน้า เช่น "เชื่อมต่อเซิร์ฟเวอร์ได้ตามปกติ" หรือ "เข้าถึง script.google.com ไม่ได้ — เครือข่ายนี้อาจบล็อก Google Apps Script ลองใช้อินเทอร์เน็ตมือถือ หรือแจ้งฝ่าย IT"

**📋 คัดลอกผล** คัดลอกรายงานเป็นข้อความ (เวอร์ชันแอป, เวลา, ชนิดเบราว์เซอร์, สถานะการเชื่อมต่อในแอป, ผลทุกบรรทัด และสรุป) ไปวางใน LINE/อีเมลส่งฝ่าย IT ได้ทันที
— รายงาน **ไม่มี** token, URL ของ Web App หรือรายชื่อบุคลากร (มีเฉพาะชื่อโดเมน) · ถ้าคัดลอกไม่ได้ ให้บันทึกภาพหน้าจอแทน

**ตรวจว่าปัญหาอยู่ที่ Wi-Fi หรือไม่** (ใช้มือถือเครื่องเดียวกัน):

1. ต่อ Wi-Fi ของโรงพยาบาล (เช่น `wifi-officer`) → เปิดแอป → 🩺 → **▶️ เริ่มตรวจสอบ** → **📋 คัดลอกผล** แล้ววางเก็บไว้ (LINE/โน้ต)
2. ปิด Wi-Fi ใช้ **เน็ตมือถือ** → **🔁 ตรวจสอบอีกครั้ง** → **📋 คัดลอกผล** อีกชุด
3. เทียบผล:
   - เน็ตมือถือผ่านทุกบรรทัด แต่ Wi-Fi ❌ ที่บรรทัด 3 หรือ 4 → **เครือข่ายของโรงพยาบาลบล็อกหรือกรอง Google Apps Script** → ส่งข้อความด้านล่างพร้อมผลทั้งสองชุดให้ฝ่าย IT
   - Wi-Fi ❌ ตั้งแต่บรรทัด 2 → Wi-Fi อาจต้อง login ใหม่ (หน้า login ของ Wi-Fi หมดเวลา) → เปิดเบราว์เซอร์เพื่อ login Wi-Fi แล้วตรวจอีกครั้ง ถ้าเป็นบ่อยให้ขอข้อ 3 ในข้อความด้านล่าง
   - ทั้งสองเครือข่ายไม่ผ่านที่บรรทัด 4 ด้วย "เซิร์ฟเวอร์ Google ขัดข้องชั่วคราว" → ปัญหาฝั่ง Google ชั่วคราว รอสักครู่แล้วตรวจใหม่

5. ทางสุดท้าย: ล้างข้อมูลเว็บไซต์ของโดเมนนั้นในเบราว์เซอร์ — ⚠️ **อย่าทำบนเครื่องที่ยังไม่ได้นำเข้าข้อมูลเดิม**, ต้องล็อกอินใหม่

### ข้อมูลหาย / ลบผิด

ดูก่อนว่าใครทำอะไรเมื่อไรจากชีต `Audit` (ไม่มีข้อความหมายเหตุ) — ถ้าเสียหายไม่มาก การกรอกใหม่ผ่านแอปง่ายและปลอดภัยที่สุด

Google Sheets เก็บประวัติไว้ให้ที่ **File > Version history > See version history** มี 2 วิธี:

1. **กู้เฉพาะแถวที่หาย (แนะนำ):** เลือกเวลาที่ต้องการ → เมนู ⋮ ของเวอร์ชันนั้น > **Make a copy** → เปิดสำเนา
   - `Days`: คัดลอกแถวของวันที่ต้องการแล้ววางทับแถวของวันเดียวกันในชีตจริง (ถ้าไม่มีแถวของวันนั้นให้วางต่อท้าย)
   - `Leaves`: **ห้ามวางทับแถวที่มีอยู่** — คัดลอกทั้งแถว (A–J) แล้ววาง **ต่อท้ายแถวสุดท้าย** หรือบันทึกวันลานั้นใหม่ในแอป
     (ชีต Leaves มีได้หลายแถวต่อวันที่ การวางทับจะเขียนทับวันลาของคนอื่น และสถานะ/เหตุผลของแถวเดิมจะไปติดกับวันลาที่วางลงมา)
   **ห้ามคัดลอกชีต `Staff` / `Config`** จากนั้นให้ทุกคนกด 🔄 (การวางค่าลงช่องถือเป็นการแก้ชีต แอปจะเห็นในการดึงข้อมูลครั้งถัดไป)
2. **Restore this version ทั้งไฟล์:** ย้อนทุกชีต รวมถึง `Staff` และ `Config` ด้วย จึงมีผลข้างเคียง:
   - เครื่องที่เคยถูกบังคับออก (มือถือหายที่ตั้งรหัสใหม่ให้แล้ว, คนที่ถูกลบ, เครื่องอื่นของคนที่เปลี่ยนรหัส) **กลับมาใช้งานได้อีก**
   - รหัสผ่านที่เปลี่ยนหลังเวลานั้นกลับเป็นรหัสเดิม และ Supervisor/รายชื่อ/จำนวนคนของ Station กลับเป็นแบบเดิม
   - ดังนั้น **หลัง Restore ให้รัน `resetAllSessions` ทันที** แล้วแจ้งคนที่เปลี่ยนรหัสหลังเวลานั้นว่าต้องใช้รหัสเดิม (หรือให้ Supervisor ตั้งรหัสใหม่ให้)
     — การรันนี้ยังทำให้ทุกเครื่องเห็นข้อมูลที่ย้อนกลับทันที (Restore ไม่ผ่าน `onEdit` ถ้าไม่รันอะไรเลย แอปจะเห็นข้อมูลหลักภายในประมาณ 10 นาที และข้อมูลระบบจัดเวรภายใน 6 ชั่วโมง)
   - **Restore ไปยังเวลาก่อนอัปเดตเป็น v3.0:** ชีตกลับเป็นรูปแบบเดิม (ไม่มีคอลัมน์ใหม่) — ระบบเพิ่มคอลัมน์ของตัวเองกลับให้เอง (คอลัมน์ที่คุณเคยเพิ่มเองถูกเลื่อนไปทางขวา ไม่ถูกทับ),
     สำเนารหัสแบบอ่านได้จะว่างจนกว่าแต่ละคนจะเข้าสู่ระบบ และคำขอลา/การอนุมัติ/ลาหาหมอ/รูปโปรไฟล์ที่ทำหลังเวลานั้นหายไปด้วย
   - **Restore ไปยังเวลาก่อนอัปเดตเป็น v3.1:** ชีตระบบจัดเวรหายไปพร้อมกับเวอร์ชันนั้น — หลังรัน `setup` (ข้อถัดไป) ระบบสร้างชีตใหม่ที่ว่างให้
     ข้อมูลตารางเวร/ผู้ช่วย/วันหยุด/เบอร์โทรที่บันทึกหลังเวลานั้นต้องกรอกใหม่ (หรือคัดลอกจากสำเนาของเวอร์ชันล่าสุดตามวิธีที่ 1 โดย **ห้ามวางทับแถวที่มีอยู่**)
   - **Restore ไปยังเวลาก่อนอัปเดตเป็น v3.2:** ชีต `Problems`, `Files`, `Chat`, `ChatReads` หายไปพร้อมกับเวอร์ชันนั้น — หลังรัน `setup` ระบบสร้างชีตใหม่ที่ว่างให้ ·
     เรื่องที่แจ้ง รูป ข้อความแชท และยอดพักร้อน/คะแนนที่บันทึกหลังเวลานั้นหายไป · แอปในมือถือจะล้างแชทที่เก็บไว้และโหลดใหม่เอง
   - หลัง Restore ทุกครั้ง ให้รัน **`setup`** หนึ่งครั้งด้วย (ปรับชีตที่ย้อนกลับให้เข้ากับโค้ดปัจจุบันทันที) แล้วจึงรัน `resetAllSessions`
   - ควรทำตอนที่ไม่มีใครกำลังบันทึก

### ถ้า selfTest ไม่จบ

Apps Script หยุดฟังก์ชันที่ทำงานเกิน 6 นาที (Execution log ขึ้น "Exceeded maximum execution time" / "เกินเวลาดำเนินการสูงสุด") หรือคุณกด **หยุด (Stop)** เอง —

1. ในสำเนา เลือกฟังก์ชัน **`selfTestCleanup`** → **เรียกใช้** → Execution log บอกว่าลบอะไรไปบ้าง (รวมข้อมูลทดสอบของระบบจัดเวรปี 2099 ถ้ามี) (ลบเฉพาะผู้ทดสอบที่ `selfTest` สร้างเอง ไม่แตะรายชื่อจริง)
2. รัน **`selfTest`** ใหม่หนึ่งครั้ง
3. ถ้ายังไม่จบอีก: **ห้ามนำโค้ดไปใช้กับชีตจริง** ส่งภาพหน้าจอ Execution log และชีต `SelfTest` ให้ผู้พัฒนา แล้วลบสำเนาทิ้ง

### สร้าง `css/tailwind.css` ใหม่ (เมื่อแก้คลาส)

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-css.ps1
```

- **รันใหม่ทุกครั้งที่เพิ่มหรือเปลี่ยนคลาสของ Tailwind** ใน `index.html` หรือ `js/*.js` (รวมคลาสที่ประกอบเป็นข้อความใน JavaScript)
  — แอปใช้เฉพาะ `css/tailwind.css` ที่ build ไว้ คลาสใหม่ที่ยังไม่ได้ build จะไม่มีผลบนหน้าจอ
- วิธีทำงาน: เปิด Edge แบบ headless ไปที่ `tools/build-css.html` (`--allow-file-access-from-files`) ซึ่งโหลด Tailwind Play CDN
  เวอร์ชันที่ตรึงไว้ (`https://cdn.tailwindcss.com/3.4.17`) อ่าน `index.html` + `js/*.js` แล้วใส่ทุกคำที่หน้าตาเหมือนคลาสลงใน element ที่ซ่อนไว้
  รอจนสไตล์ที่ Play CDN สร้างนิ่ง แล้วส่งผลออกมาใน `<pre id="css-output">` — สคริปต์ดึงผลนั้นมาเขียน `css/tailwind.css` (UTF-8 ไม่มี BOM)
- ต้องต่ออินเทอร์เน็ต (โหลด Play CDN) · ก่อนเขียนไฟล์ สคริปต์ตรวจว่าเป็น Tailwind v3.4.17 และมีกฎตัวอย่างครบ ถ้าไม่ผ่านจะ exit 1 โดยไม่เขียนทับ
- ตัวเลือก: `-Edge <path ของ msedge.exe>`, `-TimeoutSec` (ค่าเริ่มต้น 120)
- เสร็จแล้ว **เปลี่ยนเลขเวอร์ชัน** (`VERSION` ใน `sw.js` และที่อื่นตามหัวข้อ 4) ก่อนอัปโหลด และรันเทสต์

### หลักสำคัญเวลาแก้โค้ด

- `Code.gs` ต้องเป็น JavaScript ที่รันได้ทั้งใน Apps Script (V8) และเป็น `<script>` ธรรมดาในเบราว์เซอร์ (เทสต์โหลดไฟล์นี้ตรง ๆ) — ห้ามใช้ `?.`, `??`, `import/export`
- เรียกเวลาปัจจุบันผ่าน `now_()` เท่านั้น, เขียนชีตผ่าน `writeRows_` เท่านั้น (ขยายแถวด้วย `insertRowsAfter` ให้อัตโนมัติ — เหตุผลอยู่ในเอกสารออกแบบ)
- ฝั่งหน้าเว็บ: ข้อมูลจริงอยู่ใน `state` ไม่ใช่ใน DOM, ข้อความจากผู้ใช้ต้องผ่าน `Utils.escapeHtml` ทุกครั้ง, ห้ามใช้ `toISOString()` หาวันที่ปฏิทิน,
  object ที่ใช้ชื่อคนเป็น key ต้องไม่มี prototype (`Object.create(null)` หรือ `Map`)
- ค่าคงที่ร่วม (`STATIONS` ส่วน id/name/count, `LEAVE_TYPES`, `QUEUE_TYPES`, `STATION_COUNT_MIN`/`MAX`) ต้องตรงกันทุกตัวอักษรใน `Code.gs` และ `js/utils.js`
- ใช้คลาส Tailwind ใหม่ → รัน `tools/build-css.ps1` (ไม่มี Tailwind CDN ตอนใช้งานจริงแล้ว)
- ถ้าเพิ่ม/เปลี่ยน URL จาก CDN ใน `index.html` (หรือ URL ของ html2canvas ใน `js/app.js`) ต้องแก้ `CDN_ASSETS` ใน `sw.js` ให้ตรงกัน (`tests/sw.test.html` ตรวจให้)
- แก้ไฟล์หน้าเว็บแล้วเปลี่ยนเลขเวอร์ชันทุกครั้ง (ตอนนี้ 3.0.0): `VERSION` ใน `sw.js`, `?v=` ของ stylesheet และสคริปต์ทุกไฟล์ และ `BOOT_BUILD` ใน `index.html`, `CLIENT_VERSION` ใน `js/api.js`,
  `APP_BUILD` ใน `js/app.js` — ต้องเป็นเลขเดียวกัน (`tests/sw.test.html` ตรวจให้)

รายละเอียดทั้งหมด (ทุกคอลัมน์, ทุก action ของ API, รหัสข้อผิดพลาด, การออกแบบ token) อยู่ในเอกสารออกแบบของผู้พัฒนา (ไฟล์ส่วนตัว ไม่เผยแพร่)
